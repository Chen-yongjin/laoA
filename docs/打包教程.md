# Windows 打包与分发教程

> 两条路径先分清：**你要打包** → 需要 Python 3.11 及以上（第一~七节）；**别人只是用你打好的 exe** →
> **什么都不用装**（第六节）。全部命令都在**项目根目录**（有 `pyproject.toml`、`src`、`build`、`tests` 那一层）执行。
>
> **默认构建方式是 Nuitka**（`build\build.bat` → `python build\nuitka_build.py`）：把 Python **编译成原生 exe**，源码不能
> 被解包还原；代价是首次构建慢得多（20~60 分钟，且会自动下载编译器组件）。**备用路径是 PyInstaller**
> （`build\laoa_trader.spec`，3~8 分钟，源码可被解包还原）：本地用 `pyinstaller --noconfirm --clean build\laoa_trader.spec`，
> CI 上手选 `builder=pyinstaller`。
>
> **分发包默认只导入 6 个月历史**（`history_years = 0.5`，约 120 个交易日、约 50 万行；同花顺 dump 本身是
> 10 年数据集，导入时按这个值过滤，**下载量不变**），库更小、首次导入更快；想要长样本就把 `config.toml` 的
> `history_years` 改成 `10` 重新下载。**运行时间由每个人自己在界面里定**（打开程序 →「系统设置」→ 自动运行
> 那一组 → 改主跑 / 补跑时间，默认 16:00 / 19:15，`auto_run` 出厂是关的；保存即生效、不用重启），
> 所以打包时**不用**替别人把时间写死。

## 一、准备一台 Windows 打包机

| 要求 | 说明 |
|---|---|
| 系统 | Windows 10 / 11，64 位 |
| 磁盘 | 至少留 **5 GB**（依赖 + 打包中间产物 + 产物） |
| 网络 | 能访问 pypi.org（装依赖）、能下 Nuitka 的编译器组件；**打包不需要同花顺 Key** |
| Python | **3.11 及以上**（3.12 / 3.13 也可以；`build\build.bat` 依次尝试 `py -3.11/-3.12/-3.13/-3`，再退到 `python`） |
| 平台 | **必须是一台真正的 Windows**：两个构建器都不能跨平台（Linux / macOS 上打不出 Windows exe） |

## 二、安装 Python 3.11

**方式 A（推荐，图形界面）**：① 打开 <https://www.python.org/downloads/release/python-3119/>
② 下载 **Windows installer (64-bit)** ③ 安装第一步的界面底部**务必勾选 `Add python.exe to PATH`**
（不勾的话后面 `py`/`python` 命令会找不到）④ 选 `Install Now`，等它装完。
**方式 B（命令行）**：`winget install Python.Python.3.11`。**验证**（新开一个命令行窗口）：

```bat
py -3.11 --version
:: 应输出：Python 3.11.x
```

## 三、把项目复制到打包机

1. 把整个 **`laoA` 文件夹**复制到 Windows（例如 `D:\laoA`）
2. **不要**把下面这些带过去（它们是 Linux 产物或本机数据，带了反而出错）：`.venv/`（Linux 二进制、几百 MB 且无法在
   Windows 用）、`dist/`、`build/build/`、`build/nuitka-out/`（打包中间产物）、`config.toml`（**含你的 API Key，别外传**）、
   `*.db`、`*.parquet`（几个 GB 的数据，运行时自己会下）、`__pycache__/`、`.pytest_cache/`、`*.tmpdir`
3. 确认目录里有：`pyproject.toml`、`src\laoa_trader\`、`tests\`、`formulas\`、`build\build.bat`、
   `build\nuitka_build.py`、`build\laoa_trader.spec`
4. **路径建议**：放在**不带中文和空格**的路径下（例如 `D:\laoA`），中文路径在少数打包环节可能出问题。

## 四、手动命令（不想双击 `build\build.bat` 的，照这条顺序走 —— **一条都不能少**）

```bat
cd /d D:\laoA

rem ① 建虚拟环境（3.11 及以上都行；没有 py 启动器就换成 python）
py -3.11 -m venv .venv

rem ② 升级 venv 里的 pip（注意用 python -m pip）
.venv\Scripts\python -m pip install -U pip

rem ③ 装依赖 —— 两种装法，二选一：
rem    A. 最省事：连开发依赖一起装（Nuitka、PyInstaller、pytest 都有）
.venv\Scripts\pip install -e ".[dev]" -i https://pypi.tuna.tsinghua.edu.cn/simple
rem    B. 只装运行依赖（体积小），但**必须再补一条装 Nuitka**，否则后面构建报
rem       `No module named nuitka`
rem .venv\Scripts\pip install -e . -i https://pypi.tuna.tsinghua.edu.cn/simple
rem .venv\Scripts\python -m pip install nuitka -i https://pypi.tuna.tsinghua.edu.cn/simple

rem ④ 先跑测试确认环境没问题（可选，但强烈建议）
.venv\Scripts\python -m pytest tests -q

rem ⑤ 构建（Nuitka；首次 20~60 分钟，要联网下编译器组件）
.venv\Scripts\python build\nuitka_build.py

rem ⑥ 看产物
dir /b dist\LuweikDecision\*.exe
```

**关键区别**：`-e ".[dev]"` = 运行依赖 + 开发依赖（含 Nuitka），**构建只要这一条就够**；`-e .` = 只有运行依赖，**少装 Nuitka**，
构建时必然报错 —— 选 B 就一定要补第 ③ 步注释里那条 `pip install nuitka`。`build\nuitka_build.py` 会**先探测** Nuitka
在不在，不在就直接告诉你补哪条命令（附国内镜像），不用去猜 Python 报错。

**为什么先跑测试**：这里就报错说明是"环境问题"（依赖装不上、Python 版本不对），跟打包无关 —— 先解决它更省时间；测试全程**不联网、不需要同花顺 Key**，只要**全绿（0 failed）**即可，条数会随版本变化。

> **`pip install -U pip` 为什么写成 `python -m pip`**：venv 里直接敲 `pip` 有时会落到系统那个 pip（PATH 顺序或
> 权限问题），升级的是别的环境；`python -m pip` 一定是"这个 venv 的 pip"。
> **`py` 找不到怎么办**（Python 启动器没装）：① 命令换成 `python`（`python -m venv .venv`）；② 用完整路径
> `C:\Users\你\AppData\Local\Programs\Python\Python311\python.exe -m venv .venv`；③ `winget install Python.Launcher`。
> **国内网络慢**：装依赖加清华镜像（见第 ③ 步），否则 PySide6 / pyarrow 上百兆，直连可能要一小时。

## 五、打包（一键脚本）

```bat
build\build.bat
```

脚本自动做四件事：① 检查 Python（没有会打印中文安装指引并退出）② 创建 `.venv`（若不存在）
③ 安装依赖（含 **Nuitka** 与备用的 PyInstaller）④ 执行 `python build\nuitka_build.py`（编译成原生 exe）。

**预期耗时**：首次 **20~60 分钟**（Nuitka 要编译整个 pandas/pyarrow/PySide6 依赖图，还要下载编译器组件）；想快点或 Nuitka 装不起来时，退回备用路径：

```bat
.venv\Scripts\pyinstaller --noconfirm --clean build\laoa_trader.spec
```

> **exe 图标**来自 `src/laoa_trader/assets/icon.ico`（多尺寸 ICO，由 `python build/make_icon.py` 生成，Nuitka 那条通过
> `--windows-icon-from-ico` 接上）—— **改了图标要重新打包才生效**：只替换 `assets/` 里的文件、不重新打包，用户拿到的
> exe 还是旧图标。图标缺失不会让打包失败（两条路径都退化成默认图标）。

### 产物结构与命名

```
dist\LuweikDecision\             ← 整个目录就是分发单位，约 300~500MB
├─ luweik决策系统.exe            ← 双击这个（由 nuitka_build.py 统一改名）
├─ formulas\                     ← 随包策略 12 条（11 个 .txt + 1 个 .tvf）
├─ config.example.toml           ← 配置示例（复制成 config.toml 用）
├─ laoa_trader\assets\           ← 素材：icon.ico / icon-*.png / pet.png（桌宠）等
└─ 一堆依赖与动态库              ← 不要删、不要单独移动 exe
```

- **包里不含注册机**：CI 与产物检查都有硬断言 —— 出现任何 `keygen*` 或 `*注册机*` 就报错（注册机里带签发算法，
  混进用户包等于授权送人）。注册机由**独立 job / 单独打包**产出，见第九节。
- **Nuitka 版与 PyInstaller 版的目录结构不一样**（前者把依赖摊在产物目录里、没有 `_internal\`），所以"分发说明"只认
  两样东西：**目录名 `LuweikDecision`** 与 **exe 名 `luweik决策系统.exe`**。
- `formulas\` 在产物里是**只读副本**：首次运行由程序复制/补齐到 **exe 同级的** `formulas\`，用户改的是那一份；
  想换位置设环境变量 `LUWEIK_FORMULAS`。

### 为什么是"目录版"而不是单文件 exe

**目录版（onedir，当前默认）**：启动快（约 1~3 秒）、杀软误报较少，分发时压缩整个目录 —— **推荐**。
**单文件（onefile）**：分发只有一个文件，但启动慢（每次解压到临时目录，10~30 秒）、**杀软误报明显更多**，除非必须
单文件否则别用。要做单文件：把 `build\laoa_trader.spec` 里 `EXE(...)` 的 `exclude_binaries=True` 与 `COLLECT(...)`
调整成 onefile 形式，或在 `build.bat` 里加 `--onefile`（不推荐）。

## 六、第一次运行 / 分发时注意

**目标机器什么都不用装**（不需要 Python、不需要 Docker、不需要连你的 NAS）。

1. 解压 `LuweikDecision` 目录到任意位置（路径里别带空格），双击 `luweik决策系统.exe`
2. 程序先做**数据自检**（纯本地、秒级）：就绪 → 直接进主界面；落后几天 → 进界面并提示、自动补增量；没有数据 →
   **弹一次窗**说清下一步（"本地数据还不能用 · 在【系统设置】里填好 API Key 再点【下载数据】"），
   点「知道了」关掉即可（不是向导，弹窗里不用填任何东西）
3. **下载中断不用重来**：dump 是几百 MB、下载链接只活约 5 分钟，程序做了**断点续传 + 过期自动重签 + 重试**，重开程序再点一次会从断的地方接着下
4. 首次下载约 **8~15 分钟**（导入最近 6 个月，约 50 万行；有进度条、可取消、关掉下次会续传）；完成后自动跑一次
   匹配，之后默认**不自动跑**（`auto_run = false`），盘中（09:30–11:30 / 13:00–15:00）按间隔（默认 60 秒）盯池提醒
5. 配置与数据位置：配置 = 程序目录下的 `config.toml`（首次自动生成）；数据 = `%LOCALAPPDATA%\LuweikDecision\data\trader.db`
   （删掉它重启会重新弹出那句“数据不能用”的提示窗）；日志 = `%LOCALAPPDATA%\LuweikDecision\logs\luweik.log`；策略 = exe 同级的 `formulas\`（记事本就能改）

**分发时注意**：① **压缩 `dist\LuweikDecision` 整个目录**再给别人，不要只发 exe；② **不要把自己的 `config.toml` 一起发**
（里面有你的同花顺 API Key），也不要发自己的 `formulas\`；③ 对方需要**能上网** + **自己的同花顺 API Key**（在 <https://fuyao.aicubes.cn/admin> 申请）；④ 首次运行会被杀软/防火墙问一次，允许即可。

## 七、常见坑与对策

| 现象 | 原因与处理 |
|---|---|
| 双击 `build\build.bat` 一堆乱码报错（`'?rem' 不是内部或外部命令`） | `.bat` 必须**纯 ASCII + CRLF**：cmd 按 GBK 解析 UTF-8 中文会把 `rem`、`if errorlevel` 都拆坏。重新取一份源码包；**中文说明只写在本文档里**，别往 `.bat` 里加中文 |
| 构建目录里有中文或空格 | 换到 `D:\laoA` 这类**纯英文无空格**路径再重来（少数打包环节对中文路径过敏） |
| `py -3.11` 不是内部或外部命令 | 改用 `python`、或用 Python 完整路径、或 `winget install Python.Launcher`。`build\build.bat` 会依次试 `py -3.11/-3.12/-3.13/-3` 再退到 `python`，并打印它实际选中的版本 |
| **`No module named nuitka`** | 依赖装的是 `-e .`（只有运行依赖）→ 补一条 `.venv\Scripts\python -m pip install nuitka`；或改成 `pip install -e ".[dev]"`。`build\nuitka_build.py` 会先探测并提示这一条 |
| `pip install` 卡住 / 超时 | 加国内镜像：`-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| `pip` 升级/安装装到了别处 | venv 里一律用 `.venv\Scripts\python -m pip ...`（裸敲 `pip` 有时落到系统那个） |
| Nuitka 首次构建很久没动静 | 正常：它在**下载 C 编译器组件**并编译 pandas/pyarrow/PySide6，首次 20~60 分钟；看 `build\nuitka-out\` 在不在长大。编译版体积比 PyInstaller 版大也是正常的（依赖摊在产物目录里），分发时整目录一起发 |
| Nuitka 报找不到 C 编译器 | 装 [Visual Studio Build Tools](https://aka.ms/vs/17/release/vs_BuildTools.exe)（勾"使用 C++ 的桌面开发"）；或加 `--mingw64` 让它自动下载 mingw64 |
| Nuitka 报下载失败（depends / 编译器组件） | 网络问题：公司网络要**配代理**；命令里已带 `--assume-yes-for-downloads`，配好代理重跑一次 |
| 打包报 `ModuleNotFoundError: xxx` | PyInstaller 没自动发现该模块 → 在 `build\laoa_trader.spec` 的 `hiddenimports` 里追加模块名重打（Nuitka 那条通常不会遇到：它按导入图编译，`--include-package=laoa_trader` 已覆盖本项目全部模块） |
| 运行 exe 报缺 `VCRUNTIME140.dll` | 目标机器缺 VC++ 运行库 → 装 [VC++ 2015-2022 可再发行组件](https://aka.ms/vs/17/release/vc_redist.x64.exe) |
| exe 被杀软删掉/隔离 | 加信任/白名单；或改用目录版（已是默认） |
| 界面能开但白屏/排版乱 | 确认 exe 与依赖目录同级且未被移动；高 DPI 异常在 exe 右键→属性→兼容性里试"替代高 DPI 缩放" |
| 托盘图标不显示 / 通知不弹 | Windows 设置 → 系统 → 通知，确认允许该应用；托盘图标可能被折叠进隐藏区 |
| 用户问"怎么授权 / 我的机器码是多少" | 让他打开【关于软件】→【授权…】，机器码就在窗口里；他发机器码给你，你用 `python build/keygen.py <机器码>` 算出注册码回给他（**别把 `keygen.py` 打包发出去**） |
| 想不开界面、只用命令行 | `luweik决策系统.exe --cli --doctor`（自检，报告也写进 `<数据目录>\logs\自检报告.txt`）、`--cli --once`、`--cli --pool`、`--cli --market`、`--cli --watchlist list`、`--version` |
| 出问题要定位 | 发四样：**完整报错文本 + `--cli --doctor` 输出 + `<数据目录>\logs\luweik.log` + 卡在验收清单第几节第几条** |

## 八、CI 构建（`.github/workflows/build-windows.yml`）

不想在本机装 Python 时，把代码放到 GitHub（私有仓库也行），让 CI 在 Windows 运行器上打包。

**怎么跑**：① **自动** —— push 到 `main` 就构建（只改 `docs/**` 或 `**.md` 的提交会跳过，省额度）；② **手动** ——
Actions → `build-windows` → **Run workflow**，两个可选输入：`builder` = `nuitka`（默认）/ `pyinstaller`（备用路径，
走 `build\laoa_trader.spec`）、`skip_tests`（布尔，只有"CI 平台问题未解决"时才勾）；③ 同一分支只留最新一轮
（`concurrency` + `cancel-in-progress`，旧的那次直接取消），build job 上限 **150 分钟**。

**这一轮做了什么**（每一步都有 `id`，结论会写进 ci-log）：检出 → 写**心跳** → 装 Python 3.11（`setup-python@v7`，
pip 缓存）→ `pip install -e ".[dev]"` → **跑测试**（不过就不出包；`skip_tests` 才跳过）→ 记录环境 → **Nuitka 构建**
（或 `builder=pyinstaller` 时走 PyInstaller）→ **检查产物**（exe 在不在、**有没有混进注册机**、关键依赖在不在）→
**冒烟**（真跑一次 `luweik决策系统.exe --cli --version` 与 `--cli --doctor`，并断言报告里运行形态是 Nuitka、随包策略与图标
目录都解析得到）→ 打 `LuweikDecision.zip` → **包内容自检**（解压确认 `LuweikDecision/luweik决策系统.exe` 在、且**没有**
`keygen*` / `*注册机*`）→ 传 artifact（保留 2 天）→ 挂到滚动 Release。

> ⚠️ 冒烟那一步的断言写死了"运行形态是 **Nuitka**"，所以手动选 `builder=pyinstaller` 时会在冒烟步骤被判红
> （workflow 当前的实际行为）—— 备用路径请在本机跑 `pyinstaller`，或先改那条断言。

**结果写在哪：`ci-log` 分支**（`if: always()`，成功也写一次）。本机看：

```bat
git fetch origin ci-log
git show FETCH_HEAD:ci-log/meta.txt        :: 这一轮是绿是红、跑的是哪个 sha
git show FETCH_HEAD:ci-log/smoke.log       :: 冒烟：exe 的退出码与它自己打印的内容
git show FETCH_HEAD:ci-log/zipcheck.log    :: 包里有什么、exe 在不在、有没有注册机
```

- `heartbeat.txt`：这一轮**启动**了就写（一分钟内可见）—— 用来区分"排队/额度问题没跑"和"还在跑"
- `meta.txt`：`run / sha / ref / job / result`、每一步的 `step_test / step_pack / step_pack_fallback / step_smoke /
  step_check / step_zip / step_zipcheck / step_upload / step_release`，以及包的三件证据 `zip_name` / `zip_bytes` /
  **`zip_sha256`**（另有 `zip_files`、`release_asset=<附件名> <字节数>`）
- `smoke.log` / `zipcheck.log`：冒烟与包自检的完整输出（失败时**唯一**能看的证据）；另有 `pytest.log` / `pytest-err.log` /
  `check.log` / `pyinstaller.log` / `build-tail.log`（Nuitka 日志只留尾部 200 行）/ `smoke-report.txt`（exe 自写的自检报告）

**Release 附件怎么发**：滚动 tag **`latest`**，附件名固定 **`LuweikDecision.zip`**（`gh release upload --clobber`
覆盖同名附件，链接永远是那一个），说明里写清这一轮是哪个提交、哪个 run。页面
<https://github.com/Chen-yongjin/laoA/releases/tag/latest>；直链
<https://github.com/Chen-yongjin/laoA/releases/download/latest/LuweikDecision.zip>。

- **为什么以 Release 为主通道**：私有仓库的 Actions artifact 存储有硬额度（免费 500MB），主包一封就几百 MB，
  额度一满 `step_upload` 必失败；Release 附件与那份额度是两回事、链接还固定。所以 artifact 那步失败只发警告、
  不让整轮变红，但 `meta.txt` 里的 `step_upload` 会如实写出 `failure`。打 `v*` 形式的 tag 时，还会额外用
  `softprops/action-gh-release` 生成一个正式 Release。

## 九、注册机（作者签发工具）：**包里不带，单独拿**

主程序包（`LuweikDecision.zip`）是干净的 —— 里面没有注册机。你要注册机走两条路：

```bat
:: 1) 作者本地打包（最快，也不用等 CI）→ 产出 dist\keygen.exe（onefile，双击即用）
pyinstaller --noconfirm --clean build\keygen.spec
```

```
2) 走 CI（不想在本机装环境时）：GitHub → Actions → build-windows → Run workflow（手动触发），
   跑完到 Release 页面 Assets 里拿 keygen.zip（解压得 keygen.exe）
   固定地址：https://github.com/Chen-yongjin/laoA/releases/download/latest/keygen.zip
```

- 注册机是**独立 job**：手动触发时跑；另外**改动 `build/keygen.spec` / `build/keygen.py` /
  `src/laoa_trader/licensing.py` / 这个 workflow 自己**的 push 也会自动重发一次（其余 push 不跑，省 runner）。
- 它挂到**同一个滚动 Release**（附件 `keygen.zip`）；产物检查与 `ci-log/keygen-meta.txt` 都能确认它传没传上去。
- 授权状态文件在 `%APPDATA%\LuweikDecision\license.json`（**不在安装目录**），覆盖升级不会丢授权。
- **发版前顺手确认**：解压出来的 `dist\LuweikDecision\` 里**没有** `keygen.exe`（清单里也有一条勾选项）。
