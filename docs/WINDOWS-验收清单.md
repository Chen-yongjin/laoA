# Windows 验收清单（拿到代码/exe 后按表点一遍）

> 项目路径：**`laoA/`**（独立的一个文件夹，整包拷到 Windows 上即可）。
> 下面所有命令都假设你已经 `cd laoA`。

> 我能在这台 Linux 上验证的：**数据层、策略、分组自选、池子、盘中规则、条件单参数、
> 通知频道逻辑、config.toml 写回、CLI 入口**，以及**离屏（offscreen）跑起来的 PySide6 主窗口**
> （渲染/复制条件单/设置页保存/后台线程回调都有测试）。
> 我**无法**验证的：Windows 原生弹窗与托盘外观、真实同花顺接口、PyInstaller 打包产物、
> Windows 路径与编码、高 DPI 与字体。（自选股逻辑、池子合成、盘中观察池都有离线测试覆盖。）
> 下面就是"必须在 Windows 上人工过一遍"的部分，按顺序做即可。

## 零、首次运行 / 数据自检（新）

- [ ] 全新环境（`%LOCALAPPDATA%\LaoATrader\data` 里没有 `trader.db`）启动 → 状态栏先显示"正在检查本地数据…"，
      随后**弹出首次向导**，里面写清"为什么不能用"（如"本地还没有数据库（首次运行）"）
- [ ] 向导里填 API Key + 确认数据目录 → 点【开始下载】→ **进度条走动**（状态栏与向导里都动）
- [ ] 下载中点【取消下载】→ 提示"已取消（已写入的数据保留）"；**再点【开始下载】能接着传**（不从头开始）
- [ ] 下载完成后 → 自动跑一次选股建池 → 池子表格出现标的
- [ ] **重启程序** → 状态栏显示"✅ 数据就绪 · N 只 · 更新到 MM-DD"，**不再弹向导**
      （行数不放在状态栏里，要看行数点【详情】）
- [ ] **有数据时不重复下载**：重启后观察日志 `<数据目录>\logs\laoa-trader.log`，**不应出现 `下载同花顺 dump`**
      （就绪状态下一次 dump 请求都不发）；`--cli --download` 也应直接提示"无需重新下载"
- [ ] **把 `trader.db` 删掉后重启 → 应重新进入下载向导**（自检三态的核心验收）
- [ ] **下完历史后行业归属不再是 0%**（用户实报过）：首次下载/向导下完后，
      概览页状态栏显示 `✅ 数据就绪 …`（不是"行业归属未同步"）；
      `config.toml` 同级的 `logs\laoa-trader.log` 里能看到行业同步那一句
- [ ] **只缺轻量项时的指路**：手工把库里行业清空（或换一台刚下完的机器）→
      状态栏/闸门提示写的是 **点【刷新数据】补齐（不用重下历史）**，
      **不是** 点【下载数据】；点一下【刷新数据】几秒后自检变可就绪
- [ ] 落后几天的场景：把系统日期往后调 2~3 天（或等几天再开）→ 状态栏提示"数据落后 N 个交易日"，
      `auto_download_on_start = true` 时**自动**在后台跑增量；改成 `false` 则只提示不下载
- [ ] `--cli --doctor` 能看到：数据自检结论、行情行数/股票数（阈值）、历史跨度、落后交易日、
      复权事件有无、行业覆盖、需要下载什么，以及**已导入区间 / 行数 / 覆盖年数 / history_years**
- [ ] 默认导入**3 年**（约 300 万行）：`--doctor` 的"已导入区间"应显示约 3 年跨度
- [ ] 把 `history_years = 10` 后重新下载 → 导入区间变成约 10 年（行数约翻倍）
- [ ] 故意写矛盾配置（`history_years = 3` + `min_history_years = 9`）→
      `--doctor`/界面提示"配置矛盾：min_history_years 必须小于 history_years"，且**不会白下载**
- [ ] 空库跑 `--cli --once` → **退出码非 0** 且提示"本地没有可用的历史数据，请先运行 --download"（无 traceback）
- [ ] 空库跑 `--cli --once --auto-download` → 先下载、再继续跑选股

## 一、开发模式跑通（建议先做这个，报错信息最全）

- [ ] 把 `laoA/` 整个文件夹拷到 Windows（例如 `D:\laoA`），命令行 `cd laoA`
- [ ] 安装 Python 3.11（`py -3.11 --version` 有输出）
- [ ] 在 `laoA/` 下执行：`py -3.11 -m venv .venv`
- [ ] `.venv\Scripts\pip install -e ".[dev]"` —— 无报错
- [ ] `copy config.example.toml config.toml`，填入同花顺 API Key（`hithink_api_key`）
- [ ] `.venv\Scripts\python -m pytest tests -q` —— **全绿**（与我这边 Linux 结果一致：1168 passed）

      * 测试**不联网**：socket 层被 `tests/conftest.py` 的守卫封死，任何真实外呼都会直接失败
      * 日志里出现"限流/5001"字样是**假客户端合成的错误**，不是真实请求
      * Windows 路径（`C:\Users\...`）：测试自己拼 `config.toml` 时统一走
        `tests/_toml.py` 的 `p()` / `q()` 转义；`tests/test_toml_paths.py` 会静态扫描
        `tests/*.py`，**未转义就把文件名+行号列出来**（CI 上那批失败就是这个根因）

#### 本地三连跑（把"只在 Windows / 只在某个时刻才红"的失败前移到 Linux）

这三类失败都真的在 CI 上连续红过，而本地一直是绿的 —— 只跑一遍 `pytest tests -q` 抓不到：

| 跑法 | 抓什么 | 为什么需要 |
|---|---|---|
| `python -m pytest tests -q` | 常规 | 基线 |
| `TZ=UTC python -m pytest tests -q` | **与时刻有关**的断言（例如"下次自动运行：今天/明天"） | CI 在 UTC 上午跑时"还没到 16:30"，写死「明天」的断言必红 |
| `python -m pytest tests -q --basetemp='/tmp/win\Users\x'` | **路径里有反斜杠**（Windows `tmp_path`）时的配置解析/转义 | Windows 的 `C:\Users\...` 会把 TOML 里的 `\U` 当转义序列 → `Invalid hex value` |

命令行（Linux/macOS 本地前置检查，三条都跑）：

```bash
PYTHONPATH=src python -m pytest tests -q                    # 常规
TZ=UTC PYTHONPATH=src python -m pytest tests -q            # 时钟
PYTHONPATH=src python -m pytest tests -q \
  --basetemp='/tmp/win\Users\runneradmin\AppData\Local\Temp\pytest-of-x'   # Windows 路径
```

另外两条**不需要特殊参数**就有效的护栏：

- `tests/test_toml_paths.py::test_no_unescaped_paths_written_into_toml`
  —— 静态扫描整个 `tests/`，谁把路径没转义地拼进 TOML，就在**普通 Linux 跑法**下点名到行号；
- `tests/test_notify_channels.py` 里的**假 `winotify`**（照抄真库的 duration 校验）
  —— 让"时长非法 → 原生通知永远弹不出来"这类只在 Windows 上出现的问题在 Linux 上也红。

- [ ] `.venv\Scripts\python -m laoa_trader --cli --pool` —— 能打印空池提示（还没下数据）
- [ ] `.venv\Scripts\python -m laoa_trader --cli --market` —— 能打印大盘概览页那几行（没配 Key 时退出码非 0 并说明原因）
- [ ] `.venv\Scripts\python -m laoa_trader` —— **界面能打开**

## 一·五、数据闸门与下载进度（分发前必修项）

- [ ] **空库启动时绝不会"顺手选股"**：首次运行（还没数据）时，只要过了主跑时间，
      日志里应出现 `本地数据不可用（…），跳过本次自动选股；数据/下载就绪后当天仍会补跑`，
      **并且没有** `stock_pool` / `signal` 新行（这是"在只写了一半的库上跑策略"那个 bug 的验收点）
- [ ] **下载期间不跑策略**：向导下载进行中时，同一时间不应出现"开始日更"的日志；
      状态栏应显示 `⏬ 正在下载历史数据…`
- [ ] **下完当天会补跑**：下载完成后（当天已过主跑时间）应当自动跑一次选股建池；
      向导路径下这一步是自动的（无需再点按钮）
- [ ] **手动按钮有闸门**：数据没就绪时点【选股建池】→ 状态栏出现
      "本地无可用历史数据（…）；请先下载：点界面上的【下载数据】…"，且不起后台任务
- [ ] **`--once` 有闸门**：数据没就绪时 `.venv\Scripts\python -m laoa_trader --cli --once`
      → **退出码非 0** + 中文指路（`--download`），且没有选出任何票
- [ ] **进度可见（180 MB 不再像卡死）**：
      * 向导窗口与主窗口的进度条都在走（**不是**不确定进度），格式形如
        `下载 daily-k｜90.0/180.7 MB 50%`
      * 状态栏主状态：`⏬ 正在下载历史数据 45% · 下载 daily-k 90/181 MB`（**只这一句**）
      * 断网后恢复：状态栏出现 `↻ 正在重签 URL 继续下载（第 2 次，从 X MB 处接着下）`
      * 命令行：进度**按秒或按 10% 成行**输出（不会刷几百行），最后一行是 `100.0%`

## 一·八、默认策略集与推送范围（**新**：用户拍板，照这个验收）

> 默认只开 `short`（T+3）；`ultra`（连板回踩，两套口径显著为负）与 `swing`（T+10 波段）
> **停用但代码保留**；`short` 里两条"依赖开盘"的策略是**可勾选的内置策略、默认照常推送**
> —— 判断权交给使用者，程序只把两套口径的数字摆在眼前（`push_only_proven` 默认 **false**）。

- [ ] 【设置 → 策略组】**默认只勾「短线·T+3」**；「超短·隔日」与「波段·T+10」不勾，
      旁边有灰字写着停用原因（ultra 那句带 `−1.21%(t=−5.36)`、`−8.87` 之类的成绩单数字）
- [ ] 【设置 → 策略组】成员策略那一行：「地量后放量变盘」「首板缩量整理」后面标着
      `⚠️ 依赖开盘`，鼠标悬停能看到两套口径的数字
      （`A +0.09%(t=2.31)` / `−0.15%(t=−3.14)`、`A +0.21%(t=1.92)` / `−0.01%(t=−2.34)`）
- [ ] 这两条**可以勾/取消**（不勾 = 该组只跑剩下那条；勾上 = 照常跑、照常推送）
- [ ] 把 ultra / swing 勾上并保存 → **能跑**（代码没删，随时可以自己开回来）
- [ ] 【股票池】表格「来源策略」列：依赖开盘的标的显示成 `地量后放量变盘（依赖开盘）`，
      卡片上也是同样的后缀（悬停提示写着"策略照常推送；想只看两套口径都为正的标的，
      把 push_only_proven 设成 true"）
- [ ] 【选股建池】后收到的推送里：**这些标的照常出现**（默认不过滤）
- [ ] 把 `push_only_proven = true` 后重跑 → 这些标的**不再出现在推送里**，
      但正文末尾有一句「另有 N 只只由「依赖开盘」的策略选出…按 push_only_proven = true 未推送」，
      而且它们**在股票池页里照常看得到**（进池了，只是不推）
- [ ] 状态栏同一次跑完写着「已跳过 N 只依赖开盘的标的（进池但没推送，因为 push_only_proven 开着）」
- [ ] 日志里有 `推送过滤：另有 N 只只由「依赖开盘」的策略选出…`
- [ ] 再把 `push_only_proven` 改回 `false` → 立刻恢复全推（不是"设过一次就永久收窄"）
- [ ] 【成绩单】默认评估**全部策略**（含停用组）—— 输出里有
      「评估范围：全部策略（含已停用的组——成绩单不受选股开关限制）」
- [ ] 3 年库跑成绩单：输出末尾有「3 年样本较短，逐年稳定性仅供参考」（Markdown 报告里也有）

- [ ] 故意写错（例如 `C>MAA(C,5)`）→ 点【校验】→ 提示区是**中文原文**：
      `第 1 行第 3 列：未知函数 "MAA"（是不是想写 "MA"？可用函数：…）`
- [ ] 公式里用了 `连板()` 或 `涨停天数(10)` → 校验通过时提示区**多一句**
      "本地涨停池（逐日同步攒的），早期日期会读到 0"
- [ ] 点【试算：当前库能选出几只】→ 提示区显示 `最近交易日 <日期> 命中 N 只：名称（代码）、…`
      （最多列 20 只；没有命中也会说明扫了多少只）
- [ ] **名称必填**：名称留空点【保存】→ 提示"请先填公式名称"，**不会**存出一个无名文件
- [ ] 名称里带 `/ : * ? " < > |` → 保存后名称框里显示**安全化后的名字**（非法字符变 `_`），
      文件就在 `formulas\` 里，用记事本打开能看到 `# 名称: …` / `# 说明: …` 注释头
- [ ] **重名覆盖要二次确认**：同名再存一次 → 弹"公式「X」已存在，要覆盖它吗？"；
      点【否】原文件不动、点【是】才覆盖（且不会多出一个文件）
- [ ] 点下面列表里的**某一行** → 该公式载入左侧编辑区，可以直接改、再【保存】覆盖
- [ ] 列表里语法错的公式标 **❌ + 原因摘要**（鼠标悬停看全文）；一条坏公式**不影响**别的公式
- [ ] 点【看成绩单】→ 按钮变灰、进度条出现，**界面仍然能用**（窗口不"未响应"）；
      算完提示区出现成绩单（样本数、平均收益、胜率、t 值、按年），
      用到 `连板()` 时成绩单里**也**有那句历史坑提醒；点【复制成绩单】能拿到全文
- [ ] 勾上某条公式的**「参与选股」** → 状态栏提示"已加入选股"，`config.toml` 里出现
      `enabled_formulas = ["<公式名>"]`（**你自己写的注释与未知键都还在**）；取消勾选则变回 `[]`
- [ ] 勾选后点【选股建池】→ 股票池里出现该公式选出的票，「来源策略」列与「来源」列显示
      **`公式·<公式名>`**（不是"短线·T+3"那类内置组名），卡片上也能看到
- [ ] 推送正文里那一行标的的标签是 `公式·<公式名>`（与内置策略的"低价股"等并列）
- [ ] **默认不参与**：不勾任何公式时，池子与推送与以前**完全一样**（公式目录里有文件也不进池）
- [ ] 故意把某条"参与选股"的公式写坏（语法错）→ 点【选股建池】→ 内置策略照常出票、
      池子照常生成；日志里有一句"公式选股：<名字> 语法有错（…），本次不参与"，
      公式列表里那一行标 ❌
- [ ] 打包后：`formulas\` 目录在 **exe 同级**（第一次打开这一页时示例公式会自动出现）；
      往里面丢一个 `.txt` 公式 → 点【载入示例】/刷新列表能看到它

## 九、交易时段行为（建议工作日盘中做）
