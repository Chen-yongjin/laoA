# Windows 验收清单（拿到代码/exe 后按表点一遍）

> 项目路径：**`laoA/`**（独立的一个文件夹，整包拷到 Windows 上即可）。
> 下面所有命令都假设你已经 `cd laoA`。

> 我能在这台 Linux 上验证的：**数据层、策略、分组自选、池子、盘中规则、条件单参数、
> 通知频道逻辑、config.toml 写回、CLI 入口**，以及**离屏（offscreen）跑起来的 PySide6 主窗口**
> （渲染/复制条件单/设置页保存/后台线程回调都有测试）。
> 我**无法**验证的：Windows 原生弹窗与托盘外观、真实同花顺接口、PyInstaller 打包产物、
> Windows 路径与编码、高 DPI 与字体。（自选股逻辑、池子合成、盘中观察池都有离线测试覆盖。）
> 下面就是"必须在 Windows 上人工过一遍"的部分，按顺序做即可。

## 零、首次运行 / 数据自检（新）

- [ ] 全新环境（`%LOCALAPPDATA%\LaoATrader\data` 里没有 `trader.db`）启动 → 状态栏先显示"正在检查本地数据…"，
      随后**弹出首次向导**，里面写清"为什么不能用"（如"本地还没有数据库（首次运行）"）
- [ ] 向导里填 API Key + 确认数据目录 → 点【开始下载】→ **进度条走动**（状态栏与向导里都动）
- [ ] 下载中点【取消下载】→ 提示"已取消（已写入的数据保留）"；**再点【开始下载】能接着传**（不从头开始）
- [ ] 下载完成后 → 自动跑一次选股建池 → 池子表格出现标的
- [ ] **重启程序** → 状态栏显示"✅ 本地数据就绪：N 行 / 最新 YYYY-MM-DD"，**不再弹向导**
- [ ] **有数据时不重复下载**：重启后观察日志 `<数据目录>\logs\laoa-trader.log`，**不应出现 `下载同花顺 dump`**
      （就绪状态下一次 dump 请求都不发）；`--cli --download` 也应直接提示"无需重新下载"
- [ ] **把 `trader.db` 删掉后重启 → 应重新进入下载向导**（自检三态的核心验收）
- [ ] 落后几天的场景：把系统日期往后调 2~3 天（或等几天再开）→ 状态栏提示"数据落后 N 个交易日"，
      `auto_download_on_start = true` 时**自动**在后台跑增量；改成 `false` 则只提示不下载
- [ ] `--cli --doctor` 能看到：数据自检结论、行情行数/股票数（阈值）、历史跨度、落后交易日、
      复权事件有无、行业覆盖、需要下载什么，以及**已导入区间 / 行数 / 覆盖年数 / history_years**
- [ ] 默认导入**5 年**（约 500 万行）：`--doctor` 的"已导入区间"应显示约 5 年跨度
- [ ] 把 `history_years = 10` 后重新下载 → 导入区间变成约 10 年（行数约翻倍）
- [ ] 故意写矛盾配置（`history_years = 5` + `min_history_years = 9`）→
      `--doctor`/界面提示"配置矛盾：min_history_years 必须小于 history_years"，且**不会白下载**
- [ ] 空库跑 `--cli --once` → **退出码非 0** 且提示"本地没有可用的历史数据，请先运行 --download"（无 traceback）
- [ ] 空库跑 `--cli --once --auto-download` → 先下载、再继续跑选股

## 一、开发模式跑通（建议先做这个，报错信息最全）

- [ ] 把 `laoA/` 整个文件夹拷到 Windows（例如 `D:\laoA`），命令行 `cd laoA`
- [ ] 安装 Python 3.11（`py -3.11 --version` 有输出）
- [ ] 在 `laoA/` 下执行：`py -3.11 -m venv .venv`
- [ ] `.venv\Scripts\pip install -e ".[dev]"` —— 无报错
- [ ] `copy config.example.toml config.toml`，填入同花顺 API Key（`hithink_api_key`）
- [ ] `.venv\Scripts\python -m pytest tests -q` —— **全绿**（与我这边 Linux 结果一致：506 passed）
      * 测试**不联网**：socket 层被 `tests/conftest.py` 的守卫封死，任何真实外呼都会直接失败
      * 日志里出现"限流/5001"字样是**假客户端合成的错误**，不是真实请求
- [ ] `.venv\Scripts\python -m laoa_trader --cli --pool` —— 能打印空池提示（还没下数据）
- [ ] `.venv\Scripts\python -m laoa_trader` —— **界面能打开**

## 二、策略组自选（新）

- [ ] 「设置」页能看到三个组：**超短·隔日（T+2）/ 短线·T+3 / 波段·T+10**，各自列出成员策略与权重
- [ ] 只勾 `swing`（波段）→ 【保存策略组设置】→ 状态栏提示已保存，**config.toml 里自己的注释还在**
- [ ] 点【立即选股并建池】→ 池子里**只有**低价股策略选出的标的，且「组别」列显示"波段·T+10（T+10）"
- [ ] 再勾回三组 → 池子里重新出现其它组的标的
- [ ] 命令行临时覆盖（不改配置）：`--cli --once --groups ultra,short`、
      `--cli --once --strategies 低价股,连板回踩低吸` → 输出里的"启用的策略组"随之变化
- [ ] `--cli --list-groups` 能列出组/成员/持有期/权重

## 三、自动运行时间（分发后每个人自己设 · 新）

- [ ] 「设置」页能看到「自动运行」：`每天自动运行` 勾选、`主跑时间`（默认 16:00）、`补跑时间`（默认 19:15）
- [ ] **改时间 → 不重启 → 状态栏显示下次运行时间**：把主跑改成 `16:30` → 【保存自动运行设置】→
      状态栏右侧出现「下次自动运行：今天/明天 16:30」（**不用重启程序**）
- [ ] 输入 `25:99` → 保存被**拒绝**、提示格式不对，且 `config.toml` 里 `run_at` **没被改**
- [ ] 补跑填得比主跑早（如主跑 16:00 / 补跑 15:00）→ 保存被**拒绝**并说明原因
- [ ] 主跑填 `09:30`（早于收盘）→ **保存成功**但提示"早于 A 股收盘…建议 16:00 之后"
- [ ] 取消勾选「每天自动运行」→ 保存 → 状态栏显示「下次自动运行：已关闭（每天自动运行）」；
      此时点【立即选股并建池】**仍然能跑**（手动不受影响）
- [ ] 到点验证：把主跑设成"当前时间 + 1~2 分钟"→ 到点自动跑一轮（状态栏/日志能看到）；
      把主跑时间设成已过去的点并重启程序 → 启动后会补跑一次
- [ ] 补跑验证：主跑故意失败（例如拔网线/填错 Key）→ 到补跑时间会**再试一次**；
      主跑成功则补跑**不发生**（日志里没有第二次）
- [ ] 同一天不会重复跑（跑成功后有"成功标记"；手动跑过之后定时点不再重复跑）
- [ ] `--cli --doctor` 能看到：当前主跑/补跑时间、自动运行开关、**下次自动运行**
- [ ] `--cli --run-at 16:30`、`--cli --no-auto-run` 能临时覆盖，且**不改 config.toml**

## 四、随时可以跑（新）

- [ ] 【只刷新数据】→ 进度条走动、状态栏给出"写入 N 行"（不选股、不推送）
- [ ] 【立即选股并建池】→ 后台跑完，状态栏显示"行情日 / 信号 N 条 / 池子 M 只 / 通知：…"
- [ ] **同一天连点两次**：`signal` 与 `stock_pool` 行数不变，且**第二次不重复推送**（状态栏显示"未重复推送"）
- [ ] 断开网络 / 填错 Key 时点这两个按钮：状态栏出现中文原因，**界面不卡死、不弹 traceback**
- [ ] 19:15 定时任务与手动跑出的池子一致（`--cli --pool` 比对）

## 五、通知方式自选（新）

- [ ] 「设置」页勾掉飞书 → 【发送测试提醒】→ 只收到弹窗/托盘，不报错
- [ ] 三个频道全不勾 → 保存后提示"不推送（只入库）"；再点【发送测试提醒】不发送任何东西
- [ ] 勾上飞书但 App ID/Secret 留空 → 提示「未配置飞书凭证，已跳过」，**其余频道照常**

## 六、自选股（新）

- [ ] 「自选股」页：填 `600519` + 备注「龙头」→ 【加自选】→ 名称**自动补全**（本地库有就填上）
- [ ] 填一个库里没有的代码（如 `601999`）→ 提示"本地库没有它的名称…仍按你给的信息添加"，**仍然加得进去**
- [ ] 列表里能看到：代码 / 名称 / 备注 / 状态 / 是否已进池
- [ ] 选中该行 → 【停用】→ 状态变"已停用"；跑一次【立即选股并建池】→ **池子里没有它**；
      【启用】后再建池 → 回来了
- [ ] 【删除自选】→ 列表里消失（`--cli --watchlist list` 也看不到）
- [ ] 命令行：`--cli --watchlist add 600519 --note 龙头` / `list` / `disable` / `enable` / `remove`
- [ ] 自选股**不在热门行业**里，也被保留在池中（策略标的会被过滤掉，自选不会）
- [ ] 池子大小设成 1（或候选很多时）：策略标的只留 1 只，但**自选股一只不少**
- [ ] 某只既是策略选中又是自选 → 池子里**只有一行**，「来源」列显示「… + 自选」
- [ ] 自选股超过 `watchlist_max`（默认 20）→ 日志/状态栏**提示**超过上限，而不是静默丢掉
- [ ] `watchlist_in_pool = false` → 自选只记录不监控（列表里显示"不监控"）

## 七、界面功能

- [ ] 顶栏显示：引擎状态、最新数据日期、今日池子只数、持仓浮动
- [ ] 点【下载/更新历史数据】→ 进度条走动 → 完成后数据日期变成最近交易日
  - 预计 8~15 分钟（默认只导入**最近 5 年**，约 500 万行）；中途关掉再打开应能**续传**
  - 向导里应写明"导入最近 5 年（约 500 万行，8~15 分钟）"，并提示"想要 10 年把 history_years 改成 10"
- [ ] 点【立即选股并建池】→ 池子表格出现约 10 只，含「来源策略」「来源」「备注」「热门行业」列
- [ ] 点某只的【复制条件单】→ 剪贴板拿到"触发价/委托价/数量/止损/止盈"整段文本
- [ ] 持仓页【添加】填代码/名称/数量/成本 → 表格出现该行，止损止盈列按成本计算
- [ ] 五个页签齐全：股票池 / 持仓 / 自选股 / 盘中提醒 / 设置
- [ ] 「设置」页从上到下：自动运行（时间/开关/保存）→ 策略组 → 通知方式（含飞书凭证与测试提醒）
- [ ] 关窗口 → 最小化到托盘（不退出）；托盘菜单能唤回窗口、能退出
- [ ] 点【暂停盘中提醒】→ 状态变化，盘中不再轮询

## 九、交易时段行为（建议工作日盘中做）

- [ ] 09:30–11:30 / 13:00–15:00 之间：按 `intraday_interval`（默认 60 秒）轮询
- [ ] 命中买卖点时：弹出提醒 + 卡片带**条件单参数**
- [ ] **自选股也能收到提醒**：把策略组全关（`enabled_groups = ["none"]`）只留自选股，
      盘中照样有提醒；有持仓时按成本算止损止盈，没持仓按昨收
- [ ] 自选股的提醒文案带备注（例如「自选（龙头，成本 12.40）」）
- [ ] 同一标的同一类型当天**只提醒一次**（不会因为每分钟轮询而刷屏）
- [ ] 非交易时段（午休/收盘后）：不再轮询，日志显示"不在交易时段"

## 十、打包与分发

- [ ] 在 `laoA/` 下双击 `build\build.bat` → 无报错 → 产物 `dist\LaoATrader\LaoATrader.exe`
- [ ] 交付目录本身要干净：**没有 `.venv`、`.pytest_cache`、`__pycache__`、`*.tmpdir`**
      （打包前跑一次 `pytest` 后请删掉这些；`.gitignore` 已列出）
- [ ] **把 exe 复制到另一个目录/另一台机器**单独运行 → 能启动
- [ ] 首次运行 exe：走数据向导、能下数据、config 生成在 exe 同目录或 `%LOCALAPPDATA%`
- [ ] 杀软没误报（若误报：改用 onedir 目录版、或给 exe 加签名/白名单）
- [ ] 数据库位置：`%LOCALAPPDATA%\LaoATrader\data\trader.db`，删掉它应能重建（会重新下数据）

## 十一、出问题时给我这些信息

1. 报错完整文本（含 traceback，别截断）；
2. `python -m laoa_trader --cli --doctor` 的输出（若有该命令，会打印路径/依赖/凭据状态）；
3. 是哪个步骤失败的（对应上面第几节第几条）；
4. Windows 版本 + Python 版本。

> 顺序建议：先做第一节（开发模式），全绿再打包。打包阶段的坑（缺 hiddenimport、
> 路径写死、编码问题）在开发模式下几乎不会出现，所以**开发模式全绿是省时间的关键**。
