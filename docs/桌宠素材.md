# 桌宠形象素材规格（想做"动态桌宠"就看这份）

主人 2026-10-10 问：「宠物形象可以换成动态吗？」
回答：**可以，程序这边已经支持好了**，剩下的是素材 —— 这份文件就是"素材怎么做、放哪里、
一定生效"的说明书。素材做好发给我（或直接放进目录），我一跑就能看到效果，不用先出包。

> **素材已经就位**（2026-10-10 主人给了 8 张机器人立绘）：`assets/pet/` 下是
> `idle-1` / `walk-1..3` / `act-1..2` / `think-1` / `sad-1`，由
> `build/make_pet_frames.py` 从 1024×1024 的立绘缩到 512 生成。
> 预览在 `docs/桌宠动态预览/`：`桌宠预览.gif`（走路循环动图）、`状态一览.png`（五种状态）、
> `桌宠预览-单帧.png`。下面是**换素材时**的规格（改完重跑两个脚本即可）。

## 〇、五种状态与文件的对应（2026-10-10 起）

| 状态 | 文件 | 什么时候用 |
|---|---|---|
| 待机 | `idle-*.png`（旧的 `pet-*.png` 也认） | 站着歇着 |
| 走路 | `walk-*.png` | **平时在桌面右下角活动**：在落点附近左右溜达 |
| 动作 | `act-*.png` | 有提醒时按顺序播一遍（没有就退回"蹦两下"） |
| 干活中 | `think-*.png` | 有任务在跑（下载/刷新/筛选） |
| 亏了 | `sad-*.png` | 止损/跌破这类坏消息的提醒 |

帧间隔固定为 **180ms**（约 5.5 帧/秒，主人要求"帧数不要过快"），走路每帧横移 3 像素
（约 17 像素/秒），并且**只在落点左右各 120 像素内**活动 —— 它是常驻桌面的，
不是满屏乱跑的玩具。自己在代码里调的话只看 `ui/desktop_pet.py` 顶部的
`FRAME_MS` / `WALK_STEP` / `ROAM_RANGE`。

## 一、两种交付形态（选一种就行）

| 形态 | 怎么放 | 优点 | 缺点 |
|---|---|---|---|
| **PNG 序列帧（推荐）** | `src/laoa_trader/assets/pet/pet-1.png`、`pet-2.png`…（按序号） | 透明是 8-bit alpha，深色桌面上边缘**干净** | 文件多几个 |
| **GIF** | `src/laoa_trader/assets/pet.gif` | 一个文件搞定 | GIF 透明只有 **1 bit**（要么全透要么不透），角色边缘常有一圈白边 |

两条路都认，**同时存在时用序列帧**（就是上面那个理由）。原来的单张图 `assets/pet.png`
继续有效：一旦放上序列帧或 GIF，程序自动改用动态的，**不用改任何设置、也不用改代码**。

## 二、序列帧的命名（程序就是按这个找的）

```
src/laoa_trader/assets/pet/
├── idle-1.png     待机
├── walk-1.png     走路循环（必须有 ≥2 帧才算循环）
├── walk-2.png
├── walk-3.png
├── act-1.png      有提醒时的动作（按序号顺序播一遍）
├── act-2.png
├── think-1.png    干活中
└── sad-1.png      亏了/止损
```

- 序号**按数字**排序（`pet-2` 排在 `pet-10` 前面），补零或不补零都行；
- 名字里没数字的（`pet-旧.png`）不参与，放着不会出错；
- `act-*` 没有的话，"来消息"照旧是**蹦两下**（老行为）；有 `act-*` 就改成播那一小段动作 ——
  两者不同时上（动作帧里通常已经画了位移，再叠蹦跳会显得乱）。

## 三、图本身的要求

- **正方形**、透明底 PNG；建议 **512×512**（程序会缩到桌宠的 180×180 显示，多大的方图都行，
  但太小的会糊、太大的没必要）；
- **角色居中、四周留 4~8 像素空隙**（贴边会被裁）；待机帧之间**角色的脚底位置尽量一致**，
  否则看起来是在"抖"而不是在"呼吸"；
- **别用绿幕 / 棋盘格 / 白底**当背景 —— 我们不抠图，原样贴上去；
- 帧数节奏建议：
  - 待机：**8~16 帧**，约 **8 帧/秒**（一圈 1~2 秒），首尾要接得上（第 1 帧与最后一帧
    差别小一点），不然循环处会"跳"一下；
  - 动作（`act-*`）：**6~12 帧**，播一遍就回待机；
- 幅度**宁小勿大**：桌宠是常驻桌面的，动作大了会抢注意力（现在的演示帧上下只浮 4 像素、
  缩放 3%）。想要更活泼也行，看到效果再调。

## 四、素材从哪来

1. **AI 工具生成**：即梦 / 可灵 / Runway 这类"图生视频"或"角色动画"工具，输入现在这张
   `assets/pet.png`，生成一小段循环动作，导出 **GIF** 或 **序列帧**（多数工具能导 MP4——
   那就用 `ffmpeg -i 动作.mp4 -vf fps=8 帧/pet-%d.png` 拆帧，透明底需要在生成时就要求）；
2. **现成的动态宠物素材**（透明底 GIF/APNG，注意版权）—— 直接按上面的路径放进去；
3. **让我做**：把想要的风格说清楚（比如"眨眼 + 尾巴摇"），我可以用程序化方式做一版
   （就像现在这份演示帧），但**手绘级的形变我做不出来**，效果上限就是"整张图轻微呼吸摆动"。

## 五、做好之后怎么验（我这边 / 你这边都同一条命令）

```bash
cd <仓库>/laoA
# ①（换素材时才要）把立绘切成程序认的帧：默认读工作区那个素材目录
python build/make_pet_frames.py "/vol4/@apphome/dsh/选股/图标宠物素材/宠物素材"
# ② 出预览：动图 + 五种状态一览
QT_QPA_PLATFORM=offscreen python build/make_pet_preview.py
QT_QPA_PLATFORM=offscreen python build/make_pet_preview.py --demo   # 没素材时看效果
```

输出在 `docs/桌宠动态预览/`：`桌宠预览.gif`（动图，双击就能看）+ `桌宠预览-单帧.png`。
预览是**按真实控件抓的**（缩放、透明、帧率都一致），所以"预览里什么样、装进程序就什么样"。
看过觉得行，我再出包（桌宠的动效不需要任何开关，放上素材就生效）。

## 六、程序这边已经做了什么（供排查）

- 素材加载优先级：**序列帧 > GIF > 单张图**（`ui/desktop_pet.py` 的 `_load_assets`）；
- 待机按 `FRAME_MS = 180`（≈5.5 帧/秒，"帧数不要过快"）循环；**桌宠被藏起来时自动停**
  （常驻桌面也不能白烧 CPU）；走路帧在"走一段、歇一会儿"之间切换（随机时长，免得像节拍器）；
- 有 `act-*` 时，"来消息"播一遍动作再回待机；没有就回到"蹦两下"；
- 坏帧文件只跳过它自己（一张坏图不会让整只桌宠降级成手画的）；
- 一张素材都没有时，仍然画那个手画小圆脸（桌宠绝不会因为没素材开不起来）。
- 用例在 `tests/test_pet_frames.py`（12 条）：排序按数字、不可见时暂停、动作播一遍、
  不同时蹦跳、GIF 走 `QMovie`、序列帧优先于 GIF、单图行为不变、坏帧跳过、窗口属性不变。
