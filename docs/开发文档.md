# 开发文档（luweik决策系统 · Windows 单机版）

面向**下一个接手这个项目的人**。目标：读完这一份就能改代码、跑测试、打包、发版，不用先去啃 8000 行的 `ui/app.py`。

- 当前版本 `1.7.1`，Python ≥ 3.11，PySide6 + SQLite，默认构建方式是 **Nuitka 编译**（PyInstaller 是备用路径）。
- 代码根目录：`laoA/`；包在 `src/laoa_trader/`。
- 所有事实以**代码**为准。文档只解释"为什么"，不重复代码里已经写清楚的实现细节 —— 这个项目的注释密度很高，读代码本身就是最快的路径。

## 0. 改名历史（维护者必读）

这个产品改过**三次**名。前两次只碰「用户看得见的名字」；**第三次（2026-10-08）连数据/配置
目录名也一起改了** —— 主人要求「不留以前名称的痕迹」，当时只有他一个人在用（见下面那一段）。

| 时间 | 名字 | 为什么改 |
|---|---|---|
| 初版 | `老牛选股` | —— |
| 2026-09-30 | `财神助手` | 平台不许发带「选股 / 荐股」字样的东西 |
| **2026-10-08** | **`luweik决策系统`**（短自称 `luweik`） | **又被限流**：在闲鱼 / 小红书上，名字里带「选股 / 荐股」类字眼照样被拦，所以这次的名字里**一个这类字都没有**；主人同时要求「数据与配置目录也改掉、不留以前名称的痕迹」（当时只有他一个人在用） |

名字分三层（下次改名照这张表改，别混起来）：

|---|---|---|
| 界面显示名 | `luweik决策系统` | 窗口标题、「关于软件」、托盘 tooltip、托盘消息、测试提醒标题 |

| 打包名 | 目录 `LuweikDecision` / exe `luweik决策系统.exe` | 产物目录、zip、CI artifact |

**改名时先想清楚的两件事**（2026-10-08 的第三版是主人拍的板，不是默认做法）：

* **数据/配置目录名这一次跟着改了**（`config.DEFAULT_APP_NAME = "LuweikDecision"`、
  slug `luweik-decision`、日志 `luweik.log`）。能这么干的前提是"只有作者一个人在用"——
  目录里有几年日线（几百 MB）与授权/试用状态。**有外部用户之后**再改名，正确做法是
  "先搬一次家再换名"（`shutil.move`，只在新位置还不存在时做），否则老用户的库会变成
  没人再读的孤儿目录、试用天数还可能重置。上一版（改名到「财神助手」时）就是这么留了
  `LEGACY_APP_NAMES` 那套搬迁逻辑的；这一版按主人要求把那套连同旧目录名一起删掉了。
* `pyproject.toml` 的 pip 分发名与包目录 `src/laoa_trader/` 里的 **import 名**：
  后者用户完全看不见，改它要动 100+ 处 import、打包清单与测试，所以**保留**
  （`laoa` 是初版"老A/老牛"的缩写，属于历史包袱，但与用户无关）。

名字的看门用例在 `tests/test_version.py`：三个旧名（`老牛选股` / `财神助手` /
`CaishenTrader` 系列）都在它的黑名单里，所以本文件的这段历史是**唯一**允许出现旧名的地方。

## 1. 架构与模块职责

### 1.1 分层总览

```
入口      __main__.py（GUI 默认；--cli 走命令行）→ ui/app.py:run_gui()
界面      ui/            只做展示与转发，耗时操作全丢 QThread
业务      pool.py        建池（策略标的 + 自选标的合成一张池子）
          scheduler.py   日更流程、数据闸门、后台线程调度
          intraday.py    盘中规则、条件单参数、竞价扫描
          market.py      大盘概览的取数与排版
          formulas.py    公式库（文件、配置、试算、成绩单、口径决策）
策略      strategy/formula.py        引擎：文本 → AST → 白名单求值
          strategy/formula_group.py 把勾选的公式跑成池子候选
数据      data/          同步、存储、各数据源客户端、自检
通知      notify/        飞书 / 托盘 / 提示音 / 语音
基础设施  runtime clock wording legacy config assets state log hints price_limits
```

**边界原则**：界面层不查库、不发请求；策略与提醒层不碰 Qt；数据层不认识"池子"这个概念。跨层调用的出口都收敛在少数几个函数上（`run_daily`、`build_pool`、`prepare_inputs`、`data_gate`），改一处就够。

| 文件 | 职责 | 边界 |

| `ui/app.py` | 主窗口：标题区 + **五个页签**（大盘概览 / 自选标的 / 持仓监控 / 策略筛选 / 系统设置）、托盘、`_tick` 定时对账、把各模块接起来 | 只展示与转发；所有耗时操作进 `QThread`；关窗 = 最小化到托盘 |

### 1.3 `data/`（数据层）

| 文件 | 职责 | 边界 |
|---|---|---|
| `data/engine.py` | `DataEngine`：策略/建池/提醒共用的**读接口**门面 | 只读；所有行情读 `stock_daily_hfq` **视图**（后复权） |
| `data/storage.py` | 建表 DDL、唯一写入口 `upsert()`、老库补列迁移、自选/持仓/信号/提醒的读写 | 只 upsert 不删；`connect()` 自动建库建表 |
| `data/sources.py` | 数据来源注册表与**单位归一**：`snapshot_map()` / `supplement_map()` | 界面不要自己判断"有哪些来源、谁先取" |
| `data/hithink.py` | 同花顺 REST 客户端（主源） | 只取数转结构，**不写库** |
| `data/public_quotes.py` | 腾讯为主、新浪兜底、东财补齐的免 Key 行情 | 只取数 + 归一单位，不管优先级 |
| `data/public_market.py` | 免 Key 的"同花顺客户端替身"（同样三个方法）+ 全市场扫描 | 每一路只"少一项"，**绝不编数** |
| `data/public_sync.py` | 免 Key 日更：一趟全市场快照出当日日线 + 涨停池 + 代码表 + 日历 | 复权靠快照昨收反推（见下） |
| `data/eastmoney.py` | 东财免 Key 第二源（快照 / 日K / 代码表） | `fltt=2` 是元、不带是分，口径是**显式参数** |
| `data/sectors.py` | 行业板块排行（走腾讯），主力净额万元 → 元 | 短缓存 60 秒；失败不进缓存 |
| `data/market_map.py` | 板块热力图的数据层：全市场快照 + 行业归属 → 行业方块（面积 = 流通市值合计）| 纯函数、不碰 Qt；拿不到的数**不写 0**（灰块 + `—`）；带磁盘缓存 |
| `data/sync.py` | 同花顺那三条同步路径 + `daily_update()` 分派 | 对外**都不抛异常**，一律返回 `SyncResult` |
| `data/preflight.py` | 运行时自检：`ready` / `needs_incremental` / `needs_full` 三态 | 纯本地、秒级、**一次请求都不发** |

要点：

- **复权分层**：`stock_daily_raw` 存不复权原始价 + `factor` 列，`stock_daily_hfq` 是**视图**（价格 × factor）。好处是复权事件更新后不必重写几百万行价格。
- **免 Key 怎么做到复权仍然对**：腾讯快照的昨收是交易所**调整过的前收盘**。等于库里最后一根收盘 → 今天没除权；不等 → 今天除权了，`k = 库里前收 / 快照昨收`，今天因子 = 上一根因子 × k。不需要事件明细，一只票一个昨收就够。
- **涨跌停规则只有一处**：`price_limits.py`。日更判涨停、池子显示、公式引擎的 `ZTPRICE()`/`DTPRICE()` 全部从那里取，各写一份迟早出现"日更说涨停、公式说没涨停"。
- **无 Key 时自动改道**：`sync.daily_update()` 拿不到同花顺客户端时，延迟导入 `public_sync.daily_update_public()`。分派只写这一处，界面/定时/CLI 三个入口行为才不会各说各话。

### 1.4 `strategy/` 与 `formulas.py`（策略与公式）

**`strategy/formula.py`（约 3500 行）= 引擎**，只管"把文本变成能算的东西"：自己写的 tokenizer → 递归下降 AST → **白名单求值器**。整条链路**没有任何 `eval`/`exec`/`compile`/动态 `getattr`** —— 公式是用户可编辑文本、程序还要分发给别人，接上 `eval` 等于交出 `__import__("os").system(...)`。

两条必须记住的语义：

- **缺值（NaN）比成 False，不是抛异常也不是当 0**。停牌、上市不足 N 日、窗口不够长每天都会出现，所以"缺值永远不产生信号"是唯一安全的默认。内部约定：条件型值也是 `0/1/NaN` 的浮点序列，沿 AND/OR/NOT/COUNT/IF 传播，只在最后折成布尔。特别地 `=`/`!=` 必须显式把缺值掩成 NaN（IEEE 下 `NaN != 5` 是 True，会把停牌日变成信号）。
- **绝对不用 `eval`**，也绝不用正则黑名单拦危险输入。

**`strategy/formula_group.py`（约 290 行）= 把勾选的公式跑成池子候选**，只暴露 `run_enabled_formulas()`。两条硬规矩：① `enabled_formulas` 为空时**一次库都不读**；② **失败隔离** —— 某条公式在某只票上算不出来只记日志 + 记进 `status`（界面标红）+ 从本批候选里去掉，其余公式照常出票。

**`formulas.py`（约 1280 行）= 公式库外壳**：目录定位、保存/删除、参与筛选名单、试算、成绩单、**K 线口径决策**。文件后缀 `(".txt", ".tvf")`（`FORMULA_SUFFIXES`），注释头 `# 名称:` / `# 说明:` 由本模块拼，不让用户在编辑框里写。

### 1.5 `pool.py` 与 `scheduler.py`

**`pool.py`** —— 池子成员两类：**策略标的**（勾选的公式 → 候选 → 打分 → 每条最多 3 只 → 取前 `size`）+ **自选标的**（不占策略名额、不受热门行业过滤、有独立上限 `watchlist_max`）。候选**只来自勾选的公式**，别的一律丢掉。

**`scheduler.py`** —— 日更流程、数据闸门、后台线程。一个守护线程 `_loop` 每 1 秒醒一次，判断两件事：到点跑日更、交易时段跑盘中提醒。**所有异常都在线程内捕获**并写进 `status()["last_error"]`（后台线程静默死掉是桌面程序最难查的 bug）。

### 1.6 `intraday.py` 与 `market.py`

**`intraday.py`** —— 6 条盘中规则（止损/止盈/跌破 5 日线/涨停打开/放量突破 20 日高/池内回踩买点）+ 2 条**只对自己持仓**发的做T近似提示（`t_high`/`t_low`，默认关）。本项目**只到 L2**：提醒 + 条件单参数，不写任何真实下单代码。另有集合竞价全市场扫描（`auction_scan`，到点才扫）。

**`market.py`** —— 大盘概览的**取数与排版只有一份**（界面拿"一个指标一个值"，命令行拿拼好的整行）。三条硬规矩：降级优先（任一路失败只少那一项）、TTL 与界面时钟解耦、涨跌家数单独一档 5 分钟缓存。

> 边界提示：`market.notify()` / `toast_icon()` 是 Windows 原生 Toast 的旧路径，**当前没有任何调用方**（通知频道注册表只有 `feishu` / `tray`）。改通知时不用管它。

### 1.7 `notify/`（通知）

`notify/__init__.py` 是唯一入口 `notify_all()`：**线程池并行、互相独立、绝不抛异常**，每个"被考虑过"的频道都返回一条结果（便于界面解释"为什么没收到"）。

| 频道 | 实现要点 |
|---|---|
| `feishu` | 自建应用：先换 `tenant_access_token` 再调 `im/v1/messages`；凭证没配齐返回 `skipped` 不算失败 |
| `tray` | 后台线程只往线程安全队列里放消息，界面 `QTimer` 定期 `drain()` 再弹气泡（Qt 控件只能在其所属线程里操作） |
| `sound` | 只用标准库 `winsound` + 系统声音别名；非 Windows 静默跳过；必须 `SND_ASYNC`（否则"点一下卡一下"） |
| `voice` | PowerShell + `System.Speech`，不引任何新依赖、不联网；后台守护线程按顺序念，**没有中文音色就不念** |

**没有 `notify/windows.py`**：Windows 原生通知整路删掉了，`config.REMOVED_CHANNELS` 里写着原因，老配置里写着 `"windows"` 也不会报错（显示成"该频道已删除"）。

### 1.8 基础设施模块

| 模块 | 一句话职责 | 为什么单独存在 |
|---|---|---|
| `runtime.py` | 回答"我是哪种运行形态、随包文件在哪" | 三种形态下"随包数据在哪"完全不同，写死 `_MEIPASS` 会在 Nuitka 上静默出错 |
| `clock.py` | **全项目唯一的时钟来源**（北京时间、朴素值） | 机器时区不一定是北京时间；日期与时间戳必须同一口径 |
| `wording.py` | 给人看的字：来源列只写策略名本身 | 只改显示、一个字节的数据都不改；显示口径必须只有一份 |
| `legacy.py` | 老数据的显示口径（类名→中文名）+ `signal` 表写入 | 老库里的数据不会消失，界面读它时必须还能显示中文名 |
| `config.py` | 配置读取、默认值、写回、老位置迁移 | 配置读不到会让界面起不来，所以 `load_config()` 承诺**绝不抛异常** |
| `assets.py` | 随包图标的位置解析 | "图标在开发机上有、到用户机器上没了"是这类代码的经典毛病 |
| `state.py` | 全局运行态"有没有正在下载"（引用计数） | 下载期间调度线程不能在只写了一半的库上跑筛选 |
| `log.py` | 统一格式 + 写文件 + 控制台 | 双击运行的桌面程序出问题时用户看不到控制台 |
| `hints.py` | 指路文案（按钮名 + "下一步点哪个"） | 按钮名只有一处是真的，指错路会让用户白等一场重下 |
| `price_limits.py` | 涨跌幅限制与涨跌停价（唯一规则源） | 见 1.3 的说明 |

## 2. 关键数据流

### 2.1 匹配链路

```
【开始筛选】/托盘菜单/定时任务/CLI --once
        │
        ├─1─ 数据闸门 scheduler.data_gate()
        │      正在下载 → 拒绝      预检 needs_full → 拒绝并指路
        │      ready / needs_incremental → 放行
        │
        ├─2─ scheduler.run_daily()
        │      ① 数据增量  sync.daily_update()
        │      ② 建池      pool.build_pool()  → 内部跑公式组、打分、并自选、落库
        │                  legacy.save_signals()（signal 表，供盘中观察池）
        │      ③ 桌面导出  pool.export_pick_file() → 桌面/luweik/*.txt
        │      ④ 消息      _record_pool_message() → intraday_alert 里记 kind="pool"
        │      ⑤ 推送      notify_all()（同一天同一份内容只推一次）
        │
        └─3─ 结果回到界面：结论 +「策略筛选」页结果表 + 状态栏
```

**所有入口共用同一个 `run_daily()`**（`scheduler.run_serve` 的 `--once`、`Scheduler.run_daily_now`、主窗口的 `on_run_pipeline`）。界面那两条路（「策略筛选」页的【开始筛选】、托盘同名项）都**先 `data_gate()` 再 `run_daily()`**；定时任务走 `Scheduler._maybe_daily()`，多了"正在下载 / 数据不可用就跳过、且**不写成功标记**"两道闸门 —— 所以数据就绪后当天仍会自动补跑一次。

**幂等靠三个键**：信号按 `(行情日, 策略, 代码)` upsert、池子按 `(行情日, 代码)` upsert + batch 清理、推送按**内容指纹**去重（`push_log`）。

**`save_picks=False`**：筛选结果**不自动进股池**，`stock_pool` 只落自选标的（用户自己加的、或在结果页点【加入自选】加的）。但不是"整条建池都不做" —— `stock_pool` 同时是**盘中监控的盯盘清单**，自选标的必须继续被盯着。选出来的票仍会：① 显示在结果页；② 导出到桌面；③ 进 `signal` 表。

### 2.2 筛选口径规则（本项目最重要的设计）

**规则一句话**：**开盘时间里跑的筛选都是实时的，不是开盘时间才采用 K 线。** 这是**内置规则**：没有配置键、界面上没有勾选框（有用例钉着"关不掉"）。

用户在盘中点【运行】/【开始筛选】，用的就该是此刻的盘面；但日更要到收盘后才有"今天"这根 K 线。所以盘中必须**自己把今天这一根拼出来** —— 拼出来之后，用户已经写好的公式（`C`、`C/REF(C,1)-1`、`量比()`、`C>MA(C,5)`）**一个字都不用改**就全变成盘中口径。这是"内置规则"与"再教用户写一条盘中策略"的区别。

**实现点**（`formulas.prepare_inputs` → `strategy/formula.py`）：

| 环节 | 位置 | 说明 |
|---|---|---|
| 口径决策 | `formulas._live_decision()` | 三条判据 + 一条数据条件，全过才走实时 |
| 拼今天的 K 线 | `formula.LiveBar` + `formula._live_arrays()` | 快照是**不复权价**，库里的列是**后复权价**，换算只需一个比例 |
| 接到日线后面 | `formula.load_series(today=…, live_bars=…, kline_day=…)` | 逐只决定接不接；接完把 `pre_close` 也补一格 |
| 打包给两条路 | `formulas.Prepared` | 试算与建池**共用同一个 `prepare_inputs`**，口径不可能分叉 |

**四条退回条件**（任何一条不成立就退回日 K，并**在结果里说清是哪一条**）：

1. 现在不是开盘时间（`intraday.in_session()`：9:30–11:30 / 13:00–15:00，北京时间）；
2. 今天是休市日（读库里 `trading_calendar`）—— 只看钟点会把上一交易日的快照当成"今天的盘"，选出一批 `pct=0` 的假信号；
3. 库里已经有今天这一根 K 线了（`kline_day >= today`）；
4. 取不到实时快照。

前三条在 `_live_decision()` 里判，第 4 条在 `prepare_inputs()` 里判：**想要实时却拿不到数据时，走 `warnings` 而不是 `notes`** —— 建池的"成功/失败"判据是"`errors` 是否为空"，把一句告知塞进 `errors` 会让一次**正常完成**（票选出来了、推送也发了）的筛选被判成失败并安排补跑。

**逐只接不接的细则**（`_live_arrays`，任一不满足就返回 `None`，即这只票照旧按日线算）：

- 库里最后一根 >= 今天 → **不接**（同一天两根会让 REF/MA 这些窗口函数全部错位）；
- 库里最后一根**不是全市场最新行情日**（`kline_day`）→ 不接（停牌/退市/好多天没开机的票，接了等于按一个断了好几天的缺口算涨幅，那是假的。`kline_day` 由 `prepare_inputs` 一起给出，调用方不该再查一次 `MAX(date)` —— 两次查询之间数据可能变，"接没接今天那根"与"跳过哪些票"就会按两个不同的日子判）；
- 缺现价或缺昨收 → 不接，**绝不编一个昨收出来**（"少算一只"与"算错一只"之间选少算）；
- 缩放比例算出来不是有限正数 → 不接。

**换算口径**（唯一容易搞错的地方）：设库里最后一根后复权收盘为 `hfq_last`、快照昨收为 `adj_prev`，那么

```
今天的后复权价 = 现价 × hfq_last / adj_prev
```

这个比例同时含了历史因子与今天的除权步长，于是 `今天的后复权收盘 ÷ 昨天那根` 正好等于 `现价 ÷ 昨收` = 今天的真实涨幅。

**扩展字段的铺法**：`流通市值`/`换手率`/`现价`/`现涨幅`/`现量比`/`现换手` 只有"今天"这一个值，铺成"末尾有值、前面全 NaN"的序列。前面填 NaN 是为了让"历史上根本没有这个数"如实体现 —— 谁写了 `MA(流通市值,5)` 会得到全 NaN，而不是一条看起来很合理的假均线。**接今天那根必须在这之前做**：扩展字段是按 `len(dates)` 铺的，先铺后接会让那个值落到"昨天"上，`现价>MA(C,5)` 里的"现价"就变成了昨天的价，而界面上完全看不出来。

**快照只取一趟**：实时口径要拿同一份快照既拼 K 线又填扩展字段。取两次会看到两个时刻的盘面 —— K 线里的涨幅与 `现涨幅` 对不上，那是最没法解释的一类不一致。一条快照字段都用不到、且不在开盘时间时，**一个请求都不发**。

**成绩单永远只用库里的日 K**（不带 `today`/`live_bars`）：它算的是"这条公式在历史上行不行"，塞一根还没收盘的"今天"进去等于拿没有结果的样本算胜率。

**"口径提示"出现在三处**（外加日志里一行）：

1. 「策略筛选」页【运行】结果的提示区**第一行**（`formulas.preview_hits()["caliber"]` → `ui/formula_page.py`）；
2. 【开始筛选】结果页**结论的最后一行**（`pool.build_pool()` 写进 `report["formulas"]["caliber"]`）；
3. 主窗口状态栏的筛选结论（`ui/app.py:_on_pipeline_done`）；
   （另：`strategy/formula_group.run_enabled_formulas()` 会把它记进日志。）

文案形如 `📊 本次口径：盘中实时（10:32，用现价拼出今天 2026-09-25 这根 K 线）` / `📊 本次口径：日 K 线（最后一根 2026-09-24；现在 20:11 不是开盘时间）`。**是纯文本不是 markdown** —— 写 `**加粗**` 用户看到的就是两个星号。

### 2.3 来源口径：来源列只写策略名

用户要的是"**这一列回答是哪条策略选出来的**"，所以：

| 场景 | 界面「来源」列 | 库里存的值 |
|---|---|---|
| 公式选出来的 | `尾盘匹配策略` | `公式·尾盘匹配策略`（`stock_pool.strategy`） |
| 老内置策略的历史行 | `短期反转` | 类名 `ReversalStrategy` |
| 用户手工加的 | `自选` | `watchlist.source_strategy = NULL` |

- **只改显示，一个字节的数据都不改**：目录还叫 `formulas/`、配置键还叫 `enabled_formulas`、代码标识符全原样，升级不迁移数据、不回写历史行。
- 剥前缀的唯一出口是 `wording.display_strategy()`（同时剥 `公式·` 与老的 `策略·`），剥尾巴的唯一出口是 `wording.strip_watch_suffix()`（剥老的 `+自选`）；来源列走一条龙 `wording.display_source_label()`。
- 判断"这一行是不是自定义策略"仍然看 `公式·` 前缀（`formula_group.is_formula_strategy`）—— 那是**数据里的值**，不是给人看的字，不能跟着改。
- **不做全文替换**：用户自己起的名里可能真带"策略"或"公式"（"我的策略一"），一个字都不动。
- 老数据救回：备注里的 `匹配来源：X` 由 `pool.watchlist_source_strategy()` 认一次（只是退路，不是主路 —— 备注是用户自己的字段，随时会被改掉）。

### 2.4 池子计数互斥（策略 M + 自选 K = 总数 N）

`pool.pool_counts()` 的口径：

- **策略 M** = 有 `strategy` 的行（自定义公式与老内置策略都算）；
- **自选 K** = **没有**策略来源、由用户手工加进来的行；
- 于是 **M + K 恒等于 N**（每只票要么是选出来的、要么是你自己加的）。

表头那一行小字、以及 `build_pool()` 结尾的日志，用的是同一个函数 —— 否则会出现"共 13 只（策略 12 · 自选 12）"这种看着就像算错的行。同一只票既是策略选中又是自选时，池子里**只出现一行**，来源写那条策略名；"它在不在自选里"由行上的 `watchlist` 标记与监控开关那一列表达。

### 2.5 盘中提醒 / 消息中心 / 桌宠的关系

```
intraday.run_once()  ← 调度器交易时段每 60 秒一拍
   ├─ build_alerts()      6 条规则 + 做T提示（只看快照字段，不查历史）
   ├─ record_alerts()     写 intraday_alert，(date,symbol,kind) 主键去重 → 只拿到"首次出现"
   ├─ 推送                 notify_all()（飞书/托盘）
   └─ 竞价到点 → auction_scan()（全市场 56 批、20~30 秒）→ auction_scan 表 + 汇总推送

主窗口 _tick()（每 5 秒与库对账）
   ├─ ui/alert_popup.py      右下角滑出浮窗（默认关）；点一条看详情
   ├─ ui/message_center.py   「消息」列表：盘中提醒 + 筛选完成（同表不同 kind）
   ├─ 托盘图标闪烁
   ├─ notify/voice.py        中文朗读（后台队列）
   └─ ui/desktop_pet.py      常驻桌面 + 冒气泡 + 蹦两下
```

六条口径：

- **一个列表收纳所有消息**：盘中提醒与"筛选完成"都在 `intraday_alert` 里，靠 `kind` 区分（`kind="pool"`）。多造一张表就多一处口径。
- **跨线程只能靠库与信号**：后台线程把消息放进 `intraday_alert`，主窗口每 5 秒对账后刷新界面。消息窗口**不查库**，数据由主窗口喂。
- **浮窗是"消息自己蹦出来"，消息列表是"图标闪、你自己点开看"**。用户要的是后者，所以 `notify_popup` 默认 `false`，浮窗留着但默认关。
- **观察面 = 持仓 + 用户打开监控的自选标的**（2026-10-05 起）：筛选结果与池子里的票只是**候选**，默认一只都不盯（主人："默认只监控持仓股票"）；把某一行的监控开关打开（写进 `watchlist.enabled`）它才进观察面。持仓跑卖出/风控规则 —— 止损止盈按**持仓成本**、跌破 5 日线/涨停打开按本地历史；做T提示单独受 `intraday_t` 管（默认关）。
- **交易日判据不许因为日历滞后就说"休市"**：日历里有今天 → 交易日；周末 → 不是；日历**已越过**今天却没有它 → 真休市；日历最新只到昨天（今早还没同步）→ 按交易日处理。判错的代价不是"少一条提醒"，而是**整天全哑、且界面上毫无提示**（2026-09-28 主人实报"盘中提醒无效"）。
- **选股结果只发一条门铃**：`kind="pool"` 的正文固定是「选股结果已出，请点击查看」（不列票名、不报涨跌），而且**默认不念**（`intraday.VOICE_OFF_BY_DEFAULT`）—— 念出来一个字的信息量都没有，要看就去结果页。
- **"没提醒"与"提醒跑不起来"必须分得出来**：`intraday.report_text()` 把一轮的结果（盯了几只/命中几条/新增几条，或为什么没跑：非交易日、不在时段、没配 Key）写成一句中文，【检查盘面】按钮、状态栏的"盘中提醒时段中（10:31 盯 12 只，命中 0 条）"、【详情】三处共用它。

库文件：`<数据目录>/trader.db`（`Config.db_path`）。连接一律走 `storage.connect()`：WAL 模式（GUI 与后台线程可同时访问）、`synchronous=NORMAL`、**缺表就整套补一遍**（全是 `IF NOT EXISTS`，所以老库升级不需要删库重下几十年数据）。

| `auction_scan` | 竞价扫描的**全部命中**（含没推送的那几十只）；主键 `(day, slot, symbol)` | `intraday._push_auction_scan` → `storage.write_auction_scan` | 竞价详情【看全部】、复盘 |

| `app_state` | 键值小表（授权记账用） | **`licensing._db_write` 自己按需建**（不在 `storage.SCHEMA` 里） | `licensing._db_read` |

### 3.2 几条必须知道的口径

- **`auction_scan` 为什么不用 `intraday_alert`**：后者只存"推给用户的前 N 只"，而用户要能在详情里看**全部命中**（含原始数值与分数）。同一时刻重扫是**覆盖**而不是追加（追加会让"命中 37 只"变成"命中 74 只"）。
- **`stock_pool` 的 `batch` 列**：同一次运行写下的所有行打同一个批次号，写完再删掉"同一天里 `batch` 不是本次"的残留行。**不能按日期 DELETE 再 INSERT** —— 中途失败当天池子就空了。批次号 = 进程号 + 进程内自增序号 + 随机后缀（不能只靠时钟：Windows 系统时钟粒度约 15.6ms，同一个 tick 里两次调用会撞号）。
- **老库补列**：`storage._ADDED_COLUMNS` 每次 `connect()` 都跑一次（一次 `PRAGMA table_info` + 最多几条 `ALTER TABLE`）。换来的是"老库直接能用新功能"。目前有 `position.monitor`、`watchlist.added_price`、`watchlist.source_strategy`。
- **`watchlist.added_price` / `source_strategy` 都是"只补空值"**：`COALESCE(已有值, 本次值)`。否则用户今天再点一次【加入自选】，盈亏基准与来源就被重置了。
- **时间戳一律按北京时间写**（`storage._now()` → `clock.stamp_cn()`）。库里 `date` 是北京日期、时间戳若是机器本地时间，UTC 机器上就会出现"日期是今天、时间戳是昨天"。
- **`position` 的"未平仓"判据是 `quantity > 0 OR closed_at IS NULL`**：改版后界面【添加持仓】只收"代码 + 成本价 + 备注"，新行 `quantity = 0`，老判据会让手工加的持仓永远不出现。

## 4. 配置与路径

### 4.1 用户可见的路径

| 东西 | Windows 位置 | 代码 |
|---|---|---|
| 配置文件 | `%APPDATA%\LuweikDecision\config.toml` | `config.user_config_path()` |
| 数据库 | `%LOCALAPPDATA%\LuweikDecision\data\trader.db` | `config.default_data_dir()` + `Config.db_path` |
| dump 缓存 | `<数据目录>\dumps\` | `Config.dump_dir` |
| 日志 | `<数据目录>\logs\luweik.log`（2MB × 3 份轮转） | `log.setup_logging()` |
| 授权状态 | `%APPDATA%\LuweikDecision\license.json` | `licensing.state_path()` |
| 用户公式 | exe 同级的 `formulas/` | `formulas.formula_dir()` |
| 桌面导出 | `桌面\luweik\luweik-筛选结果-<日期>.txt` | `pool.export_pick_file()` |

**配置文件为什么放在 `%APPDATA%` 而不是 exe 同级**：更新软件是"整包覆盖那个目录"，放 exe 旁边会被一起盖掉（用户的飞书 app_id/secret、自选、持仓会全没）。同理 `license.json` 与 `config.toml` 同目录。

**老位置自动迁移**：`config._migrate_legacy_config()` 在"新位置没有、老位置有"时**复制**（不是移动）一次，老文件留着当保险；失败只记日志、绝不抛异常（迁移只是锦上添花，配置读不到会让界面起不来）。

**查找顺序**（`config.config_search_paths()`）：环境变量 `LUWEIK_CONFIG` → 用户目录 → 当前工作目录 → exe 同级 / 仓库根（老位置）。**保存永远写用户目录那一份。**

**可用的环境变量**：`LUWEIK_CONFIG`、`LUWEIK_FORMULAS`（公式目录）、`HITHINK_FINANCE_API_KEY` / `FUYAO_TOKEN` / `API_KEY`（同花顺 Key）、`DATA_SOURCES`、`INTRADAY_T`、`INTRADAY_POOL_ONLY` 等（见 `config._apply_env` 与 `intraday.py` 顶部的常量）。

### 4.2 随包资源的三种形态（`runtime.py`）

| 形态 | 随包只读数据 | 用户可写目录 |
|---|---|---|
| 源码运行 | 仓库里（`laoA/formulas/`、`src/laoa_trader/assets/`） | 仓库根 |
| PyInstaller onedir | `sys._MEIPASS`（解包目录） | exe 同级 |
| **Nuitka standalone（默认）** | **exe 同级**（`--include-data-dir` 的落点在产物目录） | exe 同级 |

Nuitka 编译后的每个模块里都会多一个 `__compiled__` 属性，所以 `"__compiled__" in globals()` 是最直接的判据；`sys.frozen` 也顺带认，三条判据**取并集**（宁可多认，也别在某个版本上退回"当成源码运行"，那会让用户可写目录跑到程序安装目录里）。

**为什么必须收成一处**：这三种判断原先散在 `assets.py` / `formulas.py` / `config.py` 里各写一份（都只认 `_MEIPASS`），换成 Nuitka 后每一处都会静默用错路径 —— 症状是"程序能起来，但图标没了 / 随包公式列表空了 / 配置跑到别处去了"，而且**开发机上（源码运行）永远看不出来**。

### 4.3 `formulas/` 随包公式的播种与退役

「内置策略」这件事就是**仓库里那个 `formulas/` 目录**（当前 8 个文件：`地量后放量变盘.txt`、`均线多头排列.tvf`、`尾盘匹配策略.txt`、`开盘抓涨停策略（超短）.txt`、`放量上攻.txt`、`短期反转.txt`、`首板缩量整理.txt`、`二板炸板（反指）.txt`）。`formulas.formula_dir()` 每次被调用时（界面打开策略列表、保存/删除公式都会走它）执行 `formulas._sync_bundled_formulas()` 做两件事，**共用同一份状态文件** `.luweik-seeded.json`（放在公式目录里，点开头所以不会被当成公式）：

1. **退役**（`RETIRED_BUNDLED_FORMULAS`）：判据是**哈希逐字节一致**，不是"文件名一样就删" —— 用户可能把这条公式改成了自己的东西，改过的就留着。删完**必须记进名单**，否则下一次启动会被原样补回来（"删了又长回来"）。
2. **播种**（`_seed_samples`）：缺哪条补哪条。同名文件已存在 → 不碰；名单里有、目录里没了 → **也不补**（多半是用户故意删的）。

**源码运行 / Nuitka 版什么都不做**：那时"用户公式目录"与"随包目录"本来就是同一个目录，不需要复制一份给他。只有 PyInstaller 版（随包那份在只读的 `_MEIPASS` 里）才真的走播种。

## 5. 授权

只有 `licensing.py` 回答授权问题，界面与 CLI 都只读它。

### 5.1 机器码

- 取值：Windows 上一条 PowerShell 问三项（CPU `ProcessorId` / 主板序列号 / 系统盘 UUID），算 SHA-256 后 Base32 取 16 位，形如 `XXXX-XXXX-XXXX-XXXX`。
- **只在打开授权窗口/点【注册】时才读**（`license_status(verify_machine=True)`）。日常判定只读授权文件与试用记账（几毫秒）。理由：读机器码要起一个 PowerShell，几百毫秒到一两秒，而启动、点【策略编辑】、刷新设置都会走到授权判定 —— 每次都读就是"点一下卡一下"。
- **只缓存在内存里，绝不落盘**。落盘的话，`license.json` 被拷到别的机器上时 `machine_code()` 会读回旧机器的码、与文件里的 `machine` 字段一致 → "拷文件就白用"成立。
- 取不到硬件时用兜底指纹（用户名 + 机器名 + 装机目录）补足三项 —— 否则所有这类机器的机器码都一样，等于没绑定机器。
- `license_status()` 在**没校验机器码时**把返回值的 `machine` 填成**空串**（而不是"机器码是空的"）—— 调用方一眼能看出"这一份状态没读过机器码"。

### 5.2 试用 7 天与两处记账

- 首次运行日期写**两处**：`%APPDATA%\LuweikDecision\license.json` 与数据库 `app_state` 表；
- 读的时候取**较早**的那个 —— 删掉其中一个不会重置试用期（删两个也没用：数据库里有更早的记录就会赢）；
- **时钟回拨防护**：记录"见过的最大日期"（同样取两份里较晚的那个），一旦系统时间比它早就按**已到期**处理并把原因说清楚。宁可误伤一个改了时间的人，也不能让试用期无限续。
- 授权判定用的"今天"是**北京日期**（`licensing._today()` → `clock.now_cn()`），与项目其它地方同一个"今天"。

### 5.3 注册码算法与其强度局限

```
注册码 = Base32( HMAC-SHA256(内置密钥, 归一化后的机器码)[:10字节] )  → 16 位，XXXX-XXXX-XXXX-XXXX
```

- 归一化很宽容：去空白与连字符、转大写（用户会从微信复制、会手打）。
- 比对用 `hmac.compare_digest`。80 位意味着"随便猜一个蒙对"的概率是 2^-80。
- 密钥在 `_KEY_PARTS` 里分三片异或还原，还原后的字节故意不是合法 UTF-8。
- **局限（如实写）**：密钥在**客户端**里，做了拆分混淆但只是挡"反编译看到一串 key 就照抄"的顺手破解 —— 逆向出来的人可以自己算注册码。这是一个**分发产品**，要挡的是"顺手把 exe 拷给同事用"，不是"有人专门逆向你"。用 HMAC 短码而不是 Ed25519 公钥验签，换的是"注册码 16 位、抄得动、口述得清"；代价就是上面这条。
- **升级路径**：`verify()` 只依赖 `expected_code()` 一个函数，将来换签名方案改这一个函数 + 放宽码长即可，界面与试用逻辑都不用动。
- 签发工具是 `build/keygen.py`（作者自用，**不进打包产物**），它直接调 `licensing.expected_code()` —— 两处各写一份密钥迟早漂移，而且这种漂移只有在用户注册失败时才被发现。
- `register()` 在写盘失败时**仍返回成功**，并明说"本次有效、重启后请再注册一次"：盘只读的机器上"点了注册却什么都没发生"是最难解释的现象。

## 7. 为什么这样设计（仍然成立的取舍）

- **为什么来源列只写策略名**：用户要这一列回答"凭什么选它"。"组合档"（`X+自选`）会让人以为"自选"也是来源之一，而"它在不在自选里"在自选表与监控开关那一列已经说清楚了。判断逻辑仍看 `公式·` 前缀，因为那是数据；显示是另一回事。
- **为什么盘中要拼 K 线**：日更要到收盘后才会有"今天"这根。不拼的话，用户在盘中点【运行】看到的是昨天的盘 —— 而他那条公式写的 `C`、`量比()` 想表达的显然是"现在"。拼出来之后公式一个字不用改，这是"内置规则"与"再教用户写一条盘中策略"的区别。
- **为什么注册码用短码而不是长签名**：用户要抄写这个码（微信发来发去、手打）。Ed25519 的码是 100+ 字符，微信传、手抄都不现实。要挡的是"顺手拷给别人用"，不是专业逆向 —— 见 5.3 的局限。
- **为什么桌宠不挂父窗口**：它是无边框 + 置顶 + `Qt.Tool` 的**顶层窗口**，不挂在主窗口的可见性上 —— 主窗口最小化/隐藏时它照样在桌面上蹲着。构造时收一个 parent **只是为了"主窗口销毁时跟着销毁"**，不是为了显示。
- **为什么日志要统一时钟**：日更、盘中提醒、数据新鲜度、提醒时间戳全都是北京时间口径；日志若按机器本地时间写，UTC 机器上"17:10 写的一行"与库里那天对不上，排查时第一步就会走偏。所以日期/时间取值一律走 `clock`，`storage._now()` 也走它。
- **为什么 `formulas.prepare_inputs()` 要打包成一个 `Prepared` 对象**：试算（【运行】）与建池（【开始筛选】）必须**完全同口径**。各写一份迟早出现"点【运行】选出 3 只、点【开始筛选】选出 1 只"，而这种差异用户没有任何办法解释。
- **为什么快照只取一趟**：同一轮里取两次会看到两个时刻的盘面，于是 K 线里的涨幅与 `现涨幅` 对不上 —— 两边都"对"，但看着就是不对。
- **为什么建池是"upsert + 按 batch 清理"而不是 DELETE 再 INSERT**：后者一旦中间失败，当天池子就空了。用户重跑下载/重跑筛选时绝不能把已有数据删掉，这是全局写完入口 `storage.upsert()` 存在的理由。
- **为什么失败要隔离**：公式是**用户自己写的**，写错是常态而不是异常。一条写坏的公式让整轮匹配失败，等于"用户越敢试错，程序越不能用"。所以解析期逐文件报错、运行期逐票逐公式兜住。
- **为什么 `notes` 与 `warnings` 要分开**：建池的"成功/失败"判据是"`errors` 是否为空"。一句口径告知（"盘中取不到快照，已退回日 K"）塞进 `errors`，会让一次正常完成、票也选出来了的筛选被判成失败并安排补跑。
- **为什么提示音要 `SND_ASYNC`、语音要有独立后台线程**：提醒是在界面线程里触发的（用户刚点了按钮 / 定时器到点），同步播放/朗读就是"点一下卡一下"。
- **为什么托盘通知走队列**：Qt 控件只能在其所属线程里操作，后台调度线程直接碰控件会随机崩溃。所以后台只往队列里放，界面 `QTimer` 定期 `drain()`。

## 9. 界面层：皮肤、自绘标题栏、配色候选（2026-10-10）

主人这一轮的原话是"**框体和颜色都很别扭……标题栏还用 Windows 自带的一点都不搭**"，
所以这一版动了两件事：窗口最上面那一条改成自己画的，以及整页的层次（圆角、渐变、间距、页签）。
下面这些是**改界面时必须知道**的判据，不是可选风格。

### 9.1 自绘标题栏：不动系统样式，自己回答命中测试

`ui/titlebar.py` 走的是 Windows 上的 "custom chrome" 路线，**不是** `Qt.FramelessWindowHint`：

| 消息 | 我们怎么回答 | 结果 |
|---|---|---|
| `WM_NCCALCSIZE` | 整个窗口矩形都算客户区（返回 0；最大化时内缩一圈边框） | 原生标题栏不再绘制，而 `WS_CAPTION/WS_THICKFRAME` 还在 |
| `WM_NCHITTEST` | 四角/四边 → `HTLEFT` 等；标题栏空白 → `HTCAPTION`；三个按钮 → `HTCLIENT` | 缩放/拖动/双击最大化/贴边吸附/右键系统菜单全由**系统**做；按钮点击归 Qt |
| 其它 | 不表态，交给 Qt | 与普通客户区一样 |

**为什么不用 `FramelessWindowHint`**：一设它，拖动、双击最大化、边缘缩放、贴边吸附、
Aero 抖动、任务栏行为会一起消失 —— 用户会立刻觉得"这软件不对劲"，
比标题栏难看严重得多。`tests/test_titlebar.py::test_main_window_does_not_drop_native_window_behaviour`
钉着这一条。

**三层兜底**（这台机器上验不了 Windows 的真实行为，所以每一步都能退）：
1. 任何一步抛异常 → `ChromeController.disabled = True`，退回系统标题栏继续跑，只记日志；
2. `WM_NCCALCSIZE` 到底有没有生效记在 `nc_applied` 里，启动后写进日志（`窗口外观：…`）；
3. Qt 以为窗口上面还有 31 像素的标题栏，`resize()` 会把外框撑大一圈 ——
   `ChromeController.sync_geometry()` 量一次客户区，对不上就用 `SetWindowPos` 校正。

**开关**：设置页「系统设置 → 其他 → 窗口外观」（`config.window_frame`，
`custom` 自绘 / `system` 系统标题栏），**改完重启生效**；环境变量 `WINDOW_FRAME=system`
可以在不改文件的情况下绕开。配置非法值一律回 `custom`。

### 9.2 皮肤与配色：色值只有一处

- 所有颜色都在 `theme.PALETTES` 里的那几套色板（**同批键名**；`SILVER_COLORS` 是手写的浅色那套，
  其余六套由 `_dark_palette` / `_light_palette` 生成），QSS 模板是所有配色共用的一张；
  `tests/test_theme.py` 会拒绝模板里出现色板之外的十六进制色。
- 自己画的地方（热力图、桌宠气泡、标题栏按钮、提醒浮窗）不许写死色值：
  问 `theme.chrome_colors()` / `theme.is_dark()` / `theme.value_color()`。
- **强调色不许是红或绿**：A 股红涨绿跌，强调色撞上语义色就分不清"这是涨"还是"这是按钮"。
  所以强调色只用蓝、紫、金、玫。
- **八套皮肤都在设置页里能选**（`config.UI_THEMES` = `theme.PALETTES` + `system`，
  用例钉着这两个集合必须一一对应）。主人 2026-10-10 的原话："默认选午夜靛紫 ——
  其它几套也可以放在程序包里供用户选择"，所以这六套彩色皮肤都是**正式皮肤**，
  不是"临时候选"；旧配置里的 `ui_theme = "tech"`（2026-10-08~10-10 那套青色）
  由 `theme.LEGACY_THEME_ALIASES` 翻译成现在的默认，不会退成"默认值"。
- 色板是**生成的**（`theme._dark_palette` / `_light_palette`：给"窗口底/卡片底/
  背景条底 + 一个强调色"，层次关系按公式推）——手工抄 50 个色值必然漏键，
  而"卡片比底色亮一档"这类关系本来就是相对的。主按钮的字色与四态也由
  `_primary_gradient` 算（亮底深字 / 深底亮字两条路，取最差状态更好的那条）。
  生成出来的色板由几条用例兜底：`test_every_palette_defines_every_key`（键名齐全）、
  `test_every_palette_text_is_readable`（正文 AA 4.5:1）、
  `test_candidate_primary_buttons_are_readable_in_all_states`（主按钮常态 4.5:1、
  按压态 3.4:1）、`test_dark_and_light_palette_lists_agree_with_the_colors`。

### 9.3 个股评分（2026-10-11）

主人原话："做进界面，自选标的 / 持仓监控加一列评分，加入自动给出。"
构架在工作区 `新功能构架-评分与热力图.md` 第 2 节（那份文档同时排了四期，
三期热力图早在 1.4.0 就做完了，一/二期就是这次）。

**四层结构（哪一层坏了查哪一层）**：

| 层 | 位置 | 干什么 |
|---|---|---|
| 判据 | `scoring.ITEMS` | 每项**一对布尔公式**（看多 / 看空），跑在既有公式引擎上 |
| 指标 | `strategy/formula.py` | 引擎里缺的三个（`ADX`/`PDI`/`MDI`/`ATR`/`MFI`）2026-10-11 补进去了 |
| 模型 | `scoring.score_series()` | 维度加权 → 归一到 0~100 + 档位 + 逐项理由 + 缺项清单 |
| 界面 | `ui/scores.py` + 两张表的「评分」列 | 后台算、算完通知、算过的记住；格子显示整数，tooltip 是完整明细 |

**四条硬规矩**（改任何一条都会让这个分不能信）：
1. **可解释**：每项都有一句人话理由（"站上 20 日线（收盘 12.34）：看多"），
   tooltip 里按维度列全；
2. **缺项不算 0**：`_availability()` 先判"数据够不够"（`formula.min_history` +
   扩展字段有没有值），不够的项进 `missing`，总分**只按可用项的权重重归一** ——
   ⚠️ 不能只看公式求值结果：比较运算遇到 NaN 返回的是 **False**，
   那样"日线只有 5 根"会被当成"中性"（实测踩过）；
3. **口径与选股一致**：序列与扩展字段都走 `formulas.prepare_inputs()`/`load_series()`，
   所以评分结果里带着与筛选同一句口径说明；
4. **带模型版本**：`scoring.MODEL_VERSION`，改了项/权重就 +0.01；
   缓存键 = 代码 + 行情日 + 模型版本（`scoring.cache_key`）。

**界面上怎么给的**：
- 「自选标的」「持仓监控」各加一列 **`评分`**（窄列，只放整数；位置在「监控开关」之前，
  所以两张表原有列的下标一个都没动）；
- **加入自动给出**：加自选（`on_watch_add`）与记持仓（`on_add_position`）之后立刻
  `_request_scores()`，不用等 5 秒拍子；
- 还没算出来显示 `—`（**不是 0** —— 0 分是"很弱"这个真实结论，与"还没算"是两回事）；
- 格子的 tooltip = 评分明细 + 那一行原有的行信息（备注/资金流），
  "悬浮任何一格都能看到备注"这条老约定不能因为新列被打破；
- 评分那两格**都进了内容指纹**：算完必须重画表格，否则用户看到的是永远挂着的 `—`。

**怎么加一项/改权重**：只动 `scoring.ITEMS`（名字 / 维度 / 权重 / 一对公式）——
界面、缓存、tooltip 全都自动跟上；改完把 `MODEL_VERSION` +0.01。

### 9.4 桌宠的动态形象（2026-10-10）

主人问「宠物形象可以换成动态吗」，选的是"换一套多帧形象（他出素材）"，所以程序这边的
活儿是**把素材接口做宽、把规格写清楚**：

- 素材优先级只有一处判据（`ui/desktop_pet.py` 的 `_load_assets`）：
  **序列帧 `assets/pet/*.png` > GIF `assets/pet.gif` > 单张图 `assets/pet.png`**。
  序列帧优先是因为 GIF 的透明只有 1 bit（角色边缘会有一圈白边）。
- **五种状态**（`assets.pet_state_frames(state)`，文件前缀就是状态名）：
  `idle` 待机、`walk` 走路循环、`act` 有提醒时播一遍、`think` 干活中、`sad` 亏了/止损
  （`pet-*` 是旧前缀，等价 `idle`）。桌宠会**在落点附近左右溜达**（±`ROAM_RANGE`，
  只在水平方向），拖动结束时落点即新锚点；情绪由主窗口驱动：
  `_set_progress_visible()` 切 `think`/`idle`，提醒类型（止损/跌破）切 `sad`。
- 帧间隔 `FRAME_MS = 180`（主人要求"帧数不要过快"）、走路 `WALK_STEP = 3` 像素/帧。
- 无论走哪条路，`self._pixmap` 都是第一帧 —— 尺寸、透明底判据、拖动、气泡这些逻辑
  **一行都没改**（静态素材走的还是老路，既有的桌宠用例也照旧）。
- `assets/pet/act-*.png` 是"来消息"的动作帧：有就播一遍它，没有才退回"蹦两下"
  （两者不同时上：动作帧里通常已经画了位移）。
- 动画定时器**只在可见时跑**（`showEvent`/`hideEvent` 里开关）：桌宠是常驻桌面的，
  藏起来还每 120ms 重画一张大图纯属白烧 CPU。
- 帧率是 `FRAME_MS = 180`（≈5.5 帧/秒）—— 主人明确要求"帧数不要过快"。
- 素材规格（**给主人出素材用**）写在 `docs/桌宠素材.md`；
  `build/make_pet_preview.py` 能把素材渲染成一张 GIF 预览（`--demo` 会用静态图
  程序化造 8 帧呼吸帧），**装软件之前就能看效果**。

### 9.5 滚轮防误触（`ui/wheel_guard.py`，2026-10-10）

主人原话：「把设置页的鼠标滚轮功能给限制掉，会无意触发。」
设置页五组三十多个控件是**纵向排一列**的，里面一堆下拉框与数字框；
Qt 的默认行为是滚轮停上去就改值（**与焦点无关**），于是"想往下翻页"变成了
"把止损 % 改成了别的数"，而且他看不出来。

口径（判据只有一处：**滚轮永远不改这些值**）：
- 拦 `QComboBox` / `QAbstractSpinBox`（数字框、时间框）/ `QSlider` / `QDial` / `QTabBar`
  上的滚轮；**故意不看焦点** —— "刚点过它、又滚过它"是设置页里一定会发生的场景，
  焦点判据挡不住（第一版就是那么写的，实测复现了）；
- 改值仍然有明确的路：点开下拉框挑、在数字框里输入或用上下箭头（键盘 ↑/↓ 照常）；
  下拉框展开后的列表是独立弹层，**照常能滚**；
- 拦下的滚动**转给最近的滚动区**，所以页面照常往下翻（不是"滚了没反应"）；
- `QScrollBar` **不在**拦截名单里（它也是 `QAbstractSlider`，写成父类会把滚动条圈进来，
  滚动条就滚不动了）；表格/列表/滚动区一律不碰。

实现是一个**应用级事件过滤器**（`install()`，幂等，主窗口构造时装一次）——
不给每个控件套子类是因为下拉框/数字框散在五个页面十几处，漏一个就还是一个洞。

### 9.6 改界面时的两条纪律

1. **界面代码不写色值、不写像素级样式**：颜色进 `theme.py`，尺寸进 `app.py` 顶部那几个常量
   （`WINDOW_MARGINS` / `PAGE_SPACING` / `FONT_*_DELTA`）。
2. **改完必须出图看**：`python build/make_screenshots.py`（产品图）与
   `python build/make_palette_preview.py`（配色对比图）都是离屏渲染，
   不看图就改排版，等于闭着眼睛排版 —— 测试证明不了"排得好看、底部没被切"。
