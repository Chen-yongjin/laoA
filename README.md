# 老牛选股助手（Windows 单机版）

一个**独立运行在 Windows 上**的 A 股选股 + 盯盘 + 提醒程序。
和 NAS 上那套（`选股/`）是**两个项目**：那套是服务器常驻版（Docker + 飞书），
这套是桌面版（双击运行、自带数据、通知是「图标闪烁 + 消息列表」）。

## 为什么要有这个版本

| 需求 | NAS 版 | 本版本 |
|---|---|---|
| 数据自己下 | 需要会 Docker | ✅ 首次运行自动下载并导入 6 个月历史（进度条，可改 10 年） |
| 通知 | 只有飞书 | ✅ **图标闪烁 + 「消息」列表**（QQ 那种：点托盘图标看列表；飞书 / 托盘气泡可另行勾选） |
| 界面 | 浏览器 | ✅ 桌面窗口五个页签（大盘概览 / 自选股池 / 持仓监控 / 策略选股 / 系统设置）+ 托盘 |
| 未来接 QMT 自动交易 | 要另配 Windows 机 | ✅ 就在本机（QMT 是 Windows-only） |

## 数据来源：**主源是同花顺（要 Key）**，免 Key 的公开源是兜底

> ⚠️ **口径在 2026-09-18 翻回来过一次，以代码为准**（用户原话："那还是不要换源吧 真晕
> 同花顺不会轻易限流"）：出厂默认 `data_sources = ["hithink", "public"]`（`config.py`），
> **同花顺排第一、是主源**，免 Key 的公开源降为**兜底**（没配 Key / Key 失效时顶上）。
> **为什么翻回来 —— 公开接口实测会被限流**（`data/public_quotes.py` 的模块头写着）：
> **腾讯 `fqkline` 抓 700 只左右就开始连续失败、新浪的列表接口直接回 HTTP 456**；
> 而同花顺是正经 API，不会这么脆。之前那版"公开源当主源"就是被这两条打回来的。
> 界面上的标记也跟着顺序变：「系统设置 → 数据来源」里**只有排第一的显示 `[主来源]`**，
> 其余行按**自己的 Key 状态**显示 `[免 Key]` / `[已配 Key]` / `[未配 Key]` ——
> **公开源显示的是 `[免 Key]`，不是 `[兜底]`**（"谁是兜底"由顺序与它那行的说明表达；
> `ui/app.py` 的 `_rebuild_source_rows()` **按配置顺序判定**，不写死谁是谁）。
> 也就是说：**填一个自己的 Key 才能拿到完整历史**；没 Key 也能用，但只有"每天攒一根"。

- **主源 = 同花顺金融数据服务**（要 Key，自己在 `https://fuyao.aicubes.cn` 申请）：
  10 年全市场日线 dump、涨停池/跌停池/炸板池（含明细）、复权事件表、
  行业归属、情绪/板块指数、指数日线、竞价扫描。
  **那一行上有 Key 输入框（密码框）+【测试连接】+ 一行可点开的申请地址**
  （2026-09-18 用户澄清后加回来的 —— 原话："设置里让你不要配 KEY，但是你也要给个 key 的输入口啊"：
  "不要配 KEY"指的是**程序里不许预置开发者自己的 Key**，**不是不给用户填**）。
  **程序侧一个字都没写死**：输入框的初值只来自用户自己的 `config.toml` 的 `hithink_api_key`
  （出厂是**空串**）或环境变量 `HITHINK_FINANCE_API_KEY`；填完点【保存设置】就写回
  `config.toml`。
  没配 Key 时这一路**直接跳过**（不会偷偷去请求）。
- **公开源那一行仍然没有输入框**（它是免 Key 的）：那行字是
  `免 Key：这个来源不用申请、不用填（填了也没有用）` —— 不给假输入框是有意的：
  画一个填不了东西的框，用户会去找一个根本不存在的 Key。
- **兜底 = 免 Key 的公开行情源**（`data_sources` 里的第二个 `public`；**只在没配 Key /
  Key 失效时顶上**）：
  **腾讯 `qt.gtimg.cn` 批量接口为主、新浪 `hq.sinajs.cn` 兜底**；两边单位不同（腾讯是"手/万元"、
  新浪是"股/元"）→ 程序内部**统一成"股/元"**，所以换来源不换口径。实测（2026-09-17）：
  腾讯批量**一次 100 只**、**全市场 5562 只约 0.7 分钟**；快照字段含
  **现价 / 涨跌幅 / 成交量额 / 换手率 / 流通市值 / 总市值 / 市盈率 / 市净率 / 量比 /
  均价 / 涨跌停价 / 五档**。免 Key 这一路**分布在三个模块**里（各管一段，别互相找错文件）：

  | 模块 | 管什么 |
  |---|---|
  | `src/laoa_trader/data/public_quotes.py` | 腾讯/新浪的**批量快照**（两张表的 `现价/涨幅/市值/换手`），单位归一 |
  | `src/laoa_trader/data/public_market.py` | **全市场扫描**（新浪代码表 + 腾讯 100 只/批）+ `PublicMarketClient` —— 大盘概览与日更**共用这一趟** |
  | `src/laoa_trader/data/public_sync.py` | **免 Key 日更**（一趟扫描 → 当日日线 / 涨停池 / 代码表 / 交易日历，含除权检测） |
- ⚠️ **字段级补齐（2026-09-18 新增；用户实报"新加入的市值和换手，都没有数据"）**：
  **价格与"市值/换手"这两项，可能来自两个不同的来源** ——
  同花顺的 `/a-share/prices/snapshot` **根本不返回换手率与市值**（官方文档
  `vendor/Financial-API/docs/api/endpoints-prices.md` 里 `PriceSnapshotItem` 一共十项：
  `thscode / ticker / last_price / price_change / price_change_ratio_pct / open_price /
  high_price / low_price / prev_price / volume / turnover`，没有这两项；
  全项目能拿到流通市值的只有**竞价**端点的 `float_market_cap`，那要求正处竞价时段）。
  所以**配了 Key 之后这两列反而空**，而没配 Key（走免 Key 公开源）时是有数的 ——
  这种"越想用好反而更少"的坑最容易被当成数据源坏了。
  现在的做法（`data/sources.py` 的 `supplement_map()`）：**价格仍由主源给**（同花顺那一路最稳），
  缺的这两项按 `data_sources` 的顺序**往后**找一个能给出来的来源补上（默认就是免 Key 公开源，
  腾讯一次 100 只，便宜）；规矩三条 ——
  **只给已经有报价的票补**（不凭空造记录）、**不重复打主源**（它缺就是缺）、
  **补到的字段带 `field_source`**（界面据此写出处），**补不到就还是 `—`（绝不抛）**。
  **`data_sources` 里只有同花顺时**（用户明确不要别的源）：不偷偷用没启用的来源，
  这两列**如实显示 `—`**，tooltip 里写明"来源不提供这一项"。
- **想纯免 Key**：把 `data_sources` 改成 `["public"]`，或者 `["public", "hithink"]`
  （**列表顺序 = 取数优先级**，前一个不可用就落到下一个；界面上那两行的标记
  `主来源` 那个标记会自动跟着挪到第一个）。**但注意**：换成纯免 Key 也**拿不到完整历史、
  也选不了股** —— 那两样要同花顺那条路（见下面那张边界表）。
- **另一路公开源**：`eastmoney`（东方财富，免 Key）在注册表里，用【添加来源】加进来就能用
  （它目前只有"实时快照"接进了两张表；历史日K 与代码表已实现但**还没接进下载流程**）。
- ⚠️ **"免 Key 能用"的边界（如实写）**：

  | 能力 | 没 Key | 依据（代码位置） |
  |---|---|---|
  | 「大盘概览」的**成交与情绪 7 个小条目**、**宽基 7 只** | ✅ 能用 | 没 Key / Key 无效时 `market.py` 换成 `public_market.PublicMarketClient`（**同样三个方法**，取数逻辑不分叉），结果里 `price_source == "public"` |
  | 两张表（自选股池 / 持仓监控）的 `现价 / 涨幅 / 市值 / 换手`（含**换手率**与**流通市值**） | ✅ 能用 | `data/sources.py` 的 `_SNAPSHOT_FETCHERS["public"]`；**有 Key 时这两项也由它补**（见下面"字段级补齐"） |
  | 热门板块两张表的 `涨幅` 与 `主力净额` | ✅ 能用 | 腾讯板块排行（`data/sectors.py`，本来就免 Key） |
  | **日更**：当日日线 / 涨停池 / 代码表 / 交易日历 | ✅ 能用 | `sync.daily_update()` 拿不到同花顺凭据时改派 `public_sync.daily_update_public()` |
  | **历史数据**（多年历史） | ❌ **拿不到** —— 只能靠免 Key 日更**每天攒一根**（当天那根会写进库） | 见下一节：免 Key 那条路**没有** dump、没有历史包、也没有逐只补缺口；公开源一天只给得出当天那一根 |
  | 同花顺 **10 年日K dump**（`daily-k` / `daily-k-10d`）与**复权事件表** | ❌ 要 Key | `sync.sync_daily()` → `make_client()`；复权事件的唯一写入口也在那条路上 |
  | **涨停池明细**：封单额 / 封板时间 / 涨停原因 / `currency_value` | ❌ 要 Key | 免 Key 涨停池这些列一律 **NULL**（不是 0），`public_sync.py` 的 `limit_pool_from_snapshot()` |
  | **情绪指数 / 板块指数**（`883xxx.TI` / `881xxx.TI`） | ❌ 要 Key | 公开源没有对应标的 → 归入 `unsupported`（**不是** `failed`），界面这两组显示 `—` 并有一句说明 |
  | **行业归属**（`stock_basic.industry`） | ❌ 要 Key | `sync.sync_industry()` 走同花顺目录 + 成分股（**没有免 Key 分支**）；免 Key 日更只写代码与名称（`public_sync.sync_names_public()` 把 industry 写成 NULL） |
  | **竞价扫描** | ❌ 要 Key | `intraday.py` 构造的是同花顺客户端（`auction_scan`） |

- 🔴 **"没 Key 就不能选股"是设计如此，不是待修**（2026-09-18 拍板；别把它当 bug，
  也别以为"历史攒够几十个交易日就行了" —— 代码里那句注释就是专门防这个误会的）：
  自检 `preflight.check()` 要求 **`adjust_event` 表非空**（`preflight.py`）与
  **行业覆盖率 ≥90%**（`MIN_INDUSTRY_COVERAGE = 0.9`），而**这两样只有同花顺那条路会写**

  `sync_industry()` 也没有免 Key 分支）。缺了它们就拒绝选股 ——
  理由写在代码注释里：**"就是不让程序拿算错的复权价去选票"**。
  点【开始选股】时界面会**明确拒绝**并把页面切到「系统设置」，提示里点明
  「复权事件」与「行业归属」这两项（本机实测复现，界面原文见 `快速验收.md` 第 ⑨ 步）。
  也就是说：**概览、两张表、日更（当天一根）都是真的能用；选股要用自己的 Key。**

    （它上面那条注释也还写着"程序默认走免 Key 的公开行情接口"——**这是待收口的代码文案**）。
  两处都点明了"公开来源的准实时快照、非交易所授权行情"，**"这数据能不能当真"的判断不受影响**；
  但顺序不一致这件事得知道，别按页脚的顺序去找"关于软件"里的同一句话。

  `data_sources` 里没有第二个来源时它们就是 `—`。

## 免 Key 时历史数据从哪来（**只有"一天天攒"这一条路**）

没有历史日线，选股一条也跑不出来。而**历史只有同花顺那条路给得出来**（几百 MB 的
`daily-k` dump，要 Key），免 Key 的公开源只能**逐只**取（一次一只票、几千次请求）。
所以现在的事实是：

- **想马上有历史 → 填一个同花顺 Key，点【下载数据】**（默认导入 6 个月，改 `history_years` 可要 10 年）；
- **不填 Key → 历史靠免 Key 日更一根一根攒**：每天（或每次点【刷新数据】）
  `public_sync.daily_update_public()` 把**当天那一根**日线写进库
  （外加涨停池 / 代码表 / 交易日历）。
  ⚠️ **但"攒够了就能选股"不成立**（2026-09-18 拍板）：自检要求"复权事件 + 行业归属"，
  这两样只有同花顺那条路会写 —— **没 Key 时不提供选股**（见上面那条 🔴）。
  所以这条路径的价值是"**没 Key 也能看行情、看概览、把当天的数据留档**"，
  不是"攒出可选的库"。
- **"每天写进库"这件事本身有用**（不只是留档）：库里**已经有当天的行情、涨停池、代码表与
  交易日历**，所以哪天用户配上了 Key、点【下载数据】把多年历史补进来时，
  日更是**接着已有的日子往上写**（`stock_daily_raw` 按 `(symbol, date)` 幂等 upsert），
  不会跟之前那几天的数据打架 —— 也就是"先攒着，后补历史"这条顺序是成立的。
  **但注意顺序不能反过来指望**：攒着的这几天**不能**让选股跑起来（见上面那条 🔴）。
- 公开快照**只给得出当天那一根**：中间缺的天（用户不是每天都开机）快照补不回来，
  日更会**如实统计**这些缺口（`gap`）并在日志里写一句，**绝不编数据**。
- **没有"随程序带来的历史包"**：`data/history_pack.py`（`build_pack` / `install_pack` / `backfill`）
  曾经存在过，但**已从这份代码里删除**，`resources/pack/` 也从来没有过，
  `build/laoa_trader.spec` 的 `datas` 里也没有它。所以点【下载数据】走的是"配 Key → 同花顺 dump"，
  不再有"装包 + 补缺口"那条路（`ui/app.py` 里也搜不到 `history_pack` 了）。

**免 Key 日更那一路的复权是怎么做的**（这一条**还在**，是 `public_sync` 里的实现）：
用**交易所自己给的昨收**。腾讯快照的 `[4] 昨收`不是"昨天的收盘价"，而是交易所
在除权除息日**调整过**的前收盘价（当日涨跌停价就是按它算的），于是：

    如果 快照.昨收 == 库里最后一根日线的收盘价  → 今天没除权，因子不变
    否则                                     → 今天除权了，
                                              k = 库里前收 / 快照昨收
                                              今天的因子 = 上一根的因子 × k

`后复权 = 不复权 × 因子`，所以这一步就让后复权序列**连续**了：分红除权那天原始价会跳空下跌，
而因子按同一个比例放大，两者相乘回到连续。这条路**不需要任何事件明细**，也不用多打一次接口
（`public_sync.detect_ex_right()` / `factor_step()`；实测 2026-09-17：5564 只里 5552 只昨收与库里一致，
不一致的 12 只比值都在 1.0000~1.0300 之间，正是分红/送转的量级）。

⚠️ **但这只解决"当天那一根"**：库里更早的历史若是从同花顺 dump 来的，那一段的因子来自
同花顺的复权事件表（5.7 万条，`adjust_event`）；免 Key 那条路**不写事件表**，所以
两块数据的因子体系**不是同一套来源**（详见上面"免 Key 边界"里那条 🔴 ——
自检要求 `adjust_event` 非空，正是因为这个）。

**免 Key 日更里"涨跌幅规则"是给历史补齐用的**（`public_sync` 的模块 docstring 有一整张实测表）：
免 Key 没有涨停池接口，所以涨停/连板要从**日线自己判**（`涨停价 = round(昨收 × (1+幅度))`），
幅度按板块定，这一条是在全市场 5564 只上反推验证过的：

| 板块（代码段） | 幅度 | 取整 | 实测依据 |
|---|---|---|---|
| 主板 `60/00` | 10% | **四舍五入** | 3050 只吻合，其中 1562 只能区分取整方式且全部是四舍五入 |
| 创业板/科创板 `30/68` | 20% | **四舍五入** | 1965 只吻合，744 只能区分且全部是四舍五入 |
| 北交所 `92/8/4` | 30% | **截断** | 181 只能区分取整方式，**全部**是截断（四舍五入会差 1 分） |
| 风险警示 `ST` | 同板块 | 同上 | 144+57+1 只 ST 的涨停价与同板块一致（**不是** 5%） |
| 未股改 S 股 | 5% | 四舍五入 | 实测 600182 佳通 是唯一的 5% 例外 |

当天那一根优先用**快照里腾讯给的涨停价**（权威值，`limit_pool_from_snapshot()` 就是这么做的），
规则只用在"库里没有当日涨停价"的历史回补那一段。

## 数据没下好时**绝不选股**（两道闸门）

分发前踩过的坑：程序启动 → 自检 `needs_full` → 用户看到标题区提示后点【下载数据】开始下载 ✓，
**同时**调度线程因为"今天已过主跑时间且今天没跑过"触发了日常选股 ✗ ——
在**只写了一半的库**上跑策略 → 选出 1 只 → 建池、还可能推了通知。
下载过程也没有进度显示，180 MB / 十几分钟看起来像卡死。

现在有两道闸门（`scheduler.data_gate`，界面 / 命令行 / 调度线程**同一口径**）：

| 情况 | 行为 |
|---|---|
| **正在下载**（`state.is_downloading()`） | 跳过本次自动选股；**不写"今天已完成"标记** |
| 本地数据 `needs_full` | 跳过，日志写明中文原因；**同样不写标记** |
| `needs_incremental` | 放行，但**先跑增量再选股**（`run_daily(with_data=True)` 的既有顺序） |
| `ready` | 正常跑 |

- **不写成功标记**的含义：拦截 ≠ 今天放弃。数据下好之后**当天仍然会补跑一次**
  （用户预期："下完就该自动选一次"）；同一个原因 5 分钟内只记一条日志，不刷屏。
- **标题区的运行状态直接说原因**（不用翻日志）：`scheduler.status()` 里有
  `skipped_reason`（为什么没自动跑，中文）、`preflight_status`（最近一次自检结论）、
  `daily_skipped_today`（今天因数据没就绪被跳过）、`downloading`（是否正在下载）。
- 为什么被跳过时**不**记成"今天主跑失败"：那个标记会让调度一直等到补跑点（如 19:15）才重试；
  而这里要的是"数据一就绪就补跑"，所以单独记 `daily_skipped_today`，重试不等到补跑点。
- **手动入口一样严格**：正在下载或数据没就绪时点【开始选股】（在「策略选股」页），
  界面**明确拒绝**并指路"请先点【下载数据】"（运行状态显示原因）；
  命令行 `--once` 返回**非零退出码**并打印可执行的下一步。
- **下载完成后**：标题区那行提示消失 → 自检缓存作废 → **自动跑一次选股并建池**（即"增量 → 选股 → 建池 → 推送"，原有行为保留）。

**下载进度（不再"像卡死"）**：

- 界面：主窗口的进度条持续走动，显示 `下载 daily-k｜90.0/180.7 MB 50%`；
  运行状态显示"正在下载历史数据 50%（90/181 MB）"，下载期间一直挂着 `⏬ 正在下载历史数据…`；
- 状态行还会显示"正在重签 URL 继续下载（第 2 次，从 87.0 MB 处接着下）"这类信息；
- 命令行：**按秒或按 10% 新起一行**（其余在原行覆盖刷新，不刷屏），跑完一定收尾 100%，
  重试/重签也另起一行（`↻ 正在重签 URL 继续下载（第 2 次…）`）。

## 下载中断了怎么办？（会自动续传，不用重来）

历史数据是几百 MB 的大文件，而下载链接（同花顺预签名 URL）**只允许 GET、有效期约 5 分钟** ——
网络一抖、链接一过期，老的"一次写完"实现就整轮失败，下次还得从 0 开始。现在改成：

- **断点续传**：写到 `<tag>.parquet.part`，已下载的字节数就是下次请求的 `Range` 起点，
  **从断的地方接着下**（180 MB 下到 87 MB 断了，下次从 87 MB 继续）；
- **过期自动重签**：每次重试都重新申请一次签名 URL（403/过期只是"再签一次"的问题）；
- **有界重试**：默认最多 5 次，指数退避；日志里能看到
  `第 2/5 次尝试，从 87.3 MB 处继续` 这样的记录；
- **分开的超时**：连接超时 15s（网络差就赶紧重试），读取超时 90s（流式下载留足余量），
  都能在 `config.toml` 里调（`download_connect_timeout` / `download_read_timeout` / `download_max_attempts`）；
- **完整性校验**：下完先确认是可读的 Parquet（行数 > 0），**通过了才原子替换**成正式文件；
  残缺文件永远不会被当成"已下好"。
- **同源校验（这条很关键）**：dump 是**每天重新生成**的，而续传请求服务端只按字节切、
  并不校验内容。所以第一次响应会把远端的 ETag / Last-Modified / 总大小记进
  `<tag>.parquet.part.meta`，续传时逐项比对；**一旦发现远端换了一代，就把本地半截文件
  作废、从 0 重下** —— 绝不把两天的数据拼成一个"能读、但内容是两代混合"的库。
  远端不给任何指纹时退回保守规则：**跨天的半截文件一律作废**。
  （换句话说：同一天内断了接着下是最省时间的；隔天再点会重新下，这是刻意的安全取舍。）
- 界面上有**百分比进度**（`87.3/180.7 MB`），不会让人以为卡死了。

**下载失败了怎么排查**：

1. 看日志（`<数据目录>\logs\laoa-trader.log`）里的 `第 N/5 次尝试…未成功（传输：…）`，
   它会写明卡在哪一步（取签名 / 建连 / 传输 / 完整性校验）与已下载多少；
2. **直接再点一次【下载数据】**（或再跑一次 `--cli --download`）—— 会从断点继续，
   不会从头再来；
3. 反复失败时：换个更稳的网络、把 `download_read_timeout` 调大（如 180）、
   或在一台网络好的机器上下好 `daily-k.parquet` 后拷进 `<数据目录>/dumps/` 目录。

## 每天几点自动跑？（**默认不跑**：选股随时手动）

程序**默认不做定时运行**（用户拍板：**选股随时手动**）—— 出厂状态下
**不会有一天自己跑起来**，全靠你点「策略选股」页的【开始选股】。想让它每天自动跑一次
「数据增量 → 策略 → 建池 → 通知」，就把 `auto_run` 改成 `true`
（改回 true 之后：`16:00` 主跑一次、`19:15` 补跑一次 —— 只在主跑没成功时才补）：

- `auto_run`（**默认 false**）：true 才按下面的时间跑；
- `run_at`：默认 `16:00` —— A 股 15:00 收盘，收盘后当天数据才齐；
- `run_at_fallback`：默认 `19:15` —— 主跑没成功时到这个点再试一次（必须晚于主跑）。

> ⚠️ **界面上没有这一组了**（改版整组移除：定时日更 / 定时推送按用户要求下线）。
> 这三个键**只剩配置文件这一条路**：改完存盘、**下次启动生效**（界面上没有"保存自动运行设置"
> 这种按钮，也没有显示"下次选股"的地方）。想临时改时间用命令行 `--run-at`。
> 时间格式写坏（例如 `25:99`）不会让程序跑不起来：`scheduler.parse_run_at()` 会退回默认 16:00
> （"拒绝保存"那句来自 `validate_run_times()`，现在只作用在 CLI 覆盖那条路上）。

校验规则（`scheduler.validate_run_times`，现在只有 CLI `--run-at` / `--run-at-fallback` 走它）：

| 情况 | 行为 |
|---|---|
| 不是 `HH:MM`（如 `25:99`） | **拒绝**这次覆盖并提示格式，配置不动 |
| 补跑 ≤ 主跑 | **拒绝**（否则补跑会先于主跑，逻辑矛盾） |
| 主跑早于 15:00 收盘 | 允许，但**明确提示**"当天数据可能还没出全，建议 16:00 之后" |

配置文件与命令行：

```toml
auto_run = false            # 默认不设定时运行（用户拍板：选股随时手动）；改成 true 才每天自动跑
run_at = "16:00"            # 每天主跑（收盘后）
run_at_fallback = "19:15"   # 主跑没成功时的补跑（留空 = 不补跑）
```

```bat
.venv\Scripts\python -m laoa_trader --cli --run-at 16:30        :: 临时改（不写配置，调试用）
.venv\Scripts\python -m laoa_trader --cli --run-at-fallback 20:00
.venv\Scripts\python -m laoa_trader --cli --no-auto-run         :: 临时关掉自动运行
.venv\Scripts\python -m laoa_trader --cli --doctor              :: 看当前生效的时间与"下次自动运行"
```

## 首次运行 / 数据自检（有库就不下载）

启动（GUI 或 CLI）时先跑一次**纯本地、秒级、不联网**的自检，结论是三态：

| 状态 | 判据 | 动作 |
|---|---|---|
| **ready** | 表齐全 + 跨度 ≥0.4 年（`min_history_years`）+ 最新交易日 ≥4000 只 + 有复权事件 + 行业覆盖 ≥90% + 有交易日历 + 不落后 | **一次下载请求都不发**，直接可用 |
| **needs_incremental** | 上面都满足，但落后 **1~10** 个交易日 | 只跑一次 `daily-k-10d` 增量（1 次请求） |
| **needs_full** | 缺表/空库/跨度或股票数不足/**缺复权事件**/**落后 >10 个交易日** | 重新下载并导入（默认 6 个月） |
| **needs_full（只缺轻量项）** | 行情都在，只缺**行业归属 / 交易日历 / 指数** | `needs_download = sync_light`：点【刷新数据】几秒钟补齐（**不用重下历史**）；定时任务与 `ensure_ready` 会自动补一次再复查 |

> 为什么"落后 >10 天"要判全量：`daily-k-10d` 只覆盖近 10 个交易日，落后更多天**增量补不回来**（官方文档明确写了窗口）。
> 为什么"缺复权事件"不能算就绪：后复权价由复权因子算出，事件表空了价格就是不复权的，跨除权日的收益率会凭空多一截。
> 为什么"缺行业归属/日历/指数"单独一档：它们是**目录类数据**（1~90 个请求、幂等、不动行情），
> 点一下【刷新数据】就补上了；把它们混进"重新下载 180MB 历史"里，用户会白等十几分钟
> （实报过：下完几年数据后提示"行业覆盖率 0%，要求 ≥90%"，其实只是没同步行业归属）。

> 🔴 **免 Key 时这两条判据永远过不去**（2026-09-17 改版后新出现的问题，必须知道，
> 否则会以为"数据攒了很久了，怎么还说数据没就绪"）：
> `preflight.check()` 的 `ready` 要求 **`adjust_event` 非空** + **行业覆盖 ≥90%**，
> 而免 Key 那条路（`public_sync`）**既不写 `adjust_event`、也不写行业**：
> - 事件表空 → `needs_full`，界面说 `本地无可用历史数据（缺少复权事件（分红/送股/配股），后复权价会算错，不能算就绪）`；
> - 就算补上一条事件 → `sync_light`（行业覆盖率 0%），而 `sync_light` 里的行业同步**仍然只走同花顺**（没 Key 必失败）。
> 结果就是**免 Key 时【开始选股】与 `--once` 都会被闸门拦住**（`scheduler.data_gate()`）。
> 自检这两条判据本身没错（后复权价确实依赖事件表），错的是"免 Key 路径还没把事件表接进来"——
> 这是**设计如此**（不是待办），详见上面「[免 Key 时历史数据从哪来](#免-key-时历史数据从哪来只有一天天攒这一条路)」那一节（**免 Key 没有历史包，也不写复权事件**）。

各端行为：

- **GUI 启动**：标题区先显示"正在检查本地数据…"，然后——
  - `ready` → 运行状态打出结论那句"✅ 数据就绪 · N 只 · 更新到 MM-DD"（行数在【显示详情】里）；
  - `needs_incremental` → 运行状态提示"⚠️ 本地数据落后 N 个交易日 · 点【下载数据】补齐"；
    `auto_download_on_start=true`（默认）时**后台自动**跑增量；关掉则只提示，点【刷新数据】可手动补；
  - `needs_full` → **标题区多一行提示**（例："本地还没有行情数据 · 在【系统设置】里点【下载数据】"），
    数据下好之前一直挂着 —— **没有模态向导**（原因全文在 tooltip 与【显示详情】里）。
    下载完成后自动跑一次选股并建池（增量 → 选股 → 建池 → 推送）；下载/导入过程可中断续传。
- **CLI**：`--doctor` 打印三态结论与各项指标；`--once`/`--pool`/`--serve` 进正题前先自检——
  `needs_full` 且没给 `--auto-download` 时**明确报错退出**（不会静默跑出空结果）；
  `--download` 在就绪时直接跳过（要强制重下加 `--force-download`）。

```toml
history_years = 0.5             # 首次导入几年历史（0.5 = 6 个月；改 10 就是 10 年库）
min_history_years = 0.4         # 跨度门槛（**必须 < history_years**）
auto_download_on_start = true   # 缺数据时是否自动下载（增量自动；全量始终需确认或 --auto-download）
min_symbols = 4000
max_stale_trading_days = 0      # ready 允许落后的交易日数（>0 则该范围内也算 ready）
```

> **为什么默认只导 6 个月**（用户拍板）：**超短线不需要长历史** ——
> 随包那几条公式看的是最近几周的形态，长历史对它们没有增量信息；
> 6 个月约 120 个交易日、约 50 万行，库更小、首次导入更快。
> 同花顺 `daily-k` dump 本身是固定的 10 年数据集（**没法只下 6 个月**），所以做法是
> **照常下载整个 dump，导入时只写最近 `history_years` 年的行**
> （下载量与下载时间不变，变的只是导入行数）。
> 复权事件（5.7 万条）**永远全部保留**，否则窗口起点之前的除权算不进去，整段后复权价会差一个常数。
> ⚠️ **代价说清楚**：成绩单的门槛是 250 个交易日，6 个月的库跑 `formulas.run_scorecard()`
> 只会显示"样本不足，无法评估"（成绩单本来就是长样本回测用的东西）。
> 想要长样本：把 `history_years` 改成 `10`（下载文件一样，只是导入更多行），
> 4 年以下的库会在报告里看到「样本较短，逐年稳定性仅供参考」。

> `formulas.run_scorecard()` 走的就是它的同一套口径。**今天它只在代码层可用**
> （`formulas.run_scorecard(公式名, ...)`），**没有命令行入口**；
> 出货默认 6 个月数据、门槛 250 个交易日，数据下够 1 年以上时它才有意义。

> ⚠️ **默认导入年限是 6 个月（0.5 年）**，而成绩单的门槛是 250 个交易日 ——
> 所以刚装好的库跑成绩单只会得到「样本不足，无法评估」（它本来就是长样本回测用的）。
> 自己把 `history_years` 改成 10 重导之后才有真结论；4 年以下的库会在报告里
> 看到「样本较短（< 4 年），逐年稳定性仅供参考」——年度分组只有两三个时，
> `✅ 每一年都为正` 的说服力比长样本弱得多。

**默认并列跑多套执行口径**（同一个策略"开盘买"和"尾盘买"的成绩可能完全不同 ——
只给一套口径，等于把一个执行假设偷偷写进结论里）：

| 口径 | 进场 | 出场 | 说明 |
|---|---|---|---|
| **A** | D+1 **开盘** | D+2 **收盘** | 旧口径（与 NAS 历史结论对齐） |
| **B** | D+1 **收盘（尾盘）** | D+2 **收盘** | **更贴近散户真实执行**：尾盘流动性好、不用抢开盘、避开开盘瞬时滑点 |
| **C** | D+1 **收盘（尾盘）** | D+2 **开盘** | 最短隔夜：只吃一个跳空 |
| A3/A5/A10、B3/B5/B10 | D+1 开盘 / 收盘 | D+3、D+5、D+10 收盘 | 对照档：看边际随持有期怎么衰减 |

输出：每条**公式** × 每套口径一行（**按平均 α 排序**），含 `样本 / 信号日 / 平均α / 胜率(α>0) /
t值 / 正边际年 / 剔开板 / 剔尾板 / 区间`，最后给出 **A vs B 结论**；并写出
`策略成绩单_<日期>.csv`（主表）、`策略成绩单_<日期>_结论.csv`、
`策略成绩单_<日期>_逐年明细.csv`、`策略成绩单_<日期>.md`。
**退出码/异常**：`0` 有结论；`1` 样本不足（会说明库里有多少行 / 多少交易日、差多少样本）；
口径写成"当天买当天卖"（= T+0）这类用法错误会被直接拒绝（抛异常，不进任何统计）。

口径（这几条决定了那些数字能不能当结论）：

| 项 | 口径 | 为什么必须这样 |
|---|---|---|
| 进场 | 信号日 D 的**次日（D+1）**：开盘买（A 家族）或尾盘收盘买（B/C 家族） | 收盘后才知道信号，最早只能 D+1 |
| 出场 | 严格晚于进场日（A/B 到 D+2 收盘、C 到 D+2 开盘、对照档到 D+3/5/10） | **A 股 T+1：当天买入当天不能卖**，"当天买当天卖"会被直接拒绝（抛异常/退出码 2），不进任何统计 |
| 买不进 | 开盘买看"进场日开盘涨幅 ≥9.5%"（一字板 → **剔开板**）；尾盘买看"进场日收盘涨停"（→ **剔尾板**） | 挂不进去的单子不该算收益；两种买法剔除的**不是同一批样本**，所以分开计数 |
| 卖出侧 | **不剔除** | 跌停卖不出去是真实风险，本表不改写收益 |
| α | 个股区间收益 − **同口径**的同期全市场等权收益 | 进场用收盘价，基准就必须用收盘价：混用会凭空多出/少掉一个开盘缺口（正好是 α 的量级） |
| t 值 | 先按**信号日**求平均，再对这条日度序列做 t 检验 | 同一天几十只票同涨同跌，按笔数算 t 值会虚高十倍以上 |
| 逐年 | 每年给出 α 与胜率（`✅6/9` / `⚠️` / `❌0/9`） | 一眼看出是"一直有效"还是"只有某一年有效" |

**怎么读（结论口径）**：只有 **A、B 两套口径都为正**才算"这个策略有边际"。
只有开盘口径为正的，报告里会明确标注「**可能依赖开盘执行**（抢开盘、滑点大、未必吃得进），
谨慎对待」；只有尾盘口径为正的，说明这个边际"抢不到开盘才吃得到"，反而更贴近真实执行。
此外还要看：**t 值 ≥ 2、逐年大多为正、α 能盖住约 0.15% 的往返成本** ——
α 在 0.1% 量级的策略，扣完成本基本就没了。**本表未计交易成本与滑点**，
且股票池是"当前仍在上市"的代码（有幸存者偏差，收益偏乐观）。

> 与服务器版口径的差别只有一处：本表把"出场"整体后移一天，保证 T+1 合法 ——
> 服务器版记的 `T+N` 是"D+N 收盘卖"（持仓 N−1 日），N=1 时那就是不可执行的 T+0。

### 怎么点着写第一条公式（小白三步）

1. 打开「策略选股」页 → 点【策略编辑】→ 点【**载入示例**】→ 编辑框里出现一条能跑的公式
   （第一次用会看到随包的 `放量上攻`：`M5:=MA(C,5)` / `V5:=MA(V,5)` / `C>M5 AND C>O AND V>V5*1.5`）；
2. 想改哪就改哪 —— **把光标放到要改的位置，点右边的按钮**。右边是**四组**按钮，
   按**变量 / 函数 / 运算符 / 排除** 从上到下排（「排除」在最下面，2026-09-18 按用户要求
   从运算符前面挪到最后），一共 52 个（变量 11 / 函数 20 / 运算符 15 / 排除 6）。
   **按钮上写的全是中文**（点一下就懂），点一下插进去的才是公式语法 ——
   每个按钮的鼠标提示**第一句就写着插进去的是什么**，两边一对就明白：
   - **变量**（`收盘价` → `C`、`开盘价` → `O`、`最高价` → `H`、`最低价` → `L`、
     `成交量` → `V`、`成交额` → `AMO`、`昨收价` → `PRE`、`行业` → `INDUSTRY`）；
     后面三个字段**2026-09-18 新增**：`流通市值`（亿元）与 `换手率`（%）
     【**来自实时快照，只有"今天"这一个值**】、`热门行业`（**最近 3 个交易日里这只票的
     行业上过几次热门榜**，0~3）—— 这几类的差别见下一小节；
   - **函数**（`均线` → `MA`、`指数均线` → `EMA`、`几天前的值` → `REF`、`区间最高` → `HHV`、
     `区间最低` → `LLV`、`求和` → `SUM`、`数次数` → `COUNT`、`上穿` → `CROSS`、
     `绝对值` → `ABS`、`取大的` → `MAX`、`取小的` → `MIN`、`二选一` → `IF`、
     `波动大小` → `STD`、`距上次几天` → `BARSLAST`），以及本项目特有的 `涨停天数` / `连板` /
     `量比`，和 **MACD 三件套** `MACD快线` → `DIF()` / `MACD慢线` → `DEA()` / `MACD柱` → `MACD()`
     （= `EMA(C,12)-EMA(C,26)` / `EMA(DIF,9)` / `(DIF-DEA)×2`；分别需要 **26 / 35 / 35** 根 K 线）。
     点 `均线` 会插入 `MA()` 并把光标放在**括号里**，接着打 `C,5` 就是 `MA(C,5)`；
   - **运算符**（`加` → `+`、`减` → `-`、`乘` → `*`、`除` → `/`、`大于` → `>`、`小于` → `<`、
     `大于等于` → `>=`、`小于等于` → `<=`、`等于` → `=`、`不等于` → `!=`、`并且` → `AND`、
     `或者` → `OR`、`取反` → `NOT`、`左括号` → `(`、`右括号` → `)`）；
     `并且`/`或者`/`取反` **自动补空格**（不会粘成 `A>1AND B`）；
   - **排除**（在最下面）：六个按钮写「非 X」，点一下插进去的是 `X=0` ——
     `非 ST` → `ST=0`、`非北交所` → `北交所=0`、`非科创板` → `科创=0`、
     `非沪市` → `沪市=0`、`非深市` → `深市=0`、`非创业板` → `创业板=0`。
     这样写的好处是**一眼看出点下去是"要"还是"不要"**（以前的按钮只写 `ST`，
     看不出点一下到底是要 ST 还是排除 ST）。口径见下一小节。
   按钮**做得比普通按钮小**（一行 4 个、固定高 20 像素、字号比默认降一档；见
   `ui/formula_page.py` 的 `BUTTON_HEIGHT` / `BUTTON_FONT_DELTA`）：
   四组 52 个按钮，用默认大小要把右侧面板滚很久才看得全；
   点按钮插入的是**当前光标所在的位置**，不是追加到末尾 —— 你改中间那一行时不会被悄悄改坏；
3. 填上**公式名称**（+ 可选备注）→ 点【**校验**】→【**运行**】→（想留证据就点【**导出选股结果**】）→【**保存**】
   （可【另存为】；底部两行按钮：上一行是 **校验 / 运行 / 导出选股结果**，
   下一行是名称框 + **保存 / 另存为 / 删除**）。
   - 【校验】通过会告诉你用到的**字段/函数**与"至少需要 N 根 K 线"；
     写错就直接给中文原文：`第 1 行第 3 列：未知函数 "MAA"（是不是想写 "MA"？可用函数：…）`；
     语法错时**标题区也会同时弹一句**（不用去下面找那一行小字）；
   - 【运行】（**2026-09-18 从"试算"改名为"运行"**，按钮上写的是
     `运行：当前库能选出几只`）用**你本地的库**跑一遍，告诉你最近一个交易日命中几只
     （`名称(代码)` 格式，最多列 20 只）。跑在**后台线程**里，界面不会卡：
     期间【运行】按钮**变灰（点不动）**、进度条转起来、提示区写「正在运行…（在后台跑，界面可以继续用）」，
     重复点击只会提示「运行还在跑，请稍候…」；跑完按钮恢复可点、进度条收起。
   - 【导出选股结果】把**刚跑出来的那一批**写成一个 UTF-8 文本文件放到**桌面**，
     文件名 `老牛选股助手-选股结果-<今天>.txt`（例：`老牛选股助手-选股结果-2026-09-18.txt`；
     行情日写在正文第一行的括号里，例 `… · 2026-09-18（行情日 2026-09-17）`），
     内容与「自选股池」的导出**同一个函数**（`pool.export_pick_file`：表头 + 每行一只票，
     来源标 `公式·<公式名>`）。**同一天里它和【开始选股】的桌面文件是同名文件**
     （都会被覆盖，不会出现两个文件）—— 这与【开始选股】"同一天再点一次会覆盖同名文件"是同一套口径。
     成功会说 `✅ 已导出选股结果：<文件名>（N 只，行情日 <日期>）` 并给出**文件位置**；
     没跑过就导出会提示「还没有可导出的结果：先点【运行】…」；
     **正在跑**的时候点导出会提示「运行还没跑完：等它跑完再点【导出选股结果】」
     （绝不会拿上一轮的结果顶上 —— 导出的永远是你刚看过的那一份）；
     跑出来 0 只则提示「❌ 最近交易日 … 没有命中的股票，没有可导出的结果」；
     写不出去（桌面不存在 / 没写权限 / 文件被占用）会说清原因并让你看日志；
   - 编辑器里**没有【看成绩单】**：6 个月的库跑成绩单只会说"样本不足"（见上面「策略成绩单」一节），
     那个能力保留在 `formulas.run_scorecard()` 里（**命令行入口已删**，只留代码层可用）。

> 公式语言是**通达信/同花顺风格**：`:=` 定义中间变量、最后一行为选股条件、
> `{ }` 或 `#` 是注释。语法、函数/字段白名单见 `src/laoa_trader/strategy/formula.py`。

| `流通市值` | 流通市值（**亿元**） | **实时快照**（`formulas.snapshot_extra()` → `sources.snapshot_map()`，含"按字段从后面来源补齐"） | **只有最后一根 K 线有值**；取不到就整条是 NaN |
| `换手率` | 换手率（**%**） | 同上 | 同上 |
| `热门行业` | **最近 3 个交易日内，这只票所属行业上过几次热门榜**（0~3，只有最后一根 K 线有值） | **离线**：`formulas.hot_industry_counts()` 每天算一遍 `pool.hot_industries()`（默认取前 12 名），把 3 天的结果并起来数次数 | 与"今天"绑定：回头跑历史那几天的选股时，用的仍是**最新**的热门榜口径（**略有前视**，只适合当天用） |
| `ST` | 是否风险警示股（1/0） | **离线**：名称含 `ST` 就是 1（`S佳通` 这种未股改 S 股**不算** —— 判据是含 ST 不是含 S） | 无（不联网、历史每一根都成立） |
| `科创` | 是否科创板（1/0） | **离线**：代码 `688` / `689` 开头 | 同上 |
| `北交所` | 是否北交所（1/0） | **离线**：代码 `4` / `8` / `92` 号段 | 同上 |
| `沪市` | 是否沪市（1/0） | **离线**：代码 `6` 开头，或 `900`（沪 B）；**科创板算沪市** | 同上 |
| `深市` | 是否深市（1/0） | **离线**：代码 `0` / `3` 开头，或 `200`（深 B）；**创业板算深市** | 同上 |
| `创业板` | 是否创业板（1/0） | **离线**：代码 `300` / `301` 开头 | 同上 |

**「排除」按钮组就是这六个标记**（点一下插 `X=0`）：`非 ST` / `非北交所` / `非科创板` /
`非沪市` / `非深市` / `非创业板`。**注意两组之间有蕴含关系**：`沪市`包含科创板，
`深市`包含创业板 —— 所以「非沪市」会**连科创板一起排掉**，「非深市」会**连创业板一起排掉**；
想只排科创、留着别的沪市票，就写 `科创=0`（两个标记互相独立，谁也不蕴含谁）。

**为什么前两类要分开说**：`流通市值`/`换手率`/`热门行业`**不在日线里**
（同花顺的快照端点也不返回市值与换手，见上面「数据来源」一节的"字段级补齐"），
而六个 0/1 标记完全由代码与名称推出来（在 `Series.__post_init__` 里**自动补齐**，
调用方不用准备），所以**运行 / 选股 / 成绩单哪个入口都直接可用**。

先把这条**可以直接粘进编辑器、已经能编译能选股**的公式给你（用户点名要的那条）。

**它现在随包预置了**（2026-09-18 起）：文件名就是 `尾盘选股策略.txt`，
第一次打开程序时自动出现在 `formulas\` 目录里、也出现在策略列表的公式那一段，
**不用自己粘**；想改就直接点它载入编辑器改（随包公式和你自己存的一条待遇，可改可删可停用）：

```text
LTSZ_OK:=流通市值>=10 AND 流通市值<=300
HSL_OK:=换手率>5
PRICE_OK:=C>=3 AND C<=50
VOL_UP:=V>REF(V,1)*1.5
LTSZ_OK AND HSL_OK AND PRICE_OK AND VOL_UP AND 量比()>=1.5 AND ST=0 AND 科创=0 AND 北交所=0
```

（本机实测：这条**能编译**，用到的字段是 `C / VOL / 流通市值 / 换手率 / ST / 科创 / 北交所`，
【校验】会告诉你"至少需要 6 根 K 线"。）

**三条必须知道的规矩**：

1. **只有最后一根 K 线有值**（前面全是缺值）：`流通市值>=10` 这种直接比较**能用**
   （选股本来就看最后一根）；但 `MA(流通市值,5)` 这种滚动计算**不会产生信号** ——
   这是**刻意的**，不许拿今天的市值倒推历史。想写均线之类的，请用价格/成交量字段。
2. **取不到就是"条件不成立"，不报错**：没快照时（**非交易时段**、或来源都取不到）
   这两个字段整条是缺值，**用到它们的条件一律不成立** → 可能**一只都选不出来**；
   程序会在结论里补一句人话：
   `⚠️ 市值/换手这两个数现在取不到（没有实时行情快照），用到它们的条件一律不成立 —— 所以可能一只都选不出来。交易时段再试，或者在「系统设置 → 数据来源」里确认来源可用。`
   **所以：非交易时段用这条公式运行得到 0 只是预期的，不是公式写错了。**
3. **不用它们的公式，一个请求都不发**：只有公式**真的用到**这两个字段时才会取那一趟快照
   （判据是 `formula.fields`，运行与选股两条路都判）—— 纯价格/成交量公式的开销与以前完全一样。
   `热门行业` 同理：**公式用到它才算**（它只读本地库、不联网，所以慢也只慢在本地那几天榜单）。

**只能用中文名**（`流通市值` / `换手率`），**没有** `LTSZ` / `HSL` 这类英文别名：
设了别名就会占住那个名字，用户再写 `LTSZ:=流通市值`（把它当**自己的中间变量**）反而会被拒
（"变量名与内置字段同名"）。现在不设别名，所以 `LTSZ:=流通市值` 是**你自己定义的变量**，
可以正常用（`C:=…` 这种与内置字段同名的才会被拒）。

编辑器右侧的「变量」面板里这些字段都在（按钮写 `流通市值` / `换手率` / `热门行业`），
**点一下就插到光标处**，鼠标停上去有口径与例子；六个 0/1 标记则不做成变量按钮，
而是最下面「排除」组里那六个「非 X」按钮（点一下插进 `X=0`）。

### 保存到哪、怎么参与选股

- 公式存成**纯文本文件**（UTF-8），目录是：
  - 源码运行：仓库根 `laoA/formulas/`；
  - **打包后：exe 同级的 `formulas\`**（程序会把随包预置的公式复制进去）。
    想换目录就设环境变量 `LAOA_TRADER_FORMULAS`。
  文件格式就是引擎认的注释头 + 公式体，用记事本也能改：
  ```text
  # 名称: 5日线上放量
  # 说明: 字段：C、VOL；函数：MA；至少需要 5 根 K 线
  M5:=MA(C,5)
  V5:=MA(V,5)
  C>M5 AND V>V5*1.5
  ```
  （文件名 = 公式名，`\ / : * ? " < > |` 会被安全化成 `_`；重名保存会**先问一句**再覆盖。）
- **随包预置的公式**（也就是「内置公式」）= 仓库里那个 `formulas/` 目录，打包时一起分发。
  2026-09-18 起是**逐条补齐**（原来是"只在空目录复制一次"）：
  - **缺哪条补哪条** —— 新版本多带一条公式时，老用户的目录里也会自动出现；
  - **同名文件已存在就绝不覆盖**（你自己存的、或改过的，永远是你的）；
  - **你删掉过的那条不再补** —— 靠公式目录里那份记录文件 `.laoa-seeded.json` 认人：
    记过"给过他、他删了"，就不再长回来（不然每次启动都冒出来，像程序坏了）。
  **退役的公式永不复制**（2026-09-18 新增的第 4 条规则）：用户要求删掉「连板回踩低吸」，
  而它在老版本里就是随包的 `涨停回踩低吸.txt` —— 只从仓库里删文件的话，**已经装过老版本
  的目录里那份还在**。所以启动时会顺手清一次，判据是**逐字节哈希与老版本一致**：
  没改过的删掉，**改过的留着**（那是你的劳动成果，程序不替你决定）。
  现在随包的是 **6 条**：
  - `短期反转`、`地量后放量变盘`、`首板缩量整理` —— **2026-09-18 从"内置策略"改写成公式**
    （条件与原策略一一对应：改写当时有一份等价性测试逐条比对过；唯一对不齐的是
    "按因子排序取前 30" —— 公式语言没有排名函数，进池时每条公式最多 3 只）；
  - `尾盘选股策略` —— 你那条 6 条件策略（2026-09-18 起随包）；
  - `放量上攻`、`均线多头排列` —— 最基础的写法示例。

  它们和你自己存的一样**可改可删可停用**（这就是"内置策略可以由用户自由编辑和删除"）。
- 想让公式**参与每天的选股**：在策略列表里**勾上那一行的「策略选取」列**。
  勾上的公式就是这一轮选股的**全部候选来源**（2026-09-18 起，那批 Python 内置策略
  已经退出选股链路）：进池、进推送，来源标成 **`公式·<公式名>`**
  （「自选股池」表「来源」列与推送正文那一行都是这个标记）。
  **默认不参与** —— 一条都不勾时只盯自选股（与"没这个功能"时的表现一致）。
  （**保存不自动勾选**：代码注释里的原话是"参不参与选股由用户自己决定，保存只管存"；
  保存完公式会出现在列表**最下面**，需要你自己去勾那一行的「策略选取」列。
  **唯一的例外是「竞价策略」那一行**：它开关的是盘中竞价扫描，勾它不参与选股，见上一节。）
- 勾选会**立刻写回 `config.toml`**（你自己写的注释与未知键都保留）：
  ```toml
  enabled_formulas = ["5日线上放量", "尾盘选股策略"]
  ```
  名字写错了（文件删了/改名了）或公式语法有错的条目**会被忽略并记日志** ——
  一条坏公式不会让整轮选股失败，也不会影响其它公式（池子照常生成，
  那条公式在「说明」列里标 `⛔ 语法错：…` / `⚠️ 运行时出错：…`，全文在 tooltip 里）。
- 点【开始选股】后会跑所有**勾选的公式**，结果**三个去处**：
  1. **这一页的选股结果表**（2026-09-18 起）—— 列表那块切过去显示，可【一键加入自选】
     /【导出结果到桌面】；
  2. **直接进「自选股池」**（主入口）—— 选出来的票就是池子里的行，在那一页右键【删除】、
     或再手工【添加自选】；
  3. **同时往桌面导出一个文本文件**（见下面「选股结果的桌面文件」一节）。

### 选股结果的桌面文件（2026-09-17 新增）

- **文件名**：`老牛选股助手-选股结果-YYYY-MM-DD.txt`（日期 = **导出当天**，北京时间）；
- **编码/换行**：UTF-8 **带 BOM** + **CRLF** —— 这份文件是给 Windows 用户双击用记事本看的，
  没有 BOM 老版记事本会把中文显示成乱码；
- **正文**：

  ```text
  老牛选股助手 · 选股结果 · 2026-09-17（行情日 2026-09-17）
  共 2 只（策略 1 · 自选 1）
   1. 贵州茅台(600519)  现价 1266.98 +0.71%  来源：公式·尾盘选股策略
   （本文件由程序自动生成；数据为公开来源的准实时快照，非交易所授权行情，不构成投资建议。）
  ```

  第一行括号里是**行情日**（本地数据的最新交易日）——它可能与导出当天不是同一天
  （周末/节假日导出时就是这样）。第二行的两个数与「自选股池」表头那行小字**同一个算法**。
- **桌面目录怎么找**（按顺序取第一个存在的）：系统答案（Qt `QStandardPaths`，认 OneDrive
  重定向与中文"桌面"）→ `Desktop` → `桌面` → `OneDrive\Desktop` → `OneDrive\桌面`；
  一个都没有就**退回数据目录**（用户找得到的地方，日志里写明落在哪）；
- **导出失败只记日志**，**不影响选股/建池/推送**（内层与外层各兜一层）；
- **同一天再跑一次会覆盖同名文件**（桌面不是归档目录）；桌面上到底写没写成功，
  运行状态里会说一句"结果已导出到 <路径>"。
- **如实说明的限制**：这个导出**没有开关**（不能用配置关掉），而且**同日覆盖**、
  不按策略分子文件。
- 公式**不打**任何证据标记（原来那套「（依赖开盘）」标注 2026-09-18 已随推送过滤一起删除）；
  那两条公式的历史数字写在它们自己的文件「# 说明:」里，你自己写的公式则由
  `formulas.run_scorecard()` 说话。

### `连板()` / `涨停天数()` 有个历史坑

这两个函数读的是**本地涨停池**（`limit_up_pool`，逐日同步攒出来的），
**早期日期会读到 0** —— 所以你刚开始用（或刚换机器）时，用到它们的公式会
"选不出票"、成绩单样本也会偏少。这不是公式写错了，是数据还没攒够。
程序在【校验】通过时**会提醒一次**；
等涨停池攒了几个月再回头看，结果会正常。

## 自选股：和公式标的并列进池，一起实时监控

池子成员现在有**两类**：公式标的 + 你自己加的自选股。自选股：

- **不受热门行业过滤**（你选的，就是要盯）；
- **不占策略名额**（池子大小只限制公式标的，自选另有上限 `watchlist_max`，默认 20）；
- 同一只**既是公式选中又是自选** → 池子里只出现一行，「来源」列标成 `公式·<公式名>+自选`；
- 停用（`enabled=0`）的不进池、不监控，但仍留在表里，随时能再打开；
- **即使一条公式都没勾也照常盯**（那本来就是默认状态：`enabled_formulas = []`）；
- 盘中买卖点与通知频道完全沿用同一套：有持仓 → 用**成本**算止损止盈；
  没有 → 用**前一交易日收盘**，并适用「池内回踩买点 / 放量突破20日高」；
  提醒文案带备注，例如「自选（龙头，成本 12.40）」。

三种用法：

1. **界面** → 「自选股池」页：填代码（**名称自动从本地库补**）+ 备注 → 【添加自选】（回车即加）；
   行上右键 = 【删除】/【关闭监控】↔【打开监控】/【打开雪球】，**单击名称直接开雪球个股页**；
   表头右边一行小字写着 `共 N 只（策略 M · 自选 K）`（M + K 可能大于 N：既是策略选中
   又是自选时只算一行）。
2. **命令行**：

```bat
.venv\Scripts\python -m laoa_trader --cli --watchlist add 600519 --note 龙头
.venv\Scripts\python -m laoa_trader --cli --watchlist list
.venv\Scripts\python -m laoa_trader --cli --watchlist disable 600519
.venv\Scripts\python -m laoa_trader --cli --watchlist enable 600519
.venv\Scripts\python -m laoa_trader --cli --watchlist remove 600519
```

3. **config.toml**：

```toml
watchlist_max = 20        # 自选股上限（超限会提示，不静默丢弃）
watchlist_in_pool = true  # false = 只记录不监控
# 想让选股也跑起来，就往 enabled_formulas 里写公式名（或在列表里勾「策略选取」列）；
# 不写 = 只盯自选股（默认状态）
```

「自选股池」的「来源」列写清**是哪条公式**选出来的（用户给定的口径）：

| 情形 | 「来源」列 | 行 tooltip 里还有 |
|---|---|---|
| 公式选中 | `公式·尾盘选股策略` | 同批选中的其它公式名 |
| 手工自选 | `自选` | 备注 |
| 既被公式选中又是自选 | `公式·尾盘选股策略+自选` | 同上 + 备注（老库里 2026-09-18 之前的行仍写作 `策略·短期反转+自选`，那是历史文本，不会被改写） |

**主策略与其余策略**：一行被多条策略/公式同时选中时，列里只写得下**主策略**
（`stock_pool.strategy` 那条，建池时按分数定的），其余策略名收进 tooltip 的
`同批选中：…` 那一行 —— 不丢信息，也不靠加列。**推送正文那一行列的是全部公式名**
（`尾盘选股策略、放量上攻`）：手机上一行没有 tooltip，多写几个字比少一条信息好；
两处用的是同一个名字（都出自公式文件里的 `# 名称:`），所以不存在"同一件事两套说法"。
`--cli --pool` 的输出同样是「来源」栏 + 备注（「组别」那一栏现在对所有行都是 `—`：
策略组这套机制 2026-09-18 已经删除，栏位留着只是不让老脚本解析崩掉）。

**四块分别是什么 / 口径**：

| 块 | 内容与口径 |
|---|---|
| **成交与情绪**（**最上面**，2026-09-17 新增） | **7 个小条目排成一行**（宽屏一行 7 个、窄屏自动换行；`MARKET_STAT_TITLES`）：`成交额` + `涨停` / `跌停` / `炸板` / `上涨` / `下跌` / `平盘`。成交额是**沪 + 深 相加的一个数**（`turnover["total"]`），**北交所成交额已删除**（数据还留在 `turnover["bj"]` 里，界面上任何地方都不画它） |
| **宽基指数** | **7 只**：上证 / 深成 / 创业板 / 科创50 / 沪深300 + **上证50（`000016.SH`）** + **中证1000（`000852.SH`）**：点位 + 涨跌幅，各自按涨跌上色。指数走实时快照端点 `a-share-index/prices/snapshot`，**必须传代码**（不支持全市场）；取回后按代码归属分组显示 |
| **情绪指数** | `market_sentiment_indices` + `market_sector_indices` **两组都装在这一块里**（它们本来就是同一类同花顺板块指数）。**现在只剩指数条目** —— 成交额/涨跌停/涨跌家数都搬到上面那一块了 |
| **热门板块** | **上涨前五 + 下跌前五 两张表**（各 5 行）：`板块名称 | 涨停数量 | 涨幅 | 主力净额`（表头四个词是用户给定的，口径写在每列表头的 tooltip 里）。上涨表按涨幅**降序**取前 5、下跌表按涨幅**升序**取前 5 |

**7 个小条目的口径**（改的是版式，不是信息）：

| 条目 | 口径 |
|---|---|
| 成交额 | 沪 + 深 **相加成一个数**：取自**上证指数 `000001.SH`** 与**深证成指 `399001.SZ`** 的成交额（这两个数就是沪深两市成交额）。所以它与指数同一个节拍（每分钟刷新），**不再是** 5 分钟一档 |
| 涨停 / 跌停 / 炸板 | **有 Key**：涨停池、跌停池、炸板池，`size=1` 只取 `pagination.total` 的**家数**（不拉明细）。**没 Key**：没有现成池子可查，由同一趟 5 分钟缓存的全市场扫描自己判（见下面那条 ⚠️） |
| 上涨 / 下跌 / 平盘 | 全市场快照分页汇总 → 由 `market_breadth` 控制（**默认开**）。**关掉时显示 `—`，页面上还会写明原因**（不去翻全市场快照，省配额）。**有 Key**：约 5571 只 / 每页 1000 / 6 个请求；**没 Key**：与涨跌停家数共用**同一趟**扫描，翻页不再花请求 |

> ⚠️ **免 Key 路径下这三项的口径要单独说清（2026-09-17 对齐同花顺定的，不是随手取的）**：
> - **涨停家数排除 ST 与北交所**（`LIMIT_EXCLUDES_ST` / `LIMIT_EXCLUDES_BJ`）。
>   实测 2026-09-17：按"现价 == 涨停价"扫出 **50 只**，而同花顺涨停池当天是 **47 只** ——
>   差的 3 只**全是 `*ST`**（腾讯给的涨停价就是昨收 ×1.10，现价正好压在涨停价上）。
>   再核对库里 1188 个交易日的同花顺涨停池：**`is_st` 全为 0、且不含任何北交所代码** ——
>   也就是说同花顺那个"涨停家数"的口径本来就是**沪深两市、不含 ST**。
>   为了让"加不加 Key"不至于让同一个数字跳 3 只，这里**跟着参照物的口径走**，而不是自作主张换一个。
> - **涨跌家数含 ST 与北交所**（与上面两个口径**故意不同**：那是"全市场涨跌"，本来就该含）；
> - **停牌不计入涨跌**：一天里停牌的票（腾讯回成交量 0、涨跌幅 0.00，实测 12 只）既没涨也没跌，
>   算成"平盘"会凭空多出十几只平盘。这一条与同花顺"快照里没有涨跌幅的行跳过是同一个意思"；
> - **炸板**等价定义 = "最高价摸到涨停价、但现价低于涨停价"（涨停价是当日硬顶，
>   所以"摸到过涨停"与"最高 == 涨停价"等价；再排除现价仍封在涨停价上的）。
>   实测当天 23 只。腾讯对"没有数据的票"回 `-1`/`0` 这种哨兵值，会先清成 `None` 再判 ——
>   不清的话"最高价 0 == 涨停价 -1"会被算进炸板，凭空多出几只；
> - **成交额有一次自校验**：把逐只 `[35]` 成交额按交易所相加，得到沪 **8685.26 亿** / 深 **9543.21 亿**；
>   指数快照那边给的是沪 8687.73 / 深 9543.61，其中**"深证Ａ指"正好 9543.21 亿**
>   （与扫描相加**逐字节相同**）、**"Ａ股指数"正好 8685.27 亿**（与扫描相加差 0.01 亿）。
>   两条完全独立的路算出同一个数，说明**代码表没漏票、成交额字段没串位**
>   （沪市那个差 2 亿多是 B 股）。

**宽基那 7 只是怎么来的**（用户 2026-09-17 要求"加上证50、中证2000、科创板"）：

- **上证50 `000016.SH`**：加上（实测腾讯 `qt.gtimg.cn/q=sh000016` 回 `1~上证50~000016~…`）；
- **中证2000：拿不到 —— 改用中证1000**。同一天实测腾讯 `sh932000` 与 `sz932000` **都**只回
  `v_pv_none_match="1"`（= 那边没有这个标的）、新浪也空，所以换用同一天实测可返回的
  **中证1000 `000852.SH`**（腾讯回 `1~中证1000~000852~…`）—— 它是小盘口径里最接近中证2000
  的可用指数，不是"随便换一个"。这件事在代码里留了可断言的记录（`market.REJECTED_INDEX_CANDIDATES`，
  `tests/test_market.py` 钉着它），**不是静默换掉**；
- **"科创板"**：宽基里的 **`000688.SH` 科创50** 就是它（保留）。同一天实测还有 `000680`
  （科创综指）可返回，但它既不是用户原话里的口径、也没有在本项目实际取数用的那个端点上验证过，
  所以**不硬加** —— 想加就在 `config.toml` 的 `market_indices` 里写 `000680.SH`；
- 实现上这 7 只 = 配置默认的 5 只（`config.DEFAULT_MARKET_INDICES`）**+ 取数层补的 2 只**
  （`market.WIDE_INDEX_EXTRA_CODES`，只要 `market_indices` 非空就一定带上）；
  `market_indices = []`（空）仍然是"这一块不要" —— 那时整块连标题一起隐藏。

**热门板块那两张表**：

- **`涨幅`**：板块**当天**涨跌幅（%），来自 `data/sectors.py` 的腾讯行业板块排行榜
  （`https://proxy.finance.qq.com/cgi/cgi-bin/rank/pt/getRank`，**免 Key**、实测可用）；
- **`主力净额`**：来自同一个接口的 `zljlr`，**原始单位是万元**，界面按**亿**显示
  （例：`-58031.01 万元` → `-5.80亿`，正 = 净流入）；取不到就是 `—`（**不是 0**）；
- **`涨停数量`**：**永远**来自本地 `pool.hot_industries()` —— 与选股时挑"热门行业"用的是
  **同一套口径**（不另起一套），所以页面上看到的涨停家数就是策略看到的那份；
  按板块名对齐，对不上的显示 `—`（不编一个 0 出来）；
- **取不到板块榜时退回"本地口径"**：涨幅那一列装的是**近 5 日行业等权涨幅**，
  而且**页内会写明"不是当日涨幅"**、主力净额显示 `—`。换个名字叫"涨幅"却不说明，
  等于拿另一个口径冒充用户要的那个数 —— 所以宁可多写一句；
- **已如实记下的三条限制**：
  1. 板块榜只有腾讯的一级行业，**实测一次只返回 31 个**（`count=60` 是"最多要几个"，
     不是"一定有这么多"）—— 所以"上涨/下跌前五"是从这 31 个里排出来的；
  2. 它走的是**公开但未授权**的接口，官方可能改字段或限流（`data/sectors.py` 有 60 秒短缓存，
     失败**不进缓存**，抖动不会让这一块白一分钟）；
  3. 板块榜的取数在**后台线程**里做，失败只影响这一块（指数那两块照常）。

**刷新节奏**：这一页有**自己的定时器，每 60 秒**刷一次（不是界面那个 5 秒的），而且

- **启动后立刻刷一次**（它是第一个页签，第一屏就是它）—— 不用干等 60 秒；
- **只在「大盘概览」页可见时才刷**（你停在别的页签上、或窗口隐藏到托盘时，一次都不打）——
  在看不见的地方每分钟白刷 4~6 个请求纯属浪费配额，也更容易撞上限流；
- **切到这一页时立刻刷一次**（定时器是整分钟对齐的，切过来时可能差几十秒到点，
  看盘的人不该盯着旧数）；
- 取数另有 **55 秒 TTL** 兜底（`market_overview_ttl`）—— 55 特意略小于 60，
  避免"每分钟刷一次却总差一点没到点"的边界抖动；页脚会写明取数时间；
- 【立即刷新】按钮 = 忽略缓存立刻重取（`request_market_overview(force=True)`）；
- **取数在后台线程**：界面线程只负责画。启动时数据自检（`run_preflight`）也在跑，
  两条要是都压在主线程上，就会出现"窗口已经出来了却点不动"（断网时每个请求还要等满超时）；
  概览取数、热门行业与**两张板块表**是**同一趟取齐**的（同一页、同一个刷新节拍，
  分两个线程会出现"表头写 10:31、热门板块还是 10:30 的"这种半新半旧）。

**怎么换指数**（配置里的三组都是 list，允许逗号分隔字符串）：

```toml
market_overview = true
# 宽基（默认这 5 只；页面上还会自动补上 上证50 000016.SH 与 中证1000 000852.SH，见上面那一段）
market_indices = ["000001.SH", "399001.SZ", "399006.SZ", "000688.SH", "000300.SH"]
# 情绪 —— **这几个是给你自己换的**（同一个端点，换个代码就换一套心情指标）
market_sentiment_indices = ["883404.TI", "883958.TI", "883994.TI", "883418.TI"]
# 板块（同花顺一级行业指数）—— 与上面那组**一起装在「情绪指数」块里**
market_sector_indices = ["881155.TI", "881157.TI"]
```

- 想换**显示名**：任意一组里都能写 `代码=名称`，例如 `"000001.SH=我的上证"`；
  名称默认走 `src/laoa_trader/market.py` 里的小表 `INDEX_NAMES`（**本地表，不每次刷新去拉目录**），
  表里没有的代码就直接显示代码本身；
- **宽基列表配空**（`market_indices = []`）→ 这一块**连标题一起隐藏**，不留一个空标题在那吊着；
  「情绪指数」块**始终显示**（与"配没配指数"无关）；
- 其它可选的情绪口径（同一个端点、实测都能取到）：
  `883900.TI` 昨日涨停表现、`883409.TI` 近期强势、`883918.TI` 昨日炸板股、`883408.TI` 近期新高、
  `883911.TI` 创历史新高、`883423.TI` 沪深主板昨日涨停、`883424.TI` 创业科创板昨日涨停、
  `883422.TI` 北交所昨日涨停表现。

> ⚠️ **一个非法代码只影响它自己**：接口对**一个**非法代码会**整批**返回 `1002 Unknown thscode`
> （例如混进 `899050.BJ` 北证50），所以程序批量失败后会**逐只重试**：
> 能取到的照常显示、只少那一项，取不到的代码记进日志、页面提示与 tooltip。
> 页面上**绝不会**因为一个代码写错就整页变空。

**`market_breadth`（默认开）与它自己的 5 分钟缓存**：涨跌家数没有现成接口，只能翻全市场快照。
跟着每分钟的页面刷新跑会白白吃配额，所以它**有独立的 5 分钟缓存**（页脚里也写着
"涨跌家数每 5 分钟更新"）。关掉（`market_breadth = false`）时：
`上涨/下跌/平盘` 三项显示 `—`，且**一个分页请求都不发**（页面还会写明"是关着的，不是坏了"）。

- **有 Key**：翻的是同花顺的全市场快照分页（约 5571 只 / 每页 1000 → **6 个请求**，
  页间还要 ≥0.3 秒）；
- **没 Key**：`public_market.PublicMarketClient.request()` 从**同一趟 5 分钟缓存的扫描**里分页
  （它是按 `limit/offset` 切内存里的行），所以翻 6 页**不再发任何请求** ——
  这是把免 Key 扫描做成缓存的另一个好处：**翻页免费**；
- ⚠️ 免 Key 时**停牌那一行必须给 `null` 而不是 `0.00`**：`market._fetch_breadth()` 对"没有涨跌幅"
  的行是**跳过**的（与同花顺快照同一语义）。给它 `0.00` 会把 12 只停牌票算成"平盘"，
  于是**同一个页面上** `counts()` 算出平盘 157、界面却显示 169 —— 同一个概念两个数。
  实测就是这么发现的（2026-09-17：157 vs 169，差额正好是 12 只停牌）。

> 这一档里**不再有"北交所成交额"**（2026-09-17 用户要求删掉）：分页循环照常按 .BJ 分桶，
> 数还留在 `turnover["bj"]` 里，但界面上任何地方都不画它 —— 页脚那句话里那半句也一并删了。

```toml
market_breadth = true     # 默认；false = 不取涨跌家数（显示 —，零分页请求）
```

**取不到数据时**：那一段显示 `—`，**绝不抛异常、绝不让界面起不来**；原因可以从三处看到 ——
页面上的提示行与 tooltip、日志（`<数据目录>\logs\laoa-trader.log`）、以及命令行输出：

```bat
.venv\Scripts\python -m laoa_trader --cli --market
```

`--cli --market` 打印的是**与页面同一份取数口径**的文本（走同一个 `market.kpi_values()`
与同一批指数请求）：前两行就是页面上「成交与情绪」块那 7 个数（摘要是"涨跌停 + 成交额"、
第二行是"涨跌家数"），之后三行分别是 `宽基` / `情绪` / `板块`（页面上后两组装在同一个
「情绪指数」块里）。
**页面上多出来的「热门板块」两张表不在这个命令的输出里**（它的数据来自 `data/sectors.py`
的板块榜 + 本地查询 `pool.hot_industries()`）。
取不到数据时 `--market` **退出码非 0** 并说明原因（网络不通 / 被限流 / 代码写错），
适合脚本或远程维护时"看一眼大盘"。

**数据来源（页面页脚）**：`数据来源：同花顺金融数据服务（配置 Key 时）与公开行情接口（腾讯/新浪/东财）；非交易所授权行情`
—— 页脚那一行写的就是这句 + 取数时间与刷新节奏（**顺序已在 2026-09-18 翻成同花顺在前**）。
「关于软件」里另有一句 `SOURCE_TEXT`（**公开源在前**，尚未跟着改），两处都写着
"均为公开来源的准实时快照，非交易所授权行情"。**本程序仅用于个人研究与学习，不构成任何投资建议。**

> ⚠️ **这一页走哪一路，取决于有没有 Key（2026-09-17 改的）**：
> - **有 Key** → `market._make_client()` 构造同花顺客户端，指数点位/成交额/涨跌停家数/涨跌家数
>   都来自同花顺那几个端点；页脚里**只有**"涨跌家数每 5 分钟更新"（三个池子是跟着 55 秒走的）；
> - **没 Key（或 Key 无效）** → `market._public_client()` 换成免 Key 的
>   `public_market.PublicMarketClient` —— **它和同花顺客户端是同样三个方法**
>   （`special_pool_total` / `index_snapshot` / `request`），所以 `_collect_overview()` 取数逻辑
>   **一行都不分叉**，"谁是主源"只落在 `fetch_overview()` 一处。
>   结果里 `price_source` 标出这一趟是谁供的数（`"public"` / `"hithink"`），
>   页脚也会跟着改口（见下一段）；
> - **Key 写错/过期/服务端未就绪**（构造时没报错、请求时才报错）也会落到公开源重取一次
>   （判据是失败原因属于 `_is_auth_problem()` 那一类；网络不通之类**不**重试 ——
>   那只会白花 56 个请求）。

**免 Key 路径下页脚会多一句（"这几项每 5 分钟更新"）**，因为口径真的不一样：

```
（有 Key）数据来源：同花顺金融数据服务（配置 Key 时）与公开行情接口（腾讯/新浪/东财）；非交易所授权行情 · 更新于 2026-09-17 15:03（每分钟自动刷新；涨跌家数每 5 分钟更新）
（没 Key）数据来源：同花顺金融数据服务（配置 Key 时）与公开行情接口（腾讯/新浪/东财）；非交易所授权行情 · 更新于 2026-09-17 15:03（每分钟自动刷新；涨跌停家数、涨跌家数每 5 分钟更新）
```

- 为什么免 Key 时**涨跌停家数也变成 5 分钟一档**：这一路没有"涨停池"这种现成接口，
  涨停/跌停/炸板与涨跌家数**全是同一趟全市场扫描**（新浪代码表 55 页 + 腾讯快照 56 批 =
  **111 个请求 / 约 103 秒**）算出来的。概览页每 55 秒刷一次，要是那趟扫描能跟着刷，
  就等于"每 55 秒把全市场重扫一遍" —— 那是自己找死（限流/封 IP）。
  所以扫描结果按 **5 分钟**缓存（`public_market.SCAN_TTL = 300`，与 `market._BREADTH_TTL` 同一个节拍），
  【立即刷新】**只刷新便宜的那部分**（指数与成交额，一个请求），**不穿透**到扫描层
  （`PublicMarketClient` 故意没有 `force` 参数）。页脚把这件事逐项写清楚，不骗人。
- **成交额不在这 5 分钟一档里**：它取自上证指数与深证成指的 `turnover`，与指数同一个节拍。
- 免 Key 路径下**情绪指数 / 板块指数那两组是 `—`**：公开源没有同花顺板块指数（`.TI`）的对应标的。
  这些代码被归进 **`unsupported`**（**不是** `failed`）—— `failed` 在界面上是"你配的这个代码有问题"，
  而这一类是"公开源根本没有这种标的"，混在一起会让用户去改一个其实没写错的代码。
  页内会有一句说明：`免 Key 公开源没有这几组的对应标的（配同花顺 Key 才会显示）：情绪、板块`。
- 页脚那句"同花顺…与公开行情接口…"是**全应用**的数据来源声明（同花顺要配 Key 才走），
  不是"这一页两路都试过了"；单独某一页具体走哪一路，看上面的 bullet 与
  「[数据来源](#数据来源主源是同花顺要-key免-key-的公开源是兜底)」那一节。

盘中提醒除了止损止盈/跌破 5 日线/涨停打开/放量突破 20 日高/池内回踩买点这六条规则，

**① 集合竞价扫描（全市场，9:15–9:25 的真实买卖盘）— ⚠️ 已就绪但默认关闭**

> 代码、界面（「系统设置 → 竞价扫描」那一组 + 【显示详情】里的扫描结果）与测试都已就绪，
> 但**阈值口径还在与你确认**，所以 `intraday_auction` **默认 false**：默认流程一次竞价请求都不发、
> 不显示竞价那一行、不产生竞价提醒。在「系统设置 → 竞价扫描」勾上并保存即可启用（不用改代码）。
> **2026-09-18 起两个开关都能开它**：设置页那一组，或者「策略选股 → 策略列表」里那一行
> **「竞价策略」**（同一行、同一个键，勾哪边另一边都会跟着变；见上面「策略选股」一节）。
> 下面这段是"当前实现"的口径。

**扫的是全市场，不是只看自己的池子**（这是与上一版的区别：上一版只扫池子/自选/持仓，
看不到池子外面的强势票）：

1. **代码来源**：优先本地 `stock_basic`（**零请求**，下载/同步时已经写好）；
   库里还没有（首次运行没下完数据）才退回 `meta/tickers/list`，再退回全市场快照分页
   （这条没有中文名，名称退回代码）—— 每次退回都会在日志里写明原因；
2. **取数**：`auction/snapshot` 按 **100 只一批**，全市场约 5600 只 → **约 56 个请求**；
3. **节奏**：**只在 `auction_scan_at` 到点时扫**（默认 `09:20` 与 `09:25`，9:25 那次是
   **竞价终态**）。为什么不每分钟扫：56 请求 × 10 分钟 = 560 请求，配额会被打光、
   也容易触发限流。批间 ≥0.3 秒、串行不并发，一次扫描约 **20~30 秒**，
   跑在**后台线程**里（界面不会卡），日志里每 10 批打一行进度。

**过滤规则**（**全部**能在「系统设置 → 竞价扫描」里改，写回 `config.toml`）——
这一组现在是**开关 + 8 个参数**：涨幅下限 / 涨幅上限 / 成交额下限 / **量比门槛** /
板块（多选）/ 打分阈值 / 推送条数 / 扫描时刻。

> **量比门槛（`auction_min_volume_ratio`）是第 8 个参数**：它决定打分里「放量」那 2 分给不给
> （满分 6），原来**只有 `config.toml` 能改**（界面上看不到，想放松一档只能去手改 TOML）——
> 现在补上了控件：标签 `量比 ≥` + `倍` 后缀的数字框（范围 0~20、步进 0.5、默认 **2.0 倍**），
> 于是**底部【保存设置】一键写回的键从 34 个变成 35 个**（多出来的就是它）。

| 规则 | 配置项 | 默认 | 说明 |
|---|---|---|---|
| 竞价涨幅下限 | `auction_min_pct` | **2.0 %** | 低于它的直接过滤 |
| 竞价涨幅上限 | `auction_max_pct` | **9.0 %** | ≥ 它的丢掉：一字板/接近涨停**买不进** |
| 板块（多选） | `auction_boards` | 四块全选 | `main` 主板 / `chinext` 创业板(300,301) / `star` 科创板(688,689) / `bj` 北交所（按 `.BJ` 后缀判定最稳）。只勾科创+创业 = "只看双创"；**一个都不勾 = 不限制** |
| 成交额下限 | `auction_min_amount` | **500 万** | 低于它不参与（挡掉小盘爆表噪声） |
| **量比门槛** | `auction_min_volume_ratio` | **2.0 倍** | 竞价量比到不了它，打分里「放量」那 2 分就拿不到（界面标签是 `量比 ≥`，带 `倍` 后缀） |
| 打分下限 | `auction_min_score` | **2** | 打分口径见下表 |
| 推送条数 | `auction_alert_max_items` | **10** | 按分数排序取前 N（1~50） |
| 扫描时刻 | `auction_scan_at` | `09:20, 09:25` | 逗号分隔的 HH:MM |

**阈值的依据**（真实全市场 5573 只数据算过，也写在 `config.example.toml` 的注释里）：

- **打分门限 2 而不是 3**：覆盖当日后期涨停 **24% vs 20%**，而池子里的推送量
  **0.44 vs 0.29 条/天** → 2 分更划算（多推一点、多覆盖一截）；
- **成交额 500 万**：全市场只有 **8.7%** 的股票能参与（嫌严可以调到 300 万）；
- **涨幅上限必须留着**：某日 25 只后期涨停里**没有一只**竞价涨幅 ≥9%，
  所以这条几乎零成本，却能挡住混进来的一字板。

打分（判强/弱）是**分级给分**，不是"多个条件同时满足"——实测"涨幅≥2% **且** 量比≥2
**且** 成交额≥500万"在 100 只里是 **0 只**，AND 判据等于永远不提醒：

| 命中 | 分 |
|---|---|
| 竞价涨幅 ≥ `auction_min_pct`（默认 +2.0%） | **+2** |
| 竞价涨幅 ≥ 它的一半（默认 +1.0%） | +1 |
| 量比 ≥ `auction_min_volume_ratio`（默认 2.0 **倍**；在「系统设置 → 竞价扫描」里能改，也可手改 `config.toml`） | **+2** |
| 量比 ≥ 它的 75%（默认 1.5） | +1 |
| 未匹配比 ≥ +0.5（**买盘剩余**占优） | +1 |
| 未匹配比 ≤ −0.5（**卖盘剩余**占优） | −1 |
| 竞价成交额 ≥ 门槛（默认 500 万） | +1 |
| 涨幅 ≤ −门槛（默认 −2.0%） | **−2** |
| 涨幅 ≤ −门槛/2（默认 −1.0%） | −1 |

- **分 ≥ `auction_min_score`（默认 2）→ 命中**（推送 + 进提醒表，`auction_strong`）；
- 接口只给**一个带符号的未匹配量**：`>0` 买盘剩余、`<0` 卖盘剩余，
  **`-1` 当"缺失"**（茅台就是 -1，实测 100 只里 1 只）—— 当成"卖压 1 手"是最坏的一种错；
- 竞价换手率、相对昨日量比、成交额一起显示在推送里；
- **推送**（9:20 与 9:25 各一条汇总）：

  ```
  ⚡ 竞价扫描（9:25）｜共命中 37 只，推送前 10：
  1. 名称(代码) 创业板 +5.21% 量比3.20 成交额2.1亿 买盘剩余3,400手（分6）
  ```

  （**名称(代码)** + 板块标签 + 原始数值 + 分数都给，用户能核对"凭什么上榜"）；
- **落库**：全部命中写进 `auction_scan` 表（【显示详情】里的"看全部"与次日复盘用），
  前 N 只另外进 `intraday_alert`（QQ 浮窗看得到，内容进两张表「监控开关」那一格的 tooltip；
  同标的同类型当天只登一次）；
- **界面**：自己那几十只票的竞价那一行（`竞价 +3.2% 量比2.8 买盘剩余1200手`）**只写进
  「自选股池」表「来源」列单元格的 tooltip**（跑的是同一份竞价快照、只取池子/自选/持仓，很便宜）；
  **想看全市场**：点【显示详情】→「竞价扫描」那一节（按分排序、可滚动、可复制，
  ★ = 已推送的前 N 只，`（池内）` = 这只也在你的池子/自选/持仓里）。

**② 当日个股异动**

- 数据源是**全市场一条请求**（`anomaly-analysis-list`），本地只留"自己的票"
  （股票池 + 自选 + 持仓）—— **不逐只问**（那要几百次请求）；
- 标签：涨停 / 跌停 / 大幅上涨 / 大幅下跌 / 快速反弹 / 快速下跌，

## 持仓做T（近似提示）

> **先把话说明白**：这是**持仓股**的盘中提示，用每 60 秒一张的行情快照**近似**判断
> "冲高回落"和"杀跌回稳"。**没有分时/逐笔/Level-2 数据，也没有历史分时数据 → 它无法回测**；
> 下面那四个阈值是**手工设定的起点**（不是拟合出来的，也没被验证过）。
> 请把它当成"提醒你现在可以看一眼盘"：提示里的价格只是一个瞬时快照值，成交价要靠自己的限价单去争取。

**A 股 T+1 是这套提示的地基**：当天买的票当天不能卖，所以一个持仓股一天只能做两种 T：

| 做法 | 顺序 | 收盘时的结果 |
|---|---|---|
| **反T** | 先**卖部分昨仓** → 当天更低时**接回等量** | 成本降低、股数不变 |
| **正T** | 用**现金先买** → 当天反弹后**卖出等量昨仓** | 赚一段差价、股数不变 |

所以提示里**永远不会出现"现在买/现在卖"这种裸指令**，而且一定带 **「部分」**：
程序不知道你今天又买过多少（那部分不能卖）、也不知道有多少股被挂单冻结 ——
**能卖多少只有券商的持仓页说了算**（提示里原样写着这句）。

### 两条规则与默认阈值

| 提示 | 触发条件（三条**同时**满足） | 默认 |
|---|---|---|
| `t_high` **高抛（近似）** | 现价较**昨收**涨 ≥ `t_high_min_gain_pct` | **2.0%** |
| | 较**今日最高**回落 ≥ `t_high_pullback_pct` | **1.5%** |
| | 现价仍在**分时均价**上方（回落但没破位） | — |
| `t_low` **低吸（近似）** | 现价较**昨收**跌 ≥ `t_low_min_drop_pct` | **2.0%** |
| | 较**今日最低**反弹 ≥ `t_low_rebound_pct` | **1.0%** |
| | 未跌破（或**刚收回**）**分时均价**（容差 0.5%） | — |

三条判据**缺一不可**（包括均价）：只有"冲高回落"或只有"跌深反弹"都不构成提示 ——
回落本身可能就是趋势反转的第一步，跌深本身可能就是继续跌。均价取不到就整条不发，
绝不用半个判据凑一条提示。

提示长这样（数字都给全，用户能自己核对）：

```
🔁 近似·T高抛（反T：先卖后买）｜持仓样本(600001)现价 12.34（+2.8%），较今日最高 12.78
回落 3.4%，仍在均价 12.10 上方 → 可卖出【部分昨仓】（反T：先卖后买），回落后当天再买回等量；
只提示部分仓位，可卖数量以券商为准
```

### 怎么改阈值 / 关掉它

**界面上现在有入口了**（原来只能手改 TOML）：开关是「系统设置 → T策略」里的
**T策略** 勾选框（`intraday_t`，默认关），四个阈值就在它下面两行；
「持仓监控」页操作行右侧那个 **T策略** 复选框写的是**同一个配置键**（一处开关，不是两个真相）。
两处都点一下底部【保存设置】才写回 `config.toml`。填 0 会被【保存设置】**明确拒绝并点名**
（"0 等于任何一点波动都算，那种提示只会刷屏"）。

```toml
intraday_t = true            # 想用就写 true（**默认 false = 关**，用户拍板：T策略默认关）
                             # 也可用环境变量 INTRADAY_T=1；关着 = 一条提示都不发、也不为它取数
                             # （阈值是手工设定的起点、没验证过，所以出厂不默认开）
t_high_min_gain_pct = 2.0    # 高抛：至少涨这么多（相对昨收）
t_high_pullback_pct = 1.5    # 高抛：从今日最高至少回落这么多
t_low_min_drop_pct = 2.0     # 低吸：至少跌这么多（相对昨收）
t_low_rebound_pct = 1.0      # 低吸：从今日最低至少反弹这么多
```

环境变量同名覆盖：`INTRADAY_T` / `T_HIGH_MIN_GAIN_PCT` / `T_HIGH_PULLBACK_PCT` /
`T_LOW_MIN_DROP_PCT` / `T_LOW_REBOUND_PCT`。写坏的阈值（0 / 负数 / 乱码）一律回到默认；
`intraday_t` 写成 `"maybe"` 这类认不出的值也**仍然按默认处理**（现在是默认关）——
反正**不会因为写错一个词就自己打开**。

### 具体怎么算的（哪里是假设，也写在这儿）

- **只看自己的持仓**（判据是"**未被显式平仓**"，不再是 `quantity > 0`：改版后界面只记
  代码 + 成本价 + 备注，新加持仓的 `quantity` 写 0，按老判据写就"加了却永远不提示"）。
  持仓**不在股票池里也照样盯** ——
  池子天天重建，用户手上的票不会跟着变（这类票只跑做T规则，不会顺带改变止损止盈的观察面）；
- **今日最高/最低**直接用快照自带的 `high_price` / `low_price`（接口返回的就是当日累计值），
  **不跨轮自己攒**：少一个会跟实际不符的状态源（进程重启、跳过几轮、跨午休都不会错）；
- **涨跌幅**用快照的 `price_change_ratio_pct`，缺了就用快照的 `prev_price` 现算。
  **绝不**拿本地日线的收盘价混算：`stock_daily_hfq` 是**后复权**视图（原始价 × factor），
  与实时价不是一套口径，有过分红送股的票会算出离谱的涨跌幅;
- **分时均价**没有现成字段，是 **累计成交额 ÷ 累计成交量**（`turnover ÷ volume`）算的：
  接口的 `PriceSnapshotItem` 只有 `last/open/high/low/prev/volume/turnover`，
  **没有均价、也没有买一卖一**。这个口径是**实测核对过的**（不是照着文档猜的）：
  - 2026-09-16 上午拿真实快照跑了**全市场 5573 只**：`turnover ÷ volume` 落在当日
    `[最低, 最高]` 区间内的有 **5550 只**、越界的 **0 只**（其余 23 只无量/无价，跳过）。
    若 `volume` 的单位是"手"而不是"股"，均价会差 100 倍、**每一只都会越界** —— 不可能是这个结果；
  - 同一批票间隔 75 秒取两次：`volume` 与 `turnover` **都单调增加**
    （茅台 1601022→1615722 股、20.21→20.39 亿元），而增量隐含均价 1256.69 元
    正好等于当时的现价 —— 说明两个字段都是**当日累计值**，不是"最后一分钟"。
  尽管实测干净，程序仍然保留一道自我校验：算出来的均价若**不在当日 [最低, 最高] 区间内**
  （容差 0.5%），**那一条提示整条不发** —— 这道校验防的是数据故障（停牌半天、
  字段不同步）与将来的接口变更，不是防单位换算；
- **今日新建仓不发高抛**（T+1 当天不可卖），但**会发低吸**（正T 用的是现金，不卖任何股票，
  提示末尾会写明"今日新建仓，T+1 当天不可卖"）。`opened_at` 为空/认不出来（老库、手工导入）
  时按"可卖"处理，并在提示里写明「建仓日未知，按可卖处理」—— 按不可卖会让高抛提示**永远不发**，
  用户看不到任何反应只会以为功能坏了；
- **一天一条**：复用既有的去重键 `(date, symbol, kind)`，同一只票的高抛与低吸当天各只推一次。
  为什么不做成"再创新高/新低就再喊一次"：那要给每个新高造一个新的去重键（形如 `t_high@12.78`），
  震荡一天能刷出十几条推送 —— 噪音比信息多。想看最新结论就看**「持仓监控」表最后一列「监控开关」**
  （鼠标停上去，tooltip 里是这只票**今天最新那一条提醒**的完整内容，没有就是
  "今天还没有这只票的盘中提醒"）；
- **怎么发出去**：与其它盘中提醒走**同一套通道**（消息列表 / 托盘气泡 / 飞书，
  按 `notify_channels` 配置）。做T提示**不生成条件单**：做T是同一天两次操作，一张条件单表达不了，
  硬塞一张还会把"正T：先买后卖"写成【条件单｜卖出】—— 方向都说错了，比不说更糟；
- 它**不参与选股**，也**不会混进当天池子的推送**：只写盘中提醒表 `intraday_alert`，
  不碰 `push_log`（测试里有这条断言）。

## 授权与试用（单机终身授权）

> 用户定的口径：「策略编辑锁住，点击提醒需要授权，请联系作者wx：q352162」、
> 「免费运行7天，到期打开同样授权提醒。」

- **免费试用 7 天**：新机器第一次打开就能用，界面上会写"试用中：还剩 N 天"。
  到期之后：**能看的照常看**（行情、自选、持仓、消息、桌宠都还在），
  **只有「策略编辑」被锁** —— 点它会弹出授权窗口，上面写着机器码与联系方式。
- **换成永久授权**：标题区【关于软件】（或授权窗口里）能看到**机器码**，形如
  `XXXX-XXXX-XXXX-XXXX`，点【复制机器码】把它发给作者 → 作者回你一个**注册码**
  → 填进授权窗口里机器码**下面**那个输入框 → 点【注册】**当场生效**，不用重启。
  注册码对大小写、有没有连字符、前后空格都容错（从微信里复制过来直接粘就行）。
- **授权是绑机器的**（"单机终身"就是这个意思）：换台机器要重新换一个注册码；
  把授权文件拷给别人也没用 —— 注册码和那台机器的机器码是绑定的。
- **文件在哪**：`%APPDATA%\LaoATrader\license.json`（与 `config.toml` 同目录）。
  这个目录**不在安装目录里**，所以覆盖安装升级不会把它弄丢（与飞书配置同一个道理）。
- **试用期不能被"小聪明"绕过**：首次运行日期在**配置文件与数据库里各存一份**，
  取较早的那个 —— 删掉其中一个不会重置；把系统时间往回调也一样会被识别成
  "检测到系统时间被调回了"，按到期处理。这两条都有用例守着。
- **作者那边怎么签发注册码**：
  - 直接用脚本：`python build/keygen.py <机器码>`（打印注册码），或不带参数运行会开一个
    小窗口（粘机器码 → 【生成注册码】→ 复制）；
  - **打成 exe 用**（用户的补充要求："注册机做成可执行文件。不随包分发。"）：
    本地 `pyinstaller --noconfirm --clean build\keygen.spec` → 产出 `dist\keygen.exe`；
    或者走 CI 的**手动触发**：Actions → build-windows → Run workflow，
    跑完下载 artifact **`keygen`**（与用户拿的 `LaoniuTrader` 是两个分开的 artifact）。
  - ⚠️ **注册机绝不随包分发**：它带着签发密钥的算法 —— 谁拿到它，谁就能给任意机器码算出
    注册码。所以主程序包里不会有它（`laoa_trader.spec` 的随包数据里没有 `build/`），
    CI 里还有一条"主产物里混进注册机就报错"的检查，`tests/test_packaging.py` 也钉着这件事。

### 将来（用户说"等版本成熟再做"）

- **加壳**：给 `dist\keygen.exe`（必要时也给主程序）加壳（VMProtect / Themida / Enigma 之类）
  能显著抬高逆向门槛，代价是杀软误报、体积与启动变差、每次改代码都要重走一遍流程，
  所以现在不做。它是对**产物**的后处理，不用改任何 spec。
- **注册码升级成长码**：现在的注册码是 16 位（HMAC 短码，便于微信传与手抄），
  强度目标是"挡住顺手把 exe 拷给同事"。要防"专业逆向"就换成 **Ed25519 私钥签名**
  （客户端只带公钥，逆向也伪造不出），代价是注册码变成 100+ 字符。
  改动只在 `licensing.expected_code()` 一处，界面与试用逻辑都不用动。

## 通知方式自己定（频道自选）

`config.toml` 里是一张**频道清单**（三选任意组合）。**默认是空列表**（用户拍板）：
出厂只走**「图标闪烁 + 消息列表」**（见下一节），托盘气泡 / 飞书由你自己勾 ——
第一次跑就被系统窗口打断不是这个程序该干的事。

```toml
notify_channels = []               # 默认：三路都不发（**消息列表与图标闪烁照常**）
notify_tray_duration_ms = 8000     # 托盘气泡时长
# Windows 系统通知那一整路已于 2026-09-18 删除（用户：「太骚扰了，影响体验」）：
# 老配置里的 notify_windows / notify_windows_sound / notify_windows_open_url
# 加载时不报错，保存时会被抹掉
feishu_on = true                   # 飞书频道总开关（凭证没配会自动跳过）
```

- 发送是**并行且互不影响**的：飞书挂了托盘照发，反之亦然；任何一路失败只记日志；
- 没配飞书凭证却勾了飞书：界面上那一行提示写着「未配置飞书凭证，已跳过」，**不报错、不影响其它频道**；
- 界面「系统设置 → 通知方式」是**四个勾选框**：**右下角滑出浮窗
  （`notify_popup`，2026-09-18 起默认关）** / 托盘气泡（`tray`）/
  飞书推送（`feishu`，含凭证三栏），下面还有提示音、图标闪烁秒数、浮窗停留秒数、浮窗条数上限；
  可以填凭证、调参数、点【发送测试提醒】**实发一条**（用页面上当前勾选，**不要求先保存**）；
- **一个勾都不勾 = 只入库不推送**（消息照样进两张表「监控开关」那一格的 tooltip）；
- 保存（底部那个【保存设置】）只就地改这几个键 —— `config.toml` 里你自己写的注释、
  备注、将来版本的键**都会保留**。

> **盘中提醒**（不是每日推送）走的是**本地这一路**：它**不在这张频道清单里** ——
> 「提醒响了没有」和「发不发飞书 / 系统通知」是两件事。

## 提醒怎么响（图标闪烁 + 「消息」列表，QQ 那种）

用户 2026-09-18 的原话：

> 「我的想法是通知仿照 QQ 桌面端，有消息软件图标闪烁，可以点开查看消息列表。」

所以默认的形态就是 QQ 那两件事 —— **图标闪给你看、消息躺在列表里等你点开**，
消息**不自己蹦出来**（原来那扇右下角滑出的浮窗改成了可选项，默认关）。

**为什么不用 Windows 系统通知**：系统弹窗的**点击行为不受本程序控制**——
实测点不开、看不到内容，在"专注助手 / 勿扰"打开时干脆不响；对盯盘工具来说
"提醒出现了但点不开、看不到是哪只票、什么价"等于没提醒。
**2026-09-18 用户又补了一句**：「windows系统通知删除，太骚扰了，影响体验。」——
所以那一整路（`notify/windows.py` + 三个配置键 + 设置页那两个勾选框）**已经删掉**；
老配置文件里还写着它也不会报错（能读，保存时抹掉）。

一条新消息到了，会同时做三件事（任何一步失败都不影响另外两步）：

1. **进「消息」列表**：这是消息的**唯一去处**（库里 `intraday_alert` 表，
   重启不丢）—— 盘中提醒（止损/止盈/做T/涨停打开/跌破5日线/放量突破/回踩买点/竞价/异动）
   与**选股完成**都在里面；
2. **响一声**：系统提示音 `SystemAsterisk`（标准库 `winsound`，不引新依赖）。
   非 Windows 静默跳过；声卡或别名有问题只记日志，绝不让提醒中断；
3. **图标闪烁**：托盘图标 + 任务栏按钮闪 `notify_flash_seconds` 秒（默认 6），
   正常图标与"右上角带红点"的图标交替（红点图标是程序化画的，落盘在数据目录的
   `cache/` 下，不占仓库、不进安装包）。**你一点开消息窗口或主窗口就立刻停**。
4. **桌宠冒泡 + 念出来**（2026-09-18 用户点名要的，默认开）：
   桌面上常驻一张置顶小卡片（就是用户给的那张图，见下），有消息时**冒气泡 + 蹦两下**，
   同时用 **Windows 自带的中文语音**把这句话念出来（`名称(代码)，类型，说明 现价 x`）。
   同一时刻来多条时只念/显示**最新那条** + 一句「还有 N 条」——
   "大声喊"要喊得有用，连着念五条会把人烦到关掉语音。

### 桌宠（常驻桌面，默认开）

用户原话：「可不可以编写个机器人，直接中文语音提醒。像一个桌宠一样的，
软件隐藏时停留在桌面，有消息时大声喊出消息内容。」

- **它就是桌面上一张小卡片**（无边框、置顶、**不进任务栏**）。**你把主窗口收进托盘之后
  它照样在桌面上** —— 这是这个功能的重点（最小化不等于"程序不见了"）。
- **有消息**：冒气泡（长文本截断、鼠标停上去看全文、点一下收起）+ 上下蹦两下 + 念出来。
- **点它**：双击 = 打开「消息」列表；右键菜单四项：
  【消息（N）】【试喊一条】【静音一小时】【藏起来】。
- **拖动**它换位置，松手后写进 `config.toml` 的 `pet_x` / `pet_y`，**下次启动回到那里**。
- 右键【藏起来】= 不再出现（配置里 `notify_pet = false`）；
  想叫回来：设置页「通知方式」里勾上「桌宠」并保存，**立刻**就回来。
- 形象是**你给的那张图**（`assets/pet.png`，由 `build/make_pet_asset.py` 从原图缩到
  512×512 随包）。**现在这版是透明底素材 → 桌宠是「自由站立的角色」**：
  窗口背景透明，不画卡片底、圆角、边框、阴影，图片直接贴在桌面上（角色的轮廓就是它的形状）。
  用哪套画法**看素材有没有透明通道**（`hasAlphaChannel()`）自动决定：
  没有 alpha 的图（第一版那张带红金花纹与水印的）会自动退回**圆角卡片**式。
  素材缺失（打包漏了、被删了）时退化成程序自己画的小家伙，**绝不开不起来**。

  > **换素材只要三下**：把新 PNG 放到 `laoA/桌宠2.png`（或改 `build/make_pet_asset.py`
  > 的输入路径）→ 跑一次 `python build/make_pet_asset.py` → 重新打包。
  > 代码一行都不用改（要不要卡片底是看素材自己有没有透明通道）。

#### 中文语音朗读（不联网、不装东西）

- 走 **Windows 自带**的语音合成（`notify/voice.py`，后台进程调 `System.Speech`，
  **不弹黑窗**），所以不用装任何东西、也不联网（提醒里有价格与持仓，不该往外发）；
- **这台机器没有中文音色时就不念**（拿英文音色念中文是怪腔怪调，比不念更糟），
  只在「通知方式」那一行的说明里告诉你"这台机器没有中文语音，装一个语音包即可"；
- 音量 / 音色 / 语速在设置里可调：**音色按「男声 / 女声」选**（不是列一堆中英文音色名）、
  语速是**倍率**（默认 1 = 正常，0.5 更慢、2.0 更快），音量默认 90%；
- **数字逐位念**：股票代码与价格一位一位读（`600519` → 六零零五一九、`1234.56` →
  一二三四点五六），成交量/家数/涨跌幅这类「数量」仍整读；这个行为可以在设置里关掉；
- **静音**（桌宠右键【静音一小时】）只停朗读：气泡与消息列表照常 ——
  要的是"别出声"，不是"别提醒"。

#### 【试喊一条】：非交易时段也能验

盘中提醒只在交易时段产生，收盘后想验"桌宠会不会冒泡、会不会念"就没有样本。
桌宠右键【试喊一条】就是给这个用的：

- 它走的是**与真实提醒完全相同**的链路：进消息列表 → 响一声 → 冒泡 → 朗读 → 闪图标；
- 它在消息列表里显示成**「测试」**，而且**不写库**（不污染真实提醒的记账与推送）；
- 它是唯一会绕过"静音"的朗读（你主动点的，就是想听）；没有中文音色时会把原因写在
  设置页那一行（"没响"必须能解释）。

### 「消息」窗口（点托盘图标打开）

- **左键单击托盘图标 = 打开它**（`ui/message_center.py`；双击仍然是开主窗口）；
  托盘右键菜单里也有一项**「消息（N）」**，N 就是未读数；
- 列表四列：**时间 | 标的 | 类型 | 说明**，新的在最上面；**未读的行加粗、前面带一个圆点**，
  标题写着「未读 N 条」；
- **点任意一行** → 弹出这一条的详情（提醒原因 + 时间 + 推送原文，含可抄进券商条件单的参数，
  那段文字能一键复制）；
- **打开即已读**：窗口一显示，未读清零、图标停闪（QQ 就是这个逻辑）；
  窗口开着时新来的消息直接算已读；窗口关掉之后新来的再开始算未读；
- 三个动作：【全部已读】【清空】【通知设置】（最后这个跳到「系统设置 → 通知方式」）。
  **【清空】只是不显示了**：历史还在库里 —— 两张表的「提醒」列与推送记录都读它；
- 「选股完成」那一行在列表里显示成**选股结果**（它的 `symbol` 是内容指纹，不是股票代码），
  同一批内容一天只留一条（与推送去重同一个口径）。

### 可选的另一种呈现：右下角滑出浮窗（默认关）

勾上 `notify_popup` 就照旧弹那扇浮窗（标题 `⚡ 盘中提醒 · N 条`、鼠标停着不消失、
连续多条合并成一扇窗、不抢焦点）：它是"消息自己跳出来给你看"，与消息列表**互不影响** ——
无论勾不勾，消息**始终**会进列表。

```toml
notify_popup = false             # 默认关：要走"消息自己蹦出来"就改成 true
notify_popup_seconds = 8         # 浮窗几秒后自动消失（鼠标停上面时不消失）
notify_popup_max_items = 5       # 浮窗最多列几条（1~10）
notify_sound = true              # 提醒时是否响一声（仅 Windows 有效）
notify_flash_seconds = 6         # 托盘/任务栏图标闪烁秒数（0 = 不闪）
notify_pet = true                # 桌宠（常驻桌面、有消息冒泡 + 蹦两下）
notify_voice = true              # 中文语音朗读（Windows 自带语音；没有中文音色就不念）
notify_voice_volume = 0.9        # 朗读音量 0~1
notify_voice_rate = 1.0          # 朗读语速（倍率：1 = 正常，0.5~2.0）
pet_x = 0                        # 桌宠位置（拖动后自动写；0 = 还没拖过 → 右下角）
pet_y = 0
```

> 上面这一组只管**呈现方式**：不勾 `notify_popup`（默认）就是"闪图标 + 消息列表"，
> 勾上就额外滑出一扇浮窗。提醒本身**永远**会入库（`intraday_alert`），
> 也永远能在「消息」窗口里回看：鼠标停在两张表最后那一列「监控开关」的 tooltip 上
> 看到的是**这只票今天最新的一条**，而「消息」窗口是**全部消息的列表**。

### 操作提示：成功不打扰、失败必可见

用户 2026-09-18 的要求：「软件操作的一些提醒都不需要。」所以这一版的刻度是：

- **成功的操作不弹提示**：勾/取消勾策略、删除自选或持仓、加自选、保存设置、
  导出结果、复制详情……干完就完了 —— 列表多了/少了一行、设置页那行小字、
  提示区那句话本身就是反馈；
- **失败与警告照旧弹**：公式语法错、保存失败（校验不过 / 只读盘）、导出失败、
  未找到要删的那条、超过自选上限、Key 是空的 —— 这些必须让人看见
  （这是用户更早定的口径：「成功不需要提示，失败再提示」）；
- **长流程的运行状态照旧**：选股、下载、同步那些"完成：…"留在标题区 ——
  那是**状态**，不是操作提醒；
- **三个"复制"动作**留在状态栏里说一句（剪贴板看不见，完全不提示会让人以为没生效）。

## 首次运行会做什么

1. 建本地库 `%LOCALAPPDATA%\LaoATrader\data\trader.db`（不复权原始价 + 复权事件 + 后复权视图）；
2. **下载历史数据**：同花顺全市场日K dump（10 年、约 1028 万行）+ 复权事件（5.7 万条）
   → **导入最近 6 个月**（约 120 个交易日、约 50 万行）→ 本地算后复权 → 入库
   （约 8~15 分钟，有进度条；**中断了会自动续传**，详见下面「下载中断了怎么办」；
   想要 10 年把 `history_years` 改成 10）；
3. **收尾自动补齐轻量数据**：股票名称 → 交易日历 → **行业归属（90 个一级行业）** → 指数日线。
   行业归属必须在行情写入**之后**跑（它只给"库里已有行情的股票"写行业），
   这几步失败不影响已下好的行情，但会提示"点【刷新数据】可重试"；
4. 之后：**默认什么都不会自动跑**（`auto_run = false`，选股随时手动）；
   盘中（09:30–11:30 / 13:00–15:00）每分钟盯一次池子/自选/持仓的提醒。

「系统设置 → 数据来源」里的【下载数据】随时可以再跑一次（增量：只补缺失的日期），
【刷新数据】只补数据不选股、不推送。

**没配 Key 时，"首次运行"是另一条路**（`ui/app.py` 的 `on_download()` 与
`data/public_sync.py` 的 `daily_update_public()`）：

1. 点【下载数据】**会被明确拒绝**，提示里指的是**填 Key 的地方**（同花顺那一行的输入框，
   或 `config.toml` / 环境变量）：
   页内点亮一句
   `❌ 完整历史数据要同花顺 API Key（每个用户自己申请一个）：在 config.toml 里写
   hithink_api_key = "你的Key"，或设环境变量 HITHINK_FINANCE_API_KEY，然后重启程序（申请地址见上面那行的 …）。`
   `没 Key 时能用的：实时行情（自选股池/持仓监控）与大盘概览 —— 每天也会自动把当天的行情与涨停池写进库；
   但**选股要 Key**：数据自检要求「复权事件」与「行业归属」齐备（这两样只有同花顺那条路给得到），
   缺了就拒绝选股（就是不让程序拿算错的复权价去选票）`，
   同时一句 toast：`❌ 选股要同花顺 Key · 没 Key 时行情与大盘概览可用 · 见【系统设置】`。
   **这两句就是"没 Key 到底能拿到什么"的官方口径**，与本文上面那张边界表一致。
2. 有 Key → 走老流程（`sync.download_history()`：同花顺 `daily-k` dump，按 `history_years` 导入，
   6 个月约 8~15 分钟，可断点续传）；
   **没 Key → 历史只能靠日更一天天攒**：`sync.daily_update()` 拿不到同花顺凭据时改派
   `public_sync.daily_update_public()`，"今天"这一根仍然会写进库。
3. 免 Key 日更那一趟快照出：**当日 OHLCV**（写 `stock_daily_raw`）+ **涨停池** + **代码表/名称** + **交易日历**。
   停牌票（成交量为 0）**不写假 K 线**；拿不到的字段（封单额/封板时间/涨停原因等）留 **NULL 不编 0**；
   中间缺的天**只统计、不编**（`gap`），并如实写一句日志。
   除权检测就在这一步做（用快照的"交易所昨收"与库里前收比，见上一节）。
   **这几天的数据是"哪天配了 Key 再补历史"的铺垫**（按 `(symbol, date)` 幂等写库，不会冲突）——
   但**别指望靠它把选股跑起来**：选股要的是复权事件与行业归属，那是同花顺那条路才有的。
4. 代价如实说：**没 Key 时行业归属永远是空的** → ①"热门行业"过滤不生效（`pool.py` 明确写
   "热门行业为空（缺行业/涨停/历史数据），本次不做过滤"）；②自检会因此判"行业归属未同步"，
   加上缺复权事件，**结果就是【开始选股】被拒绝**（见上面那个 🔴 —— **设计如此**）。

## 标题区（一行：软件名 + 运行状态 + 两个按钮）

改版把原来那三行（主状态 + 右侧四个短标签 + 一排七个按钮）压成**一行**
（原话"太啰嗦、很多词看不懂"），窗口标题就是 `老牛选股助手`：

```
老牛选股助手  ·  运行状态：✅ 数据就绪 · 更新到 09-11 · 5560 只 · 盘中提醒时段中      [显示详情] [关于软件]
```

- **运行状态是唯一说"现在在干什么"的地方**，按优先级取（`_compose_status`）：
  1. 有瞬时消息（刚点过的动作、任务完成/失败，10 分钟内有效）→ 显示它；
  2. 正在下载 → `⏬ 正在下载历史数据 48%（写入行情 62/285 万行）`；
  3. 本地数据落后或不可用 → `⚠️ 本地数据落后 3 个交易日 · 在【系统设置】里点【下载数据】补齐`
     （**必须点名在哪个页**：那两个按钮改版后搬进了「系统设置」）；
  4. 一切正常 → `✅ 数据就绪 · 更新到 09-11 · 5560 只`；
  5. 末尾再补一句盘中提醒的**进行时**状态（`盘中提醒时段中` / `提醒已暂停`）——
     不在时段时**什么都不补**（不写"未在时段"：那等于每次开机都提醒用户"现在没在盯盘"，是噪音）。
- **没有右侧短标签了**（池子只数、持仓浮动、下次选股这四项**全部取消**，
  一件事只说一次）：池子只数在「自选股池」表头上（`共 12 只（策略 10 · 自选 4）`）、
  持仓浮动在【显示详情】里（`持仓浮动：+1.20%`，只有比例没有金额）、
  「盘中提醒」进运行状态那一句、其余事实都在【显示详情】里。
- **【显示详情】**：点开一个**可复制**的窗口（内容与运行状态那行的 tooltip 是同一份文本）：
  版本号、后台任务、最新数据日期、本地股票数与行情行数、今日池子（含自选）、持仓浮动、
  盘中提醒状态、数据自检结论与阈值、**竞价扫描的全部命中**、数据目录、日志文件路径。
  报障时把整段贴过来即可。
- **【关于软件】**：版本号 / 作者 / 版权 / 数据来源 + 【复制版本信息】——
  改版后**窗口标题只写软件名**，版本与版权只在【关于软件】和【显示详情】里。
- **细进度条只在任务运行时出现**（`PROGRESS_BAR_HEIGHT` 像素、**不显示百分比文字**：
  百分比在运行状态那句话里，两处都写数字是同一件事说两遍）—— 常驻一条灰条既占地方，
  又会被误读成"卡在 0%"。
- **一行提示**（`first_run_hint`，只在数据不够用时出现）：例如
  "本地还没有行情数据 · 在【系统设置】里点【下载数据】"，**数据下好之前一直挂着** ——
  原来的**首次运行向导模态弹窗已经取消**（它问的"填 Key / 选目录 / 开始下载"三件事
  在「系统设置」里都有，再弹一个窗口只是把同一件事说第二遍，还会挡住主界面。
  顺带一提，"填 Key"这件事在界面上**没有入口**了（写 `config.toml` 或环境变量），
  而**同花顺是主源**：不填 Key 时它整个跳过、由免 Key 的公开源兜底）。
- **标题区不放操作按钮**：数据类操作在「系统设置 → 数据来源」，选股在「策略选股」。

## 界面：五个页签、两张表、设置五组

**五个页签（顺序即显示顺序，`ui/app.py` 的 `TAB_TITLES`）**：
`大盘概览 / 自选股池 / 持仓监控 / 策略选股 / 系统设置`。
每个页面的标题字号比正文大两号，块标题大一档 —— 全程序只有三级字号（层级分明，不是字号丰富）。

### TAB 1 大盘概览

只有**四块**（成交与情绪 / 宽基指数 / 情绪指数 / 热门板块）+ 一行页脚，口径与刷新节奏见上面
「[大盘概览（四块）](#大盘概览第一个页签启动就停在这一页四块)」一节。
块标题常量是 `MARKET_SECTION_TITLES`，**顺序即页面上下顺序**。

### TAB 2 自选股池（8 列）

- **添加行**：代码 + 备注 →【添加自选】（**回车即加**）；
- **表头**（`WATCH_HEADERS`）：
  `名称(代码) | 现价 | 涨幅 | 市值 | 换手 | 板块 | 来源 | 监控开关`；
- 表头右边一行小字：`共 N 只（策略 M · 自选 K）`；
- **口径**：`现价 / 涨幅` = **实时快照优先**（60 秒轮询），没有实时数据就用本地最新**不复权**
  收盘价 —— **单元格里不加任何符号**（以前会写成 `12.34*`，用户把它误当成"监控状态标记"，2026-09-17 起
  去掉），区别写在 tooltip 里："这是本地最新收盘价（MM-DD），**不是实时价**"。
  绝不拿后复权价冒充现价（改版修掉的老 bug）；
  `市值` = **流通市值（亿）**、`换手` = **实时换手率（%）**（都来自实时快照，**取不到显示 `—`，
  不显示 0** —— 0 亿市值 / 0% 换手是真实存在的值，拿 0 冒充"没取到"会被读成"这只票没人交易"）。
  ⚠️ **这两项的来源可能与「现价/涨幅」不同**：同花顺的快照端点不返回它们，
  所以主源是同花顺时由后面的来源（免 Key 公开源）**按字段补**上，tooltip 里各写各的出处
  （例：`流通市值 15726.28 亿（快照 14:56）`）；
  **`data_sources` 里没有第二个来源时就是 `—`**；
  `板块` = `stock_basic.industry`；`来源` = 见上面「自选股」一节；
- **`监控开关` 列**（原来的「提醒」列，2026-09-17 改名）：
  - 文字是 `开启` / `关闭`，**点一下这一格就切换**（与右键菜单的【关闭监控】/【打开监控】
    是**同一个动作**）；关了监控的那一格用灰字；
  - **原来的提醒内容一点没丢**：**今日最新一条提醒**的完整那句（含时间与触发数字）
    挪进了这一格的 **tooltip**（列只有一格宽，写不下整句话）；没有提醒时 tooltip 里写的是
    "今天还没有这只票的盘中提醒"；
- **行交互**：悬浮 → 看备注与这一行的全部明细（公式名、今日涨停、竞价那一行）；
  右键 → 【删除】/【关闭监控】↔【打开监控】/【打开雪球】；**单击名称 → 打开雪球个股页**
  （`https://xueqiu.com/S/SH600000` 这种）。行级操作跟着行走 —— 右键哪一行就操作哪一行，
  不会像原来"先在表格里选中、再点顶部按钮、结果点错了行"。

### TAB 3 持仓监控（10 列）

- **添加行**：代码 + 成本价 + 备注 →【添加持仓】（回车即加）；同一行右侧一个
  **T策略** 复选框（与「系统设置 → T策略」里的是**同一个配置键** `intraday_t`）；
- **表头**（`POSITION_HEADERS`）：
  `名称(代码) | 成本价 | 现价 | 涨幅 | 市值 | 换手 | 盈亏比例 | 止损位 | 止盈位 | 监控开关`；
- **没有「数量」列**：用户给定的字段只有 代码 + 成本价 + 备注（不做自动交易，"数量"没有意义）。
  库里的 `position.quantity` 保留仅为兼容老库（新行走 `quantity = 0`，靠"未被显式平仓"判据显示）；
- **口径**：`市值 / 换手` 与自选股池完全同一套（流通市值亿 / 实时换手率%，取不到 `—`；
  **出处可能与价格不同**，见上面"字段级补齐"）；
  `盈亏比例 = (现价 − 成本价) ÷ 成本价`，涨红跌绿，**缺价显示 `—`（不是 `0.00%`）**
  —— 显示 `0.00%` 会被误读成"刚好打平"；
  `止损位 / 止盈位 = 成本价 ×（1 ∓ 比例）`，比例在「系统设置 → T策略」里改；
  `监控开关` 与自选股池同一口径（`开启`/`关闭` + 点一格切换 + tooltip 里带今日最新一条提醒）。
  每列的**表头 tooltip 就是那一列的说明书**（不用翻文档）；
- 行交互与 TAB 2 相同（悬浮备注 / 右键 / 单击开雪球）。

### TAB 4 策略选股

策略列表（`策略名称 | 说明 | 策略选取`）+ 选股结果（**平时隐藏**）**共用同一块地方**，
启停、编辑、开始选股都在这一页 ——
见上面「[策略选股](#策略选股不会写公式也能用点按钮就插入)」一节。

**选股结果界面的口径改过两次**：2026-09-17 用户要求"这一页只显示策略、不显示选股结果"，
当时把结果表、【全部加为自选】整体删了；**2026-09-18 又要求加回来**（原话："选股状态时，
策略列表界面变为选股结果界面（选股结果界面平时隐藏），结果可以一键加入自选和导出"）。
现在点【开始选股】→ 列表那块切成结果表（`名称 | 代码 | 来源`）+【一键加入自选】
/【导出结果到桌面】/【返回策略列表】；**平时看到的是策略列表**。
结果照旧还会进**「自选股池」页**（在那一页增删）并自动导出
**桌面上的 `老牛选股助手-选股结果-YYYY-MM-DD.txt`**（见上面「选股结果的桌面文件」一节）。

编辑器里另有一个**【导出选股结果】**：它导的是**【运行】刚跑出来的那批**（不是整轮选股的结果），
文件名与格式跟选股结果桌面文件完全相同（`老牛选股助手-选股结果-<今天>.txt`，来源标 `公式·<公式名>`；
同一天里两份会互相覆盖），
方便"先跑一条公式看看、满意了再存下来"。

**主窗口不再自带【开始选股】**（同一页两个同名按钮，用户按哪个都可能、而"哪个才真的会跑"
只能靠猜）：这一页的按钮只发出 `start_pick_requested` 信号，主窗口把它接到选股流程
（`on_run_pipeline`）。选股完成后运行状态里会说一句结果去向（含桌面文件路径）。

### TAB 5 系统设置（五组 + 底部一个【保存设置】）

五组的顺序 = 页面上下顺序（`SETTINGS_GROUPS`）：**数据来源 → 通知方式 → 竞价扫描 →
T策略 → 其他**。**页面底部只有一个【保存设置】**，一键写回本页全部设置
（原来四组各有各的保存按钮，用户得记住"这两个按钮都要点一遍"，漏点哪个都是"改了没生效"）。
整页套了滚动区：五组三十多个控件的最小高度合起来有 1000 像素以上，
不套滚动区就会把**整窗的最小高度**顶到屏幕外（1366×768 的笔记本上底边被切掉，用户实报过）。

| 组 | 控件 | 写回的配置键 |

如果你在【添加来源】里加了**别的**需要 Key 的来源，它自己的 Key 会额外多写一项
（所以测试里会出现"35 个固定键 + 1 个来源 Key = 36 项"）。
收集**按界面上真正存在的行**做（`row.key_config` + `row.key_edit`）：注册表读不出来时那一行
照样有输入框，也就照样收得到（早先按注册表收集时，这种情况下**填了 Key 却不写盘**）。
收集入口是 `_collect_settings_updates`；`tests/test_ui_smoke.py` 直接断言这个键集合 ——
**少一个键就是"改了没生效"、多一个键就是把不属于本页的东西悄悄改了**。
保存的行为三条：

1. **校验不过就明确拒绝，并点名是哪一项**：`❌ 未保存：止损比例（stop_loss）必须大于 0%（填 0 等于
   「任何一点波动都算」，那种提示只会刷屏）` —— 止损/止盈、下载年限、四个做T阈值都必须 > 0，
   竞价涨幅上限必须大于下限。**一个字都不会写进文件**；
   止损控件刻意允许填 0（下界不夹成 0.5）："填 0 = 不想止损"这种误解必须在保存那一刻当面说清；
2. **成功回显**：`✅ 已保存 35 项（已写入 config.toml）；生效：主题 银色；通知 QQ 浮窗 + …；
   竞价扫描 关；T策略 关；当日异动 关；自选上限 20 只` —— 写盘成功不等于**生效**，
   所以把生效的那几条也摆出来（用户不用去别处核对）；
3. **保留用户自己的注释与未知键**：只就地改这几个键（`config.save_settings`），
   你在 `config.toml` 里写的注释、自己加的键、将来版本的键**都会保留**。

> 界面主题是**换完立即生效**的（不用重启，选择也写回 `ui_theme`），
> 所以那一个下拉框不等【保存设置】。

### 窗口与线程

- **窗口尺寸按屏幕可用区域自适应**：默认 `min(1120, 可用宽-40) × min(760, 可用高-40)` 并居中，

## 下载/导入期间界面不卡（性能）

用户实报“下载数据时界面卡死”。三个叠加原因，各自的处理：

1. **界面每 5 秒做全表扫描**：`data_summary()` 里有两条重活，其中 `COUNT(DISTINCT symbol)`
   要在几百万行的行情表上做全表去重（实测 168 万行 64 ms、300 万行 **111 ms**，
   而界面每 5 秒问一次，导入线程又正在同一张表上大批量写入）。现在：
   - `symbols` 改用 `stock_basic` 的行数（SQLite 对无 WHERE 的 `COUNT(*)` 走 O(1) 优化，
     实测 **0.00 ms**，语义相同）；
   - 数据概况在界面层加 **30 秒 TTL 缓存**，并且**下载期间一律用上一次的值**；
   - `_tick()` 在 `state.is_downloading()` 为真时**跳过重活**（不查概况、不重建两张表），
     只更新进度与运行状态那句；下载结束后的第一拍立刻完整补刷一次。
   实测：整个 `data_summary()` 从 **126 ms → 15 ms**（300 万行库），每分钟少占 1.3 秒界面时间。
2. **导入循环长时间占着 GIL**：读 Parquet、清洗、逐批写库都是纯 CPU 的 Python/C 代码，
   pyarrow/pandas 在这些路径上不释放 GIL —— 主线程连事件循环都转不动（不是“慢”，是“冻住”）。
   现在：Parquet **按 row group 分批读**（每批让出一次），导入循环**每 20 万行让出一次**
   （`sync._yield_gui()`：`time.sleep(0.001)` 会把 GIL 让出去）。十几分钟的导入因此只多几十毫秒，
   界面却能一直画帧、响应点击。
3. **进度回调太密**：10 年库能发出几千次，每次都跨线程排队 + `QProgressBar.setValue` + 重绘。
   现在在 `sync.throttle_progress()` 里统一节流：**同一阶段最多约 5 次/秒、或百分比变化 ≥1%
   才发一次**，阶段切换与首末值一定发（否则进度条会停在 99%）。命令行那边用它同一套门限。

## 在 Windows 上跑起来

### 最省事：双击 `一键运行.bat`

仓库根目录有个 **`一键运行.bat`**：双击它就行 —— 它会自己找 Python、建一个只属于本程序的
`.venv`、装好依赖、然后启动界面。第一次约 1~3 分钟（装依赖），之后每次秒开。

前提只有一个：**本机装了 Python 3.11 或更新版本**（没装的话脚本会弹出下载页并告诉你勾
"Add python.exe to PATH"）。它不动你的系统 Python，也不写注册表；不想要了就把整个文件夹删掉。

> 为什么要有这个脚本：正常路径是从 GitHub Actions 下载打包好的 exe，但那要等云端构建，
> 遇到额度/排队时可能迟迟不出包。这个脚本让你**不等 CI 也能把界面跑起来**。
> 打包成 exe 见 `docs/打包教程.md`（也可以本机双击 `build\build.bat`，前提是上面那套依赖已装好）。

```bat
.venv\Scripts\python -m laoa_trader --cli --market     :: 看概览那几行（与页面同一份口径；取不到数据时退出码非 0）
.venv\Scripts\python -m laoa_trader --cli --serve      :: 常驻：定时日更 + 盘中提醒
.venv\Scripts\python -m laoa_trader --cli --doctor      :: 自检：路径/依赖/凭据/数据概况 + 数据三态结论
.venv\Scripts\python -m laoa_trader --cli --once --auto-download :: 数据不可用时先下载再继续
```

> **2026-09-18 删掉的三个入口**：`--groups` / `--strategies`（临时覆盖跑哪些策略）与
> `--list-groups`（列策略组与成员）—— 它们背后的策略组机制已经不存在了。
> 现在"跑哪些"只有一个答案：`config.toml` 里 `enabled_formulas` 勾了哪几条公式
> （界面上就是「策略选取」列）。
> `--scorecard`（成绩单）也一起删了，只留代码层的 `formulas.run_scorecard()`。
`--once` 与（把 `auto_run` 打开后的）定时任务走的是**同一个流程**：同一天重复跑不会产生重复行，
也不会重复推同一批消息（按内容指纹去重）。

## 图标

图标来自**设计稿原图**（`build/logo/source-logo.jpg`，2048×2048、白底、红橙配色），
由脚本转换成程序要用的各档尺寸 —— **不是随手另存几个位图**，因为"从 2048 缩到 16"
这一步有好几个坑（白底要抠掉、几十倍缩小会发暗、小尺寸上文字必然糊），
这些都在脚本里处理并有自检兜着。

- **白底转透明**：按"颜色是叠在白底上"做反预乘，笔画保留饱和色、边缘变半透明
  （阈值抠图会在笔画边上留一圈灰）；这样贴到深色/浅色任务栏都不会是一块白方块。
- **上下自动拆分**：设计稿是"上图下字"（图形 + 「老牛选股」），脚本自己找中间那条空白带切开，
  不用手填坐标 —— 以后改字号、改间距，重跑就自动对上。
- **按尺寸选构图**：`≥128px` 用"图形+文字"完整版（这时文字还看得清）；
  `≤64px` **只留图形** —— 四个汉字缩到 20px 以下就是一坨，谁都认不出。
- 产物在 `src/laoa_trader/assets/`：`icon.png`(256，窗口图标/关于页)、
  `icon.ico`(16/24/32/48/64/128/256 七档，Windows exe 用)、`icon-16/24/32/…png`（各档单图）；
  定位只认一个模块 `src/laoa_trader/assets.py`（源码运行 / `pip install` / PyInstaller 打包三种形态
  都在这里解析，**拿不到图标就返回 None，界面优雅降级**而不是崩）。
- **要换图标**：把新设计稿覆盖 `build/logo/source-logo.jpg`（或 `.png`/`.webp`），然后
  `python build/import_logo.py`（需要 Pillow + numpy，**只有改图标时才装**；产物是位图，运行时不需要）。
  想要"白底圆角卡片"风格就加 `--background white`；想让人肉眼比对就加
  `--preview 出图目录`（会导一张"各尺寸放大 4 倍"的对比图，重点看 16/32 这两档）。
- 没有设计稿时的兜底：`python build/make_icon.py` 会用代码画一版（深蓝底 + 白 A + 红折线）。
- 界面接线：窗口图标用 256 那份、托盘用那一档专用小图（16~32px 场景）、
  「关于」对话框里 64×64 一份；全都**拿不到就降级**，不影响开窗口。
- 打包时由 `build/laoa_trader.spec` 自动带上：`assets/` 进 `datas`，`icon.ico` 接成 exe 图标
  （**改了图标要重新打包才会生效**，光换文件、不重打包，用户拿到的 exe 还是旧图标）。
- 图标自检在 `tests/test_assets.py`（不依赖 Pillow：自己解 PNG）：文件与 ICO 各档齐全、
  内容真的画上了、**品牌红不许被缩暗**、四角透明、小尺寸里不该出现文字块、资源缺失时返回 None。

## 打成 exe 分发

> 分发包默认**只导入 6 个月历史**（约 50 万行）：同花顺 dump 本身是 10 年数据集，
> 导入时按 `history_years = 0.5` 过滤，库更小、首次导入更快（**下载量不变**——
> dump 还是要整个下，变的只是导入多少行）—— 收到包的人想要更长样本，
> 改 `config.toml` 的 `history_years = 10` 重新下载即可。

```bat
cd laoA
build\build.bat
:: 产出 dist\LaoATrader\LaoATrader.exe（目录版，启动快）
:: 想做成单文件加 --onefile（启动慢、杀软误报多，不推荐）
```

首次运行 exe 时同样要在「系统设置 → 数据来源」里点【下载数据】建库
（标题区会挂着那一行提示，没有向导弹窗）。

> 打包细节见 `build/laoa_trader.spec` 顶部注释：onedir（启动快、杀软误报少）、
> `--noconsole`（不弹黑框，日志写到 `<数据目录>\logs\laoa-trader.log`）、
> `config.example.toml` 随包分发。exe 旁边的 `config.toml` 就是它的配置。

## 与 NAS 版的关系

- **策略与规则完全同源**：都是 10 年样本检验过的同一批规则（短期反转、地量后放量、首板缩量
  三条已改写成随包公式；连板回踩 T+2 与低价股 T+10 两条 2026-09-18 删掉），参数一致；
- **数据协议一致**：本地 SQLite + 自算后复权；数据来源都可以走同花顺 REST（各自的 Key），
  桌面版另外默认挂了一个**免 Key 的公开行情源**（腾讯为主、新浪兜底），NAS 版没有这一路；
- 两套可以同时跑（互不干扰），也可以只用其中一套。
